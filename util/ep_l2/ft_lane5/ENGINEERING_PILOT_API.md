# One-time engineering resource API (review_r8)

This API launches no compiler and grants no scientific qualification. Ordinary `Registry.admission`, `build_lease` and simulation retain their original48GiB disk predicate; only two additional guards block ordinary heavy claims during an active ENGINEERING_PILOT and prevent the old release API from bypassing its audited terminal. The caller uses2CPU/8GiB, available memory after reservation>=64GiB, and no overlapping EP-L2 run/build/scan. Test dependencies cannot target the real central registry.

No live authorization is implied by this file or by synthetic tests. A real approved envelope must exist, be published/read back from Lane5, and be registered under the permanent central lock before Lane1 can claim it. `NO_SAFE_PILOT_ENVELOPE` is never an authorization.

## Request and authorization binding

Lane1 publishes exact `LOW_SPACE_PILOT_REQUEST.json` bytes. Required shared fields: `pilot_id`, `host`, `boot_id`, `cpu_units=2`, `memory_bytes=8589934592`, positive `max_duration_seconds`, `execution_identity`, `execution_locations`, `output_roots`. Include exact commands, output/log/temporary caps, and monitor/stop plan as request evidence. The immutable request publication commit/path/SHA256 is retained by Lane5.

`execution_identity` contains full `core_source_commit`, `framework_source_commit`, `vendor_commit` (40hex), and `driver_sha256`, `build_entry_sha256`, `repair_commands_sha256` (64hex). The engineering wrapper is a separate driver; `build_entry_sha256` binds unchanged original build_r0_1.py. `repair_commands_sha256` hashes `ast.get_source_segment` of the unique top-level repair_commands function (UTF-8, no added newline). The exact published original function supplies all21 directed commands; do not reimplement a different matrix.

`execution_locations`: absolute `core_repo`, `framework_repo`, `vendor_repo`, `driver_path`, `build_entry_path`, `repair_commands_path`. Live sampling independently reads Git HEAD/clean tracked state and actual driver/function bytes; caller-supplied pins alone are insufficient.

Each `output_roots` item has absolute `path`, stable `resolved_path`, and `filesystem` budget key. Use new disjoint roots; TMPDIR nested inside the new build root is included in that root, not double-counted. Existing `/workspace/results` ancestor alias may resolve to Share, but actual mount/device and final resolution must stay bound. No root itself may be a symlink. No old formal build/root is reused.

An approved authorization has schema `EPL2_ENGINEERING_PILOT_AUTHORIZATION_V1`, status `APPROVED_ENGINEERING_ONLY`, issuer `lane5`, r8 authority56a0517d3a5941a0a870b50e8c915a8a36b9ee5d, the shared request fields, request publication binding, a generated64hex token, issued/expires Unix times, monitor_interval_seconds<=2, term_grace_seconds<=3, mount_namespace, protected_processes and external_inventory_complete=true, and scientific_use=`FORBIDDEN_ENGINEERING_EVIDENCE_ONLY`.

Each distinct write filesystem has one budget, folding aliases such as workspace/tmp. Fields: `probe_path`, `device`, `mount_signature` (`filesystem()` supplies live identity), positive integer `entry_free_bytes`, `hard_stop_free_bytes`, `max_pilot_allocated_growth_bytes`, `external_write_reserve_bytes`, `monitor_and_kill_overshoot_bytes`, `minimum_untouched_emergency_bytes`, and independently reviewed `evidence`. Entry must cover the sum of growth+external+overshoot+emergency; hard stop must preserve emergency+overshoot. Missing/unknown terms cannot become zero. protected_processes uses the exact stable `protected_inventory()` result; unknown/new/lost DTC/C16 ownership stops. These API checks enforce a reviewed budget, not prove an invented budget safe.

## Explicit lifecycle

1. Lane5 alone independently reviews the actual request/commands/source/vendor/all filesystems and writes an approved authorization only if quantitatively safe. Push/read back authorization, then call `PilotRegistry().register(auth, request_bytes, {commit,path,sha256})`. Default verifier checks current Lane5 GitHub authority and exact published Lane1 request bytes. Registration rechecks live entry and rejects any previous r8 campaign registration. No grant is issued for the present refusal.
2. Lane1 wrapper is dry-run by default and requires explicit execute/pilot ID/authorization. It verifies exact actual pins and uses `api.claim(auth, request_bytes, measured_identity)`. In-lock preflight rechecks TTL, source, mount, roots, quota, original RAM floor and all budgets; atomically consumes token and creates one resource_leases row. No replay across processes/restarts. If live50GiB is reached, pilot refuses in favor of the sole formal entry.
3. Before each owned command, recheck `api.monitor(key,auth)`; after Popen(start_new_session=True), immediately `api.attach_process(key,auth,process)`. Monitor throughout configuration/build/tests at<=2seconds. Any STOP, exception, timeout or inability to monitor must stop only that command group with `terminate_owned(process, exact_process_identity)`. Keep OMP/BLAS threads1 and CMake-j2. STOP is latched; resource recovery cannot resume a stopped campaign. The wrapper must always terminate/wait in finally, preserve partial directories/logs and write an exact engineering receipt. Allocated bytes, actual f_bavail on every filesystem, external reserve, process-tree RSS, source/vendor, project inventory, heartbeat and total deadline are guarded.
4. Call `api.release(key,auth,'COMPLETE_ENGINEERING_ONLY' or 'PILOT_STOPPED_...', receipt_sha256)` after all owned children have exited. Pilot-specific terminal is stored separately from compatibility RELEASED; token remains consumed. No runtime_ready=true, scientific certificate or formal run follows. Explicit Lane5 dead-owner recovery requires both old owner and last child dead plus a recovery receipt hash; no automatic stale lease reclamation.

Source/driver changes are rejected. A within-campaign repair needs a separately reviewed authorization amendment/API extension retaining the original total caps/history/deadline; this first implementation does not silently rebind pins or permit a second claim. Do not treat that limitation as permission to bypass the registry.

34 new isolated pilot tests and10 affected original registry regressions pass. Positive budgets are synthetic tool fixtures only. Tests use small owned Python sleep children to verify exact PID/PGID TERM/KILL and unrelated-child survival; no actual compiler/simulator or real central pilot registration occurs.
