## 2. 当前论文草稿的比较语义

依据用户当前v0.2架构稿与项目交接：

- Tag决定后续地址查询可见性；物理行可能在Tag替换后继续保护既有消费者。
- PIB主要保存等待元数据，不预留完整返回结果向量。
- IO依赖顺序完成/释放；OO显式跟踪等待消费者、引用和Tag可见状态。
- 不采用独立传统MSHR不等于不存在缺失状态或合并元数据。
- 映射被替换后，相同地址可能再创建请求；不宣称全局重复请求消除。

这些是本轮比较对象的定义，不是本次文献调研新发明的机制。与任何前人“首次不同”的断言仍需要各自原文支持。

## 4. 下一次比较必须逐项记录

比较至少包含：地址查找存在哪里；何时分配物理数据；响应未到时后续消费者如何登记；Tag被替换后谁持有旧数据引用；响应如何找到正确目的地；何时可以回收；资源不足时在哪里反压；全部元数据与端口/选择成本。

两篇论文都出现“decoupled”“reference”“MSHR”或“buffer”不构成机制等价；不同平台名称也不构成机制新颖性。未知字段保留未知。
