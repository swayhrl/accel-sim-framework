## 2. Stage B1 — Btree single-PC conditional reconstruction

**Hypothesis:** the frozen Btree trace's 6000 `findRangeK/PC1c40/LDG.E.SYS` (4-byte) records have P with one active lane but mode0 full32 address words. An inspected historical producer family prints P yet serializes addresses in E-lane order. Under that **declared** E-list contract, the selected active-lane address is obtained by correctly mapping its lane within the E-ordered original words, rather than treating the first word as its address. The existing source review reports 5792 changed active addresses and 208 unchanged; independently recompute them, never hard-code a correction count as proof.

**Necessary semantic gate:** inspect the archived serializer's exact mode0 list production and the unchanged actual consumer decoder to prove word-to-lane mapping for **every** affected record. A full32 list must not be taken to prove a particular E mask if the serializer may emit padding or otherwise violates that inference. Fail closed if E/lane mapping is not uniquely supported by the declared producer contract and original bytes; neither choose addresses by array-range plausibility nor by expected DTC performance. The historical E-list producer is a conditional model only: the actual trace-capture build/ELF is unbound and three old Btree binary candidates had a nonmatching PC1c40 BRA.

**CPU-only candidate (conditional on gate):**
1. Pin original member/list hashes, original risk-index and prior source-code/hash receipts. Reuse 6000 indexed raw records with exact original-line SHA, rather than rescanning 629 traces.
2. Write a **new, immutable candidate** `BTREE_E_LIST_CONDITIONAL_V1` in a dedicated raw namespace; do not overwrite the original member. Transform only the source-justified address serialization at the one PC. Preserve P/CTA/warp/instruction order, opcode, width, all other operand and control records, active instruction counts, kernel list/ROI, and non-target bytes (or explicitly prove a necessary serialization-only change).
3. Independently compute all active-lane addresses from original bytes plus the pinned historical serializer model and compare against what the unmodified actual parser/consumer produces from the candidate. Audit the **complete Btree member** for changed/unchanged record identity and exact unchanged instruction scope; avoid reliance on generator self-check alone. 4. Record new member/list/bundle digests, source/consumer hashes, exact changed-row/changed-address counts, independent validation and negative evidence. The only possible successful label is `DERIVED_INPUT_ADMITTED_FOR_E_LIST_CONTRACT_ONLY`, never `ORIGINAL_CAPTURE_SOURCE_BINDING_PASS`.
