# Experimental Framework-only progress producer: source prepared

**SOURCE_PREPARED_NOT_BUILT_NOT_QUALIFIED.** No Core source/header/library was modified. Baseline `gpu-simulator/accel-sim.cc` was checked by `git hash-object` against Framework8e43 blob `c709f4b5942aec7ce9b7f06e07ae76e3b042e1f6` before editing. This preparation changes that Framework file and adds `gpu-simulator/ag7_policyb_progress.h`; no build, test, fixture, model-ELF read or trace-content read was performed by this producer subtask. The original270 options, call order, launch flags and model operations are retained. Scientific equivalence remains an independent gate.

## Protocol and binding

The exact opt-in is `DTC_AG7_POLICY_B_PROGRESS=1`. Without it, producer setup returns after reading that environment variable; every observation is guarded before evaluating model fields. No extra model state query is made for terminal classification while OFF. No model pointer enters the producer. The opt-in changes Framework ELF; it does not justify reusing an old exact-runtime BASE by itself.

The controller must inherit an already connected, dedicated AF_UNIX `SOCK_DGRAM` or `SOCK_SEQPACKET` descriptor with `O_NONBLOCK`, then set:

- `DTC_AG7_PROGRESS_FD`: decimal descriptor >=3.
- `DTC_AG7_GENERATION`: unique1–64-character generation nonce, using only ASCII letters/digits/`._:-`, bound by the receiver to the independently proven actual root exec event.
- `DTC_AG7_INPUT_SHA` and `DTC_AG7_ROI_SHA`: exact lowercase64-hex preregistered identities.

The producer obtains real `getpid()` and `/proc/self/stat` field22 start_ticks itself. Generation nonce, input and ROI are claims supplied by the trusted controller, **not** new self-proofs; the receiver must join them to the exact postfork root PID/start_ticks/exec-generation/loaded image/input/ROI registration and verify its socket peer. A parent admission identity, an arbitrary inherited helper or an unbound nonce cannot satisfy that join. Env values alone must never qualify it. No descriptor or socket mode is repaired by the producer. Setup and every emission preserve the caller's errno on all success/failure paths. Socket credentials must be checked per datagram using `SO_PASSCRED`/`SCM_CREDENTIALS`, including rejection of helper PID writers that inherit the descriptor.

Each datagram is <=1023 bytes, contains schema, producer identity, declared generation nonce/input/ROI, strictly increasing `seq`, `CLOCK_MONOTONIC` `mono_ns` nanoseconds, whole-input `epoch=0`, `phase_epoch`, phase, stream scope, coherent cumulative `completed` active-lane instructions and terminal `end` class. Frozen protocol required keys are `v=1,pid,start_ticks,generation,input,roi,seq,mono_ns,completed,phase,end`; optional metadata are `epoch,phase_epoch,stream_id,stream_scope`. Phases are `INIT/PARSE/SIMULATE/BOUNDARY`; terminal classes are `NONE/NATURAL/LIMIT/ERROR`. Producer and receiver must use the same Linux monotonic clock domain; reject future/stale/reversed/duplicated/truncated/unknown records. `phase_epoch` is only a transition identifier; it cannot renew a watchdog or phase lease. `stream_id=-1` means whole-input multiple/no active stream, while a single actual stream ID is reported at launch/running. Totals cover all active streams, not a per-stream subtraction. Exact stream attribution is not fabricated when multiple streams exist.

## Coherent safe points and failure bounds

Only the serial model thread reads `gpu_tot_sim_insn + gpu_sim_insn`, after `cycle()` returns and before existing `deadlock_check()` and destructive `finished_kernel()` consumption. Additional snapshots bracket existing initialization, command parsing, kernel launch, cleanup and the existing loop end. This does not add another `finished_kernel()` read or mutate a queue. `update_stats()` remains unchanged and completes between snapshots, preserving the cumulative sum. No timer thread, signal handler or external unsynchronized model read is added.

During running, the producer attempts emission after10 seconds since its last successful record. Transition/terminal records emit immediately. The bounded source cap is8192 datagrams, each <1024 bytes (<8MiB per process); a cap, syscall error, backwards clock/count, identity mismatch, short send or EAGAIN permanently disables telemetry. Sending uses `MSG_DONTWAIT|MSG_NOSIGNAL`, no retries, no flush/disk output, no queue wait and no model-state error repair. The independently qualified guard must fail closed on missing/stale records and actual cadence gaps >30 seconds. These failures cannot silently become a successful terminal receipt.

**There is no source-guaranteed <=30-second heartbeat during a blocking initialization/header/trace read/memcpy preparation or one long `cycle()` call.** No initial record is emitted until Core `init()` has returned and the same thread can read initialized counters; that first `INIT` record reports an actual coherent sum. Before that, lack of freshness remains a guard failure rather than a fictitious zero-counter heartbeat. Phase transitions do not extend the600-second no-retirement cap. No finite source-proven long-phase exception is asserted here. If a phase lasts past30 seconds without returning, the guard must STOP instead of treating a receiver timestamp or a cached counter as a new producer observation. A separate model-reading timer would race accounting and is intentionally absent. Source preparation therefore does not claim real-workload freshness qualification; the first authorized arm may spend its start and fail this guard if every prelaunch gate otherwise passes.

## Terminal causality

`BOUNDARY` terminal records classify a reached explicit model limit as `end=LIMIT`; only complete command exhaustion, empty kernel list and no limit produces `end=NATURAL`. That `NATURAL` candidate is deliberately weaker than a natural successful terminal receipt: final acceptance additionally needs strict expected input/ROI/instruction/CTA/options closure, no guard STOP, no deadlock/abort/late contradiction, the registered actual simulator's natural exit0 and full event/loader closure. Existing main's textual footer and exit0 can follow a limit and are insufficient.

A normally returned loop that is neither complete nor limited emits `end=ERROR`. Signals, fatal asserts, `_exit`, exceptions or a killed process may emit **no** producer terminal. The guard's authenticated process outcome must then synthesize the separate protection/abort terminal receipt, invalidate any completion candidate, stop/reap only proven owned instances and leave cycles unaccepted. No async-signal-unsafe “last packet” handler is installed. An abort after an earlier natural candidate still invalidates it; receiver acceptance cannot stop at the first candidate.
