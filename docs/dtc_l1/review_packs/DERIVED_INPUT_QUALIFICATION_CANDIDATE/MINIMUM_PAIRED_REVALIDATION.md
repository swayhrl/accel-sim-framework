# Review proposal only: minimum new-input comparison scope

There is no launch authorization in this document. User final review precedes Lane A's formal input admission and new immutable attempt registration. Every existing Hotspot HOLD remains. B does not modify the 44-row plan, attempt identities, scheduler, parser or runtime binary.

The minimum comparison set for a main Hotspot baseline/IO/OO claim is **three new attempts: B16-N, IO and OO**, all consuming the exact same new derived bundle identity. Lane A must choose and freeze a common compatible Framework/Core/binary, unchanged simulation model/config policy, input-list identity and full instruction scope before registration. Historical baselines on another Core or input are not substitutes. No particular existing binary is preapproved for this future set.

| Intended claim | Minimum additional new-input arms | Reuse constraint |
|---|---|---|
| Main IO/OO versus B16-N | B16-N, IO, OO | All three must share the derived input and common matched model identity |
| Capacity-matched TC80 comparison | TC80-N, and the new-input IO/OO arms actually compared | Reuse only newly admitted matching derived-input receipts, never old TC80 results |
| TRAD96, IO128 or WAIT128 control claim | Only each named control actually used, plus its new-input matched reference arm | Existing unlaunched controls remain held; no blanket launch of all 12 historical labels |
| Modern baseline extension | A separately reviewed modern baseline and every arm actually compared | Outside this round; no modern capacity implementation or SM89 adaptation is proposed |

CPU preflight before any attempt: independently verify the new bundle/member/list hashes, approved model/normalizer hashes, exact six-PC delta counts, full explicit-list address checks, original instruction/control-record invariance and compatibility with the chosen consumer. Existing frozen oracle plus candidate differential checks provide evidence, not A's final admission decision. If A selects another consumer/build, it must establish compatibility for that consumer before registration.

After each future run, Lane A performs strict terminal/invariant validation, full expected dynamic-instruction scope and existing arm-specific checks under a new immutable identity. `terminal_validation` and `scientific_promotion` remain separate. Record a new scientific input namespace, e.g. HOTSPOT_SOURCE_PROFILE_RECONSTRUCTION_V2, and its bundle digest on every receipt.

Do not divide a new-input cycle count by an old-input baseline or combine mismatched arms in a geometric mean. Preserve old raw traces, cycles, receipts and scientific-promotion holds as original frozen-model evidence. A twelve-workload aggregate would additionally need resolved applicability/admission decisions for every included input; this pack's narrow eleven-input review is not blanket qualification.

The new Btree/LUD/2DConvolution format risks are separate review items. This proposal does not authorize correcting their addresses, changing their scientific input definitions, stopping their jobs, changing current acceptance, excluding them from the set or launching new paired runs for them.
