2. Fixed certificates and compatibility with running supervisors
Only 1 of the fixed 33 certified generations is still live; actual discount
is 0.410 GiB. New generations do not inherit certificates automatically.
Their eventual disappearance returns scheduler/frontends to full forecasts.

Source evidence (full paths and SHAs in SOURCE_REFERENCES.json):
- l2_resources.py:166-167: runtime fresh=False forces physical_RAM_pass=True.
- padding_overlay.py:83: runtime preserves that base flag.
Thus a scheduler seeing a new fresh-admission discount while an old runtime
does not see it does NOT by itself trigger MEMORY_HEADROOM. Disk, own RSS
caps, lifecycle and all other original guards remain active.
The actual frozen B5 project method passed a minimal CPU counterexample:
budget=40, old growth=50, fresh discount=15 -> fresh growth=35 passes, while
old runtime decision remains false but physical_RAM_pass remains true.

The real danger is overwriting pinned B5 policy/certificate/source paths.
core:65 checks policy and certificate SHA on every call, including runtime
False. In-place replacement raises; native finally:236-238 may kill the
healthy model and leave no normal DONE. A second actual-B5 CPU case proves
this failure. A new immutable version path leaving old bytes intact does not
break the old runtime. Ordinary HISTORICAL_RSS appends and registered changes
to unspent estimates are different and do not imply that failure.
Changing shared RESOURCE_POLICY.json may not RAM-kill an old runtime, but old
padding strict construction at core:47 still checks its old base-policy SHA.
That can HOLD old acceptance. No-TERM does not mean old evidence is valid.

Future certificate or prediction changes require a fresh-only versioned
operational contract, qualification, registration and per-generation strict
dispatch. Keep old files and proof paths through their natural completion
and strict/archive closure. Complete version isolation can coexist with old
supervisors; if the implementation requires replacing a shared pinned path,
wait for its referencing supervisors to close naturally before retiring it.
Existing candidate_full_original uses max(canonical,new forecast), core:60-63.
A certificate/history refresh cannot silently lower a new Lava candidate from
81.18 to 74.32 GiB. A properly evidenced new LIVE Lava certificate might save
about 6.859 GiB per generation, but that is not currently registered and does
not prove a third slot. The 128-MiB structure margin is an empirical convention,
not a proven absolute bound.
