# Finite engineering canary priority lease — qualified candidate only

This is an operational qualification exception for the single already-registered
cohort in ACTIVE_MEMORY.allowed_cohorts. It adds no grant or scientific point,
changes no SF/full35 inference gate, and does not select by measured speedup.
Nothing is installed by import or by the CPU qualification script.

The unchanged E chooser runs first. Every ordinary E decision wins unchanged.
Only E HOLD may invoke the current aging.original([exact finite canary]), which
is the actual memory348 → a650 → complete B5/f3 chain. This borrows virtual R
priority without changing R or minting natural-release credit. Both fresh
checks retain the complete B5 peer/live/claim projection, canonical/forecast
maximum candidate cost, .95/10GiB arithmetic, pressure, disk, inode, own-write
and CPU gates. Native prepare/run-native independently use the already-installed
immutable memory V2 frontend and complete joint strict. No runtime override is
added. Outside-canary workers and all healthy models keep their current routes.

Installation wraps only gate.original_choose and observes the unchanged CPU
wrapper's final return. CPU/frameguard closures, executor/claims objects,
aging.original, resource functions, canonical bindings and worker routes are
not replaced. Main must ensure B34's obsolete one-shot layer is restored first.
An immutable UUID-named RESERVED receipt and CPU_RETURNED receipt are fsynced
before returning a priority decision to the original dispatcher (before CLAIM
and INTENT). Failure to write either returns HOLD. Receipts include source,
QA/readback, memory config and canonical spec SHA plus both full resource proofs.
No existing receipt is overwritten. An unspent, unclaimed, no-INTENT/no-DONE,
no-active-worker cohort may retry using a fresh immutable engineering attempt;
this is not a model retry and never refunds a consumed identity. Ordinary
registry/CPU logic still creates or rebinds canonical dispatch bindings.

Main-only activation after publication/all-byte readback:
1. Copy priority_lease.py and CPU_QUALIFICATION.json to the template deploy path.
2. Create verified PUBLICATION_READBACK.json with the exact source/QA/dependency
   joins shown in its template. Templates deliberately cannot activate.
3. Write ACTIVE.json from ACTIVE.template.json with ACTIVE_FUTURE_ONLY and the
   real readback SHA; create attempts directory. Require ACTIVE_MEMORY remains
   exactly the same singleton FINITE_CANARY, including its SHA and sourcepins.
4. Record exactly priority_lease.record(cfg) in q.additional_operational_overlays
   via Main's existing locked authority operation; no budget/consumed/R changes.
5. In the existing sole owner's main thread call apply_in_owner(ACTIVE.json),
   retain the object/token in __main__, and persist scalar-only ACK. It validates
   actual parent PID/start against EXECUTION_PLAN, current lease and exact chain.
6. After canary is spent/INTENTed this exception cannot reapply to it. Restore
   with restore_in_owner() before any broad memory scope update. Restore refuses
   to overwrite newer wrappers and preserves all immutable receipts.

Qualification: CPU_QUALIFICATION.json runs real frozen E, B5/f3, a650, memory348,
CPU rebinder and FrameGuard modules in private isolated objects. Authority,
resource samples, no-model running map and readback are explicitly synthetic.
40 checks pass, including physical/source/finite-scope/claim/spent/INTENT/DONE/
token faults, normal E priority, exact restore and zero-start fresh-attempt
retry. No real owner attachment, simulation, signal or production mutation.
The fixture file is a documented small derivative of B32's frozen fixture;
its original production dependency pins remain unchanged. CPU temp directories
are evidence only and are excluded from the delivery manifest.

## V2 minimal engineering corrections

V1 remains byte-identical and is not installed. V2 preserves the exact original
FrameUnavailable class from type(gate).choose.__globals__. A sentinel raised by
old E or by fallback's bounded fresh frames propagates into the unchanged guard,
which restores aging.state.__dict__ and aging.calls. Other old E call exceptions
are translated to that exact sentinel with UPSTREAM_E_CHOOSER_ENGINEERING_EXCEPTION
evidence, not mislabeled as a JSON fault. Exceptions from the outer CPU callable
become an explicit engineering HOLD, so they cannot terminate the scheduler.

When a genuinely validated memory configuration has transitioned to broad scope,
V2 calls only the ordinary prior E/CPU chain. It neither borrows priority nor
requires the obsolete finite config SHA. Current broad source/authority joins
must still validate. Unknown/invalid scope, missing registration or source drift
remain fail-closed. Main can still explicitly restore this adapter before broad
activation. A merely changed in-memory context without its matching active file
and authority record is not treated as a valid broad transition.

The six new CPU cases exercise mutated-R old E exception rollback, unchanged
sentinel identity/status rollback, actual bounded three-read failure in fallback's
second fresh frame with full state/call rollback, an outer CPU exception, broad
HOLD without borrowing, and broad ordinary E decision pass-through.

## Canonical SHA timing — not an INTENT identity claim

The priority receipts' canonical_spec_sha256 is the canonical SHA at chooser
return, BEFORE the unchanged l2_ops dispatcher may call
l2_registry.refresh_pending_resource_spec. It is not claimed equal to INTENT's
spec_sha256. This adapter does not create a dispatch binding or interfere with
that refresh. The later exact audit must traverse resource_spec_history/<cohort>/
<newSHA>.AMENDMENT.json and its <oldSHA>.json preimage. Each transition must prove
both byte SHA endpoints, cohort, and that ONLY estimated_peak_model_RAM_bytes,
limits.max_process_tree_rss_bytes and limits.max_process_tree_vms_bytes changed.
All other limits (including timeout/output cap), complete input/config/physics/
clock/source/argv identities remain exact. Then the final newSHA must equal
q.admitted_specs, dispatch_binding.canonical_spec_sha256 and INTENT.spec_sha256;
dispatch_binding.resolved_spec_sha256 must hash the final canonical spec with
its recorded host_cpu. INTENT SHA/UUID must join the actual consumed row, with
normal launch/PID memory+IO(+padding) bindings and native strict/archive proofs.
Missing/ambiguous transitions, a changed fourth field or stale DB are unproved,
not acceptance. No actual INTENT linkage or real model success is asserted by
these CPU tests. CANONICAL_REFRESH_AUDIT_CONTRACT.json records these obligations.
