# Inactive V3 primary and IR observation entry

Complete candidate implementation; no production installation, registry edit,
new model, Git action, or ACTIVE_ENTRY is made by this package. Real engineering
four prerequisites are missing, so production validation and installation HOLD.
CPU QA/readback flags describe mechanics and never authorize actual release.

The new absolute entry/private worker uses the unchanged native, observer,
atomic IO and CPU2 stack. Only selected strace argv gains one seccomp-BPF flag;
full simulator argv, all270 options, Core/Framework/binary/input remain fixed.
Existing engineering4 retain exact V2 mode/worker, and old/non-scope jobs retain
the exact previous route. No old native path or global subprocess is patched.

Scope is derived from actual registered unspent MATRIX primary points and the
official exactIR11 records/frozen recovery plan. It is not a copy of today's15
pending cells. No unregistered, unknown, unresolved, reference or supplemental
identity is promoted. PRIMARY/IR cycles are not compared to P0 or failed cycles.
IR remains excluded with no automatic union. Full new natural strict/archive
is mandatory for every actual run.

Before any selected INTENT, the source-bound actual4 release verifier must
replay all four V2 original/CPU2/IO/observation strict and real archive/native
restoration. A CPU gate requires a private root and both qualification flags;
it always remains nonproduction. Unsupported activation/fallback is unaccepted,
and no consumed UUID is retried or downgraded.

The worker writes an immutable zero-credit routeclaim before calling the
private original worker clone. Snapshot and three bindings pin that claim,
source set, policy/gate, current canonical/resolved CPU identity, scope/matrix,
memory config and deterministic original-SCOPE P0CH trace reference (DH only
if no CH). No cycles select the trace contract. This signpost prevents omission
of all new observation fields from silently taking the old consumer path.
An admitted dangling claim blocks worker/consumer restoration. No claim is
silently deleted. Existing running jobs born before activation are not relabelled.

See INTERFACE.json for exact five native copy paths, config assembly, QA/readback
schema, release export and installation/restore calls. cfg_metadata.py reads and
returns data only; it does not write configuration or authority. Actual4 capture
must precede V3 consumer wrapping and must be outside authority EX. Main must
drain pre-exec claims and preserve same owner/frame/pool/claims; independently
qualified IR memory and view integration is outside this package.
