# Repair postprocess V2 — metadata-only publication, 2026-10-26

This package preserves exact bytes of the independent V2 metadata reviewer and
finite metadata consumer, their CPU/read-only qualification, existing user
authorization, R14 publication binding, and runtime/source recovery metadata.
It contains no simulator binary, runtime library, archive tar, captured trace,
or raw simulation log. The source-manifest JSON describes separately retained
assets; copying this JSON does not copy those payloads. Existing 214-file and
178-file publication packs remain unchanged.

All ten engineering sentinels completed their native simulations naturally.
The registered V1 strict template nevertheless has two metadata defects: the
sentinel expected option echo inherited an unrelated old 6M-trace path, and the
IO/OO/SECTOR counter contracts use the requests spelling instead of the printed
credit spelling for the same Core9eed accounting functions. V2 corrects only
these exact, source-bound metadata fields in a private replay. It retains all
other 269 option comparisons, the complete instruction/CTA/kernel population,
all remaining counter contracts, BA decisions, raw/progress/terminal protocol,
resource, generation, runtime binary and source identity checks. It does not
edit the registered strict source, request.strict_sha256, canonical specs,
simulator sources, binaries, original runs, or native execution receipts.
The thirteen ordinary repair points receive zero metadata corrections.

The consumer preserves the original R14 ENGINEERING results and writes separate
POSTPROCESS_V2 results. It cannot start or retry a scientific model. It waits
for each point's DONE, registry execution_receipt, and final R14 RESULT. For an
existing archive it independently verifies the 164 archive/native restore and
writes V2 evidence outside the archived output directory, preserving manifest
bytes. For a naturally completed sentinel with the known V1 ENGINEERING result
and no archive, it performs the full V2 replay, writes an explicitly V2 science
qualification under the closed-copy lock, then uses the pinned COPY164/native
restore path. It never treats a native failure as PASS; accepted_cycles remains
null. COPY lock contention may wait; unexpected errors become review issues,
with no automatic model retry. Execution requires a separate root activation
receipt after exact-byte publication/readback, with at most four metadata
workers. The included activation TEMPLATE is not an activation receipt.

The CPU qualification passed 16 fakeRoot/AST safety cases and read-only complete
terminal replays for five mixed sentinels plus an already V1-qualified/archived
BFS-DH ordinary point. The latter also passed independent archive/native-restore
verification. These checks appended no live output, science qualification or
R14 result; performed zero COPY calls and zero authority changes; and started
zero scientific models. A missing-activation negative was refused before locks
or worker creation. The unpublished first CPU binding draft is preserved in
ops as a preimage and is not this package's final execution binding.

This publication is not a claim that the finite validation request is complete
or that all points passed. The reported 15-DONE checkpoint did not mean all 23
points were PASS. Two lavaMD validations failed with bad_alloc under the old
16GiB hard cap; a separate two-point memory request is being prepared and is
outside this package. No such new request is launched or authorized by this
metadata consumer. The original full matrix also retains its historical missing
execution-receipt gaps and remains incomplete; V2 does not fill those gaps or
merge repaired correctness evidence into the original performance statistics.

Runtime recovery receipts bind the separate 164 tar and independent native
restore of the 45 required runtime files plus complete tracked Core/Framework
source and provenance. All fast-tier source assets were kept. The included
SOURCE_MANIFEST is an index, not payload. Its exact canonical source paths and
SHA/mode entries are recovery evidence rather than active-path installation.

After all 23 independently verified archives/native restores, the consumer can
write a new REPAIR_VALIDATION_CLOSED_V2 receipt and modify only this request's
state=CLOSED, reserved_write_bytes=1GiB metadata floor, and validation_status.
It preserves budget/consumed rows, all peer requests, and the registered R14/V1
history. A V2 closure does not claim a registered V1 terminal/closure PASS.
