# CORE32 controlled-Oracle opportunity analyzer: CPU implementation V1

This is a reusable read-only analysis module, **not a final CORE32 result**. It consumes S v2's already-closed structured snapshot and immutable derived kernel facts. It never reads raw model logs, imports scientific launch/management code, changes the running consumer/watch, or touches Core, requests, budgets or ledgers.

The frozen population is always32 complete-input SHAs x four DH modes=128 cells, with a separately labeled initial8 subset. All statuses stay present. Current immutable example has8 runtime-accepted cells,8 identity/work-supported cells, and only two accepted matched pairs:vectorAdd M andL1. The other accepted rows have no matched OFF yet, so S/H remainnull. Four-cell common accepted coverage is0/32. These are preliminary runtime-closer observations; final independent review is retained separately.

## API

`oracle_opportunity_analyzer.analyze(snapshot, matrix, kernel_facts, *, matrix_sha256, expected_build_identity, expected_configs_by_mode, snapshot_sha256=None, c1_context=None)` is a pure function with no filesystem or process operations. `kernel_facts` maps exact plan_id to S's complete flat KERNEL_FACTS dict. The caller must SHA-check cache bytes; the CLI does this. `expected_build_identity` pins Core/Framework/executable/libcudart, and mode configuration lists pin all five ordered config-file SHAs. Settings here come from Main's frozen source/build and configuration contracts.

Only the exact18b1 authority, CH budget0 and complete32x4 DH matrix are supported. Duplicate/foreign/missing slots fail closed. Each accepted row must have matching fixed source/build/config identities, spec/strict/plan/result/kernel SHA references, and complete frozen ROI work. Actual kernel ordinals/names, active instruction counts, cumulative CTA differences and explicit noncumulative cycles are checked. Matching OFF must additionally have the same original270 option-vector hash and ordered kernel work. The analyzer consumes runtime ROI/strict evidence; it does not independently recapture or reread original traces and does not assert identical cross-warp issue order.

## Statistics and evidence

S=actual_OFF/Oracle and H=1-Oracle/OFF preserve slowdowns, negative H and exact-zero responses. Each mode has its own accepted matched subset GM, explicit fixed32/fixed8/suite denominators and missing counts. Pairwise mode and four-cell intersection GMs use the same accepted inputs; different-denominator subset GMs are never presented as direct comparisons. No per-program best-Oracle GM is computed.

All32 program records retain modes/statuses/UUIDs, unaccepted observed cycles, negative/HOLD/failure proofs, engineering-event references, final-review status and source pins. They include actual mechanism exposure, real per-kernel cycles, Tag/request/Physical/PIB/Ref and finite-service counters, traffic and exact sparse proofs. Printed missing values remainnull; source-proven derived0 is separate. Kernel counters are copied as printed without invented reset/delta semantics. Whole-input service occupancy means are derived only when printed samples match64xwhole-input cycles. None is promoted to a saturation, causal critical-path or implementable-headroom claim.

Historical C1 actual downstream/structural results are copied as a separate32-input metadata context with their original source/build/acceptance identities. Historical negatives/HOLD and exploratory best-observed references remain labeled. The code never uses C1 or historical DH0 to fill current OFF or compute Oracle GM. C2 remains a controlled counterfactual; neither its speedup nor differences among modes constitute a mathematical, additive or feasible-DTC upper bound.

## Replay and integration

`run_closed_opportunity_analysis.py` reads one S snapshot and only SHA-named flat KERNEL_FACTS gzip files alongside it. It supports immutable copied bundles, verifies every cache SHA, and writes into a new independent output directory. It never follows raw_path. Example source/output is under `early_eight_accepted_final_v1`; INPUT_PROVENANCE.json pins the snapshot, matrix, settings and kernel caches. Main/S may call the pure function after a new closed fingerprint; this package does not install any hook or watcher.

`qualify_opportunity_analyzer_cpu.py` passes43 CPU checks/mutations, including slower Oracle, missing OFF despite historical/C1 cycles, mismatched source/build/270/config/ROI/kernel work, repeated kernel names, invalid cumulative fields, negative/HOLD preservation, independent/four-cell GMs and null/derived0 separation. The real8-accepted copied snapshot also passes all identity/work checks with0 raw reads. Future new closed results must retain the same rules and all missing/negative rows.
