# Read-only unified Oracle data consumer V2

This independent adapter consumes the frozen initial eight programs (32 accepted cells) as immutable data, and the separate private remaining-24 root as a new operational generation. It does not register science, authorize execution, inspect live owner processes or locks, start models, run a dispatcher, change source/binary/configuration, write archives, or publish Git commits.

The frozen S4182 consumer is loaded into a private namespace. Only its two-stage directory enumeration is replaced by explicit roots; its original strict/native/archive/restore acceptance routine remains the new-result acceptance routine. A narrow wrapper copies pinned initial-32 result identities and existing kernel-fact caches. It never reopens old raw logs or applies old owner PID/context assertions. Frozen S source bytes are unchanged. The approved M b5c analyzer remains unchanged and retains constant CORE32 denominators, per-mode and common-intersection GM, null/negative/HOLD cases, and separate historical C1 context.

## New private operational binding

The reader checks final plan phase and authority, fixed 96 slots/24 inputs/zero CH budget, input/mode/cohort scope, exact scientific build and five configuration SHA values, new parent PID/start metadata, private lease/controller/guard metadata, explicitly pinned new-root operational source (including oracle_successor_engine.py), and the final source-forward receipt. The portable scientific RESULT_ENGINE_PIN is not mistaken for a private operational-engine pin. No requirement for legacy PID continuation or an old Python frame is imposed.

The final-bind receipt is preregistration CPU engineering evidence only. It cannot make a result accepted. A new accepted result still requires the original real RESULT UUID, natural terminal state, strict lifecycle/work/configuration evidence, true164 archive and native restore receipts. The reader does not independently renew or establish a live lease: runtime enforcement and final independent data review remain separate. Completed results do not require the former parent to remain alive.

## One-shot API

`snapshot_once(bindings_path, out_dir, analyze=True)` writes only its requested derived output directory. Main may call it on a publication cadence; this package installs no watch loop or publisher. The CLI is:

```sh
python3 -B oracle_unified_roots_consumer.py --bindings UNIFIED_BINDINGS.fixed.json --out /independent/derived/output
```

The binding file pins fixed matrix, science settings, unchanged S/M modules, frozen initial32 snapshot/manifest/final data review, and the private remaining24 root. The new plan and final binding are checked at each refresh. If the new stage remains CPU draft, its cells remain unregistered. If a closed result lacks valid final binding or acceptance evidence, it remains HOLD; negative states and observed-but-not-accepted cycles are retained.

## CPU qualification and actual data snapshot

CPU_QUALIFICATION.fixed.json records 46 passing cases: source/identity/scope/lease/receipt mutations, forbidden old PID context, missing source and changed build, fake PASS with only a CPU receipt, retained negative/HOLD cycles, and constant 128 slots. A guarded real projection rejects all /proc and raw/stdout log reads while preserving all 32 old UUID/resultSHA/cycles. Synthetic rows are confined to temporary CPU-only directories and are not scientific identities.

At this package freeze the actual data projection is 32 runtime-accepted cells and 96 CPU_DRAFT_UNREGISTERED cells. Initial program coverage is 8/32; this is not a complete CORE32 experiment. The old eight-program uniform-mode GMs remain M=3.4462853178256734, L2=2.103432830863556, L1=5.106115891060019. Future actual accepted cells may change coverage; CPU qualification never does.

Counter missing values remain null; source-derived zeros require proof. Oracle-M retains ICNT-full admission and finite per-cluster 32B round robin; L2 and L1 are distinct controlled counterfactual paths. Their cycle differences are not additive, mathematical upper bounds, or promises of realizable DTC gain. No per-program best-Oracle GM is constructed. Historical Tag safety HOLD, capture/numerical limitations and English v0.23 freeze remain in force.

The CPU draft actual projection and synthetic output are immutable examples; caller-selected future snapshots must use new output directories or deliberately owned mutable derived locations. Frozen package manifests must not be overwritten by later execution.


## V2: finalizer schema compatibility and declared external evidence

V1 remains immutable and records the independent review findings. V2 accepts the actual finalizer's `no_same_PID_exec_continuation: true` generation marker; the older explicit `same_PID_exec_or_legacy_frame_required: false` marker remains compatible, while contradictory flags are rejected. All private operational controller/guard/lease/engine paths remain restricted to the new root. Other source pins can be external only when the exact resolved path and SHA are predeclared in `remaining24_private.allowed_external_source_pins`; each is still hashed. Prefix similarity grants no permission.

The shipped binding has an empty external allowlist because there is no real final binding yet. Main must create a new caller-owned binding file from the independently reviewed actual final source-forward plan/release and explicitly pin its approved external references. A final plan's unreviewed external paths are not automatically trusted. This adapter does not write or install that science plan.

`qualify_actual_finalizer_product_cpu.py` directly calls frozen finalizer 646310 on a disposable CPU tree, using the existing independently tested complete-finalizer fixture structure. It substitutes only a declared MOCK parent/guard and relocates private references to the temporary CPU tree; actual scientific spec/config/input bytes and the real finalizer metadata/source/96-layout logic remain unchanged. It does not invoke the production finalizer, install the native route, register a request, or claim actual final metadata exists. The actual function's generated new-marker plan with six declared external evidence pins is accepted by the read-only binder. Removing that allowlist or changing one external SHA is rejected. This additional fixture supplements the 46-case qualification, and distinguishes real function-produced schema from handwritten mock metadata.

The first real clean-owner attempt failed closed before registration and has no actual final plan/receipt. The actual snapshot remains 32 accepted old cells plus 96 CPU drafts. Engineering attempts or this CPU finalizer fixture do not consume scientific budget and do not add accepted cells.
