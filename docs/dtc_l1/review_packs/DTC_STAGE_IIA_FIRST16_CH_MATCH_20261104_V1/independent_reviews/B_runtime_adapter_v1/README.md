# Actual-schema read-only result adapter V1

`actual_readonly_adapter.py` consumes only the16 fixed `E2-DTC2A16-...-CH-F128/F256-V1` points in the source-SHA frozen B contract. It never imports or calls native model engines, registrars, dispatchers, result producers, archive writers, owner callbacks or controllers. It never signals processes. All outputs remain in a new child snapshot directory here.

It verifies the current exact epoch/registry pair and this request's16-grant scope, canonical registered SPEC SHA, EXECUTION_PLAN source pins, original32 reference SHA, full effective options/config/input binding/ROI/build, matching intent/DONE/native EXIT/UUID, and dispatch binding. Successful performance requires exactly `PASS_STAGEII_CH_STRICT_ARCHIVE_NATIVE_RESTORE`, `STAGEII_AUTHORIZED_CH`, actual `L2_STRICT.json` equal to RESULT.proof, `DTC_STAGEII_FIRST16_STRICT_V1`, qualified status, accepted cycles, and Root's matching SCIENCE_QUALIFICATION strict SHA.

Archive checks cover same-UUID local/archive receipts, genuine164 mount, exact task namespace, SOURCE_MANIFEST canonical SHA, COMMIT/index canonical SHA, every archive chunk and concatenated stream SHA/size, native restore proof rows plus every restored regular-file SHA/size on native device2128, and critical source-file SHA against the manifest. It does not extract, reconstruct or rewrite an archive or re-run strict raw parsing. The source-pinned existing outbox owns tar construction and independent archive verification.

`FAIL_STAGEII_CH_ARCHIVED_NO_RETRY` can be reported as a verified same-UUID archived negative with cycles=null and performance_accepted=false, without a strict file. It can never become accepted performance. Unknown, partially written or mismatched evidence becomes HOLD/missing with its reason; no retry or model identity is created.

After verification, the adapter emits the SHA-bound `OBSERVATIONS.json` interface and exercises the frozen B consumer's source loader and paired-statistics logic. It reports S_CH/S_DH/R/I, exact per-F sets, the common F128/F256 set and first8-subset GM. Pending/negative/missing rows stay visible. No IR/R2/EP/PQ/PS or best-per-program replacement occurs.

Usage: `python3 -B actual_readonly_adapter.py --output-dir <this-directory>/snapshots/<new-unique-snapshot>`.

The output directory must not already exist and must stay beneath this adapter directory. No-source-result operation legitimately yields16 missing rows,0accepted quads; the initial actual-native smoke is retained under snapshots. Root can run this command from the existing result-consumption/background path; it is not another simulation controller.

CPU qualification uses17 synthetic fixtures, explicitly mocks device number only for archive-restore file tests, and does not grant native hardware/scientific qualification. The fixtures test safe paths, success integrity, archive-only negatives, corruption of chunks/restored/source members, strict absence, source-overlay mismatch, scientific-status abuse, wrong namespace and commit/index mismatch. The existing18 B formula/identity tests remain frozen separately. A naturally completed real accepted CH point must still pass this adapter before claiming that actual path qualified.
