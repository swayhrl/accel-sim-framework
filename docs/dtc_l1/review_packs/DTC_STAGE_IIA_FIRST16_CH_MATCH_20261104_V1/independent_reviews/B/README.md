# Agent B — First16 read-only analysis preparation

Fixed plan: `5001c3f35052f7f91f1ad41eeff83f2947a0878d`. Exactly the predeclared eight programs and16 CH F128/F256 slots. This agent does not register or dispatch models, signal owners, or modify original sources. Root owns execution and Git publication.

- `ANALYSIS_CONTRACT.json`: expected16 CH cohort/input/profile/config/options/ROI bindings, with fixed32 original comparison references.
- `BASELINE_REFERENCES.json`:32 exact original CH-P0/DH-P0/DH-F sources, RESULT/spec/input-binding SHA, build/config/options and P0 reuse disclosure. No IR/R2/EP/PQ/PS substitution.
- `readonly_first16_consumer.py`: read-only SHA-bound index consumer; computes S_CH, S_DH, R and I with the fixed plan's statistics code. It preserves every pending/negative row and reports per-F paired sets and the identical common F128/F256 set. GM is labelled first8 subset, never full35/core32.
- `OBSERVATION_INDEX_TEMPLATE.json`: pending-only interface template. It is not execution registration, a qualified result index, or acceptance.
- `CPU_CONSUMER_QUALIFICATION.json`:18 synthetic CPU checks, including mismatched identity/build/clock/lineage, duplicate, negative/missing and common-set tests. Synthetic values are never written into production result tables.
- `HISTORICAL_ETA_AND_PERFORMANCE.md`: existing32 native elapsed/RSS references, original performance and existing phase-cycle evidence.

The consumer CLI reads existing RESULT/spec/input-binding files and verifies SHA before using baselines. For new accepted CH observations Root must provide an exact SHA-pinned observation index using the documented interface. The current production adapter remains pending Root's actual strict/archive schema release; CPU formula qualification does not certify a future runtime consumer hookup.

Each accepted index row supplies exact normalized identities (`input_binding_sha`, ROI/build/downstream fingerprints), config SHA list, complete effective options, cycles, UUID and role `STAGEII_AUTHORIZED_CH`; `qualification` must contain true flags `strict_pass`, `actual_input_verified`, `actual_build_verified`, `actual_effective_options_verified`, `natural_exit_verified`, `true164_archive_verified`, `native_restore_verified`. `sources` maps RESULT/SPEC/STRICT/ARCHIVE_RECEIPT/NATIVE_RESTORE to exact JSON paths and SHA. The Root-qualified index is an authority input, not a certificate invented by this agent. Source RESULT/proof and SPEC identities are independently cross-checked; schema-specific archive/restore semantics must be supplied by Root before deployment.

Usage after Root schema hookup: `python3 readonly_first16_consumer.py --root-index <root-qualified-index.json> --root-index-sha256 <exact-sha> --output-dir <new-immutable-snapshot-dir-under-B>`. Without a Root index it emits16 missing rows and zero accepted quads, as verified in `snapshots/BASELINE_ONLY_NO_NEW_CH_V1`.

CH/DH downstream matching does not establish equal L1 area, capacity, queues or timing. F expansion changes FR-FCFS window and shared credits together. No best-per-program configuration selection, cross-population GM comparison, missing-as-one fill, or simulated combination prediction occurs.
