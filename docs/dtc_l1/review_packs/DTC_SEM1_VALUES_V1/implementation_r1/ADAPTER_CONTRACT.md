`tests/dtc_l1_sem1_values_ldst.cc` adapts the fixed AG3/Y2 ABI technique: real GPU/cluster/core/LDST, synthetic coalesced instructions fed to actual `issue`, real `mem_fetch` replies fed to actual `fill`, actual LDST `cycle`, actual operand-bank conflict, real pending writes/scoreboard/ledger and Ref accounting. It does **not** call GPU `cycle()`, launch a kernel, replay trace, start runtime threads or acquire an execution lock. Per process max140 LDST component cycles, one SM, one memory channel. Source seed/schedule variants not implemented are not counted.

Producer refill bytes and expected memory are independent fixture arrays; only producer packets are passed into Core. Expected values are consulted only after actual collected-sector output. Wrong-byte injection modifies the packet while expected memory stays fixed. A raw observer-memory lookup or expected-value writeback is absent. Initial bytes and externally selected publication times are assumptions, not inferred from timing completion.

The narrow possible result is **CONDITIONAL_PRODUCTION_SECTOR_ROUTING_VALUE_TEST**. It tests explicit bytes through actual accepted return, physical-generation storage, finite collection and successful WB output boundary. It does not compute an architectural destination register, functional instruction result or actual CUDA application output; the final requested-byte extraction is a fixture-side inspection of the sectors actually collected. It cannot establish native, ISA, general store propagation, actual load/store alias correctness or coherence. `no-e` executes no store: it is a conditional countermodel under explicitly external publication, not an observed production store or application wrong value. `with-e` invokes selected source E at the real LDST entry; it does not pretend to validate E's upstream idle/MEMBAR guards again.

Preparation can close this **bounded conditional route** without a functional ISA. General real-trace architectural values still require capture-bound payload flow and an ISA/memory/publication model. No such expansion is proposed. Unimplemented original plans (full native output, cross-SM domain, complete late-slot/eviction combinations and fixed-seed schedules) remain gaps, rather than being relabeled passed by the new harness.
