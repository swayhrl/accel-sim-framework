## R1: real child-stop reorder can falsely claim coverage

**Concrete defect**, `qualify_ag5_changed_dispatch_v2.py:172-187` at the reviewed commit. When a real parent fork/vfork/clone event is intercepted, the adapter obtains the actual child PID, manually quarantines it, holds the parent event, and makes just one nonblocking `original(child_pid, flags)` call. If that call returns `(0,0)`, the next adapter call immediately returns the held parent event. The existing `injected` and `seen` checks are already true, and the ordinary guard run can finish successfully. Thus the named `real_child_stop_before_parent_observer` case can pass without ever delivering a real child-stop status to production wait dispatch before its parent event. Manual quarantine and a pending verdict do not establish that wait ordering.

The included `CHANGED_DISPATCH_REAL_ORDER_FIX_PREPARED.patch` changes only that existing adapter and its evidence. It keeps the parent event held while polling only the actual event-proven child with the existing nonblocking flags, for at most one second. It sets a delivery flag only when returning that child's real stopped status to `run_guarded`; only a subsequent call returns the parent event. Successful completion additionally requires both deliveries and an empty held queue. A missing stop fails the case with an explicit bound error. It does not invent a status, create a child, add a case or rerun any old AG5 case. Existing missing-event and forced-stop modes retain their existing expectations. On the local bound error it releases the held parent event to the existing guard cleanup path, which remains responsible for event-confirmed cleanup.

Patch status: **PREPARED_NOT_TESTED**, not applied to the coordinator. The starting qualifier SHA256 is `d643bdd6f7ff32b6b32ff8cbfafd82b164984c125883ae7b6866012d70f13ab8`. Parent integration must update the source closure, exact role closures and immutable registrations before any separately admitted execution. The existing 20-second guard timeout remains; the new one-second nonblocking reorder deadline is a tighter adapter bound. Execution and kernel scheduling behavior have not been validated here.
