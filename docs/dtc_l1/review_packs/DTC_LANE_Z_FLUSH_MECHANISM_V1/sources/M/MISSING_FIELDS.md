# 缺失字段和最小下一步

已知缺口不阻止有身份和明确语义的既有量比较，但阻止相应因果宣称。没有修改旧raw、Core、observer或统计合同。

| 字段或结论 | 状态 | 不能使用的替代物 | 最小处理范围 |
|---|---|---|---|
| GEMM同active PIB128的原IO运行 | UNAVAILABLE | IO256/OO128差不能改称纯组织效应 | 已预声明T0，一个新GEMM IO128，满足T的独立strict/authority门槛 |
| C+ fully-ready/ready-to-collect/collection/WB及map-loss分解 | UNAVAILABLE | conventional response/cache latency、DTC legacy frontend-ready计数 | 如果确有需要，另审同定义默认OFF observer和公平对照；本任务不实现 |
| OO Tag grants/conflicts、PIB拒绝、no-free-pool、allocation-width拒绝的完整终端字段 | UNAVAILABLE | IO的0、低全周期平均占用、ordinary L1D的MSHR/失败 | 现有代码有部分内部getter不代表raw已输出；另审observer；T1不能假装已有完整压力归因 |
| OO duplicate-after-eviction同义在途重复请求字段/地址关联 | UNAVAILABLE | Tag eviction、new miss、map-loss lifetime | 另审以line+generation+request identity定义的默认OFF观察；不能由Tag数倒推重复量 |
| conventional与finite统一ready/pending命中率 | UNCOMPARABLE | 普通cache的32B coalesced访问结果 vsDTC成功去重128B reference；有限主load绕过L1D而出现的0 | 分别报告原值和各自合法分母；不制造统一百分比 |
| PIB/MSHR/Tag/pool失败的互斥stall cycles和饱和时间 | UNAVAILABLE / 现有event语义不能升级 | 含retry事件或名字带_cycles的历史别名 | 新观察必须给cycle去重规则、优先级、overlap及clock；本任务只报event |
| fully-ready之前的完整issue/admission/refill/replay时延 | UNAVAILABLE | DTC11的fully-ready-to-complete | 另审完整生命周期timestamp；不能把post-ready分解当总memory latency |
| 64SM active-only占用或分位数/短时峰值 | UNAVAILABLE于统一定义 | all-SM all-cycle积分均值 | 原PIB/physical integrals包含idle/gated/tail；保留原均值；不按假设active比例缩放 |
| 逐PC/地址reuse距离、Tag miss类型分解及下层请求时间序列 | UNAVAILABLE | global_read、L2/DRAM总体计数的相关性 | 只能提出可证伪假设；Tag/并发/顺序反馈的独立归因需要新有界干预或另审observer |
| per-kernel独立reset的DTC11与独立DRAM字节 | UNAVAILABLE作为统一旧日志合同 | 跨kernel重复累计打印直接相加 | 本次取final累计量；独立kernel周期/指令scope仍可核，不能再累加所有counter快照 |
| actual DRAM read/write payload | AVAILABLE | 禁止credit×128 | 已由issued read/write命令×32及终端CSV sector交叉验证；含所有实际DRAM类，非逐PC归属，非总线控制能耗 |
| lower cap外的全部下层瓶颈消失 | UNAVAILABLE | cap-full=0 | L2 retry、DRAM流量和NoC仍可有压力；不要作排除性结论 |
| 扩大Tag的硬件时序/metadata/面积或功耗 | UNAVAILABLE | 1cycle model、等数据字节 | T CPU先核可配置范围/资源；晋升还需独立holdout和真实硬件成本审查 |

M没有科学raw缺失或身份失败：固定九臂与两条旧DWT2D raw均存在、strict和hash闭合，故不是以包装文件替代payload。上述UNAVAILABLE指其特定观察量未被旧输出采集。原41PASS/3HOLD、全部原输入格式pending、现代容量HOLD、2D STOP、LUD不追加以及原GM12未定义均保持。
