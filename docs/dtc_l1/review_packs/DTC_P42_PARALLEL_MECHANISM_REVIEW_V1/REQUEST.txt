5. 哪些结论足够进入 ISCAS 论文。

### Agent B：访存特征与可重复分类

不要直接按照加速比把应用称为memory-bound。

优先从已有合法trace及CH原始遥测提取：

- 逐Kernel CTA/SM并行度；
- Global load/store及算术指令比例；
- L1→L2请求、L2命中/未命中、DRAM读写量；
- 每条有效指令对应的访存请求强度；
- 唯一128B cache line、重访次数、地址跨度及复用距离；
- 可验证的访存突发与时间局部性特征。

注意32B sector与128B line不能混为同一计数。静态trace的记录顺序不得冒充模拟器真实跨SM执行时间顺序。

先用物理含义明确且与DH性能结果无关的指标定义候选分类，再观察各类别的DH/CH表现。

至少区分：

- L2命中主导；
- DRAM请求主导；
- 高重访/映射敏感候选；
- 低CTA并行度；
- 计算/特殊函数密集；
- 证据不足、暂不可判定。

DM/DH的Hash响应分类可以另列，但不能反过来充当访存敏感性的独立定义。

大输入分析必须有RSS、磁盘IO、扫描范围限制。只生成一次共享地址索引供Agent D消费。

交付：WORKLOAD_FEATURE_MATRIX及CLASSIFICATION_CONTRACT。

### Agent C：DTC高收益微架构归因

重点：

- 2DCONV：CH/DH=3.347×；
- 3DCONV：1.344×；
- particlefilter_naive：1.329×；
- 3MM：1.744×；
- GEMM：1.689×。

必须回答：

1. 哪些收益与Hash关系很小，却来自完整DTC结构？
2. 哪些收益伴随Tag替换、下行读请求下降？
3. 传统缓存MSHR/PIB、Tag访问、完成时序与DTC之间有哪些实际建模差异？
4. 是否存在低估传统路径吞吐或高估DTC服务能力的风险？
5. 可以证明的机制和仍需实验区分的机制是什么？

特别优先2DCONV。它是当前GM最大贡献者，不能继续只分析GEMM。

禁止将不同结构的同名计数器未经语义核实直接相减。对每项结论提供源码、配置、raw计数及Kernel身份。

交付：POSITIVE_CASE_MECHANISM_REPORT。

### Agent D：ATAX/MVT/BICG负收益根因

与Agent B协作，使用同一份地址索引。

固定已选的完整输入身份，分析主要跨步访问Kernel：

- CH与DH的L2访问次数、accepted miss、DRAM读请求；
- 唯一地址/缓存行与重复请求；
- L2替换及时间复用的可观测证据；
- 请求时序、排队和反压；
- 低CTA并行度对访存延迟隐藏的限制；
- DTC完成服务与物理池是否存在独立阻塞。

重点解释：

为什么DH相比CH减少约25%–31%的L2读流量，却产生约14%–32%更多DRAM读取？

不得将低CTA单独当作CH/DH性能差异的原因，因为两者使用相同CTA输入。

将每个假设分为CONFIRMED、SUPPORTED_ASSOCIATION或UNPROVEN，并提出能够区分候选原因的最小后续实验。

交付：STRIDED_WORKLOAD_ROOT_CAUSE_REPORT。

### Agent E：PQ/PS现有实验的独立审查与敏感性评估

本Agent只读消费已发布、已关闭或明确允许读取的状态和证据，不控制正在运行的模型，不持续扫描活动raw。

检查：

**PQ：**
- 确认实际resolved队列是否仅从`64:64:64:64`变为`64:256:64:64`；
- DRAM scheduler、return queue、时钟、L2和其余配置是否保持一致；
- FIFO-full是否消失；
- 阻塞是否转移到DRAM scheduler、return queue或其他资源；
- 完整Kernel及整输入cycles是否改善。

**PS：**
- 确认实际时钟是否仅由`1410:1410:1410:850`变为`1410:1410:1410:1700`；
- Core、ICNT、L2和DRAM周期时序参数实际是否未改；
- 明确频率翻倍同时改变DRAM服务速率和周期时序对应的绝对纳秒延迟；
- 不将其描述为纯带宽翻倍；
- 检查前5%约2×改善是否使用相同语义进度和GPU模型周期；
- 只有在自然完成且严格验收后，才给出完整Kernel加速比。

必须匹配CH和DH，并计算：

`K_PS=(DH_baseline/DH_PS)/(CH_baseline/CH_PS)`

PQ同样计算相对恢复因子。

对未完成点保留PENDING，不预测最终cycles、不用早段结果外推。

交付：PQ_PS_INDEPENDENT_REVIEW；结果暂不可用时输出已完成的配置资格、指标定义及待消费清单。

另外设计但不启动：
- 保持主要DRAM绝对纳秒时序的频率变化对照；
- 必要时PQ×PS的2×2交互实验；
- 针对缺失的服务与队列事件的instrumentation-only最小实验。
