四、定量结论与解释审核

CORE32：
M GM = 1.6767585258096842，正/零/负=32/0/0。
L2 GM = 1.2806486845080634，正/零/负=19/11/2。
L1 GM = 1.9399115770053144，正/零/负=32/0/0。

S = C_OFF/C_mode；GM = exp(mean(log S))，同集合逐输入等权。
H = (C_OFF-C_mode)/C_OFF；1-1/GM(S)不等于H的算术均值。
实际同build OFF是分母；历史DH-P0不能替代。initial8高GM不能代替完整32；总体GM不能通过对四个suite GM不加权平均得到。

L2精确零11项：
3MM、BlackScholes、GEMM、cutcp、dwt2d、gaussian、histogram、lud、mergeSort、particlefilter_naive、transpose。

L2回退：
- myocyte：145147976 -> 145147978，增加2周期。
- srad_v1：7324411 -> 7339063，增加14652周期。

L2近零正响应：
- bfs减少5周期，4170294/4170289 > 1。
- mri-q减少692周期，360174/359482 > 1。
不能把上述正/负关系因显示精度抹为零，也不能将固定模拟中的微小差异直接外推为现实芯片的显著收益或损失。

kernel案例：
- myocyte/L2：5993个kernel，0快、5992相等、1慢；其ordinal 1为25652 -> 25654。M和L1各为32快、5961相等、0慢。
- srad_v1/L2：502个kernel，215快、13相等、274慢。prepare/reduce/srad/srad2/compress/extract分组saved cycles为-1503/-2869/-11304/+1079/-55/0，和为-14652。

- stencil应用整体L2少4398周期，kernel分布仍为52快、2相等、46慢。
- 3MM/GEMM的小案例逐kernel L2精确零成立。
- M比L1快的五项为3MM、GEMM、fastWalshTransform、scalarProd、heartwall；myocyte相等。模式不是已证明单调、嵌套或可加的硬件上界。
这些案例定位周期变化出现在哪些kernel组，尚不证明变化的微架构因果。

计数器：
29,192条kernel事实中，averagemflatency、avg_icnt2mem_latency、avg_icnt2sh_latency各100个显式null，avg_mrq_latency为21156个。上述计数沿用冻结M缺失记录及其资格，未重新扫描raw计数。
未打印字段和显式null保持UNKNOWN；仅具有固定源码证明的稀疏省略零可独立标为source-derived值。32B L2 sector、32B DRAM atom、request object、128B line分别处理。均值、积分、峰值、瞬时gauge和累计值不得任意相减。
ready/collect均值不是关键路径占比；physical占用可能包含Ref-free retained cache；零DRAM不证明compute-bound。

真实性与外推：

六、下一阶段排序与关键反证

第一：有限下游服务与本地完成路径中的一个具体机制。
理由：强Oracle响应与历史有限资源干预的正负并存，支持继续寻找真实有限路径的性能机会。
限定：现有“协同”仍是E3。候选须精确说明改变注入、返回、notify、collect、WB/retire中的哪一个作用点；不能把整个领域名称当成已定义方案。
E2限定：历史F同时改变FR-FCFS窗口与shared credits，并非孤立L2容量干预，也不能单独证明本地完成机制。
主要反证：候选在预测phase未被触发；触发后等待或阻塞只转移到下一阶段；单纯扩容/重排带来同等或更慢结果；有限端口或时序成本抵消改善；所谓效果实际由不公平基线或附带参数改变造成。

第二：PIB/Ref与physical生命周期。
理由：admission、引用注册、完成等待与释放的耦合值得核查；历史小幅和相反响应不支持统一扩容必然有益。
主要反证：高physical占用主要来自可保留缓存而非活动引用压力；候选没有改善受阻准入；扩大一处只将等待转移到另一处；Ref/credit/generation或公平性受到破坏。
该方向可能与第一方向涉及相同的完成/释放事件。最终按一个真实机制组织实验，不因目录名称重叠而另开两套任务。

第三：Tag映射与前进性先验安全。
理由：当前首先存在安全问题，尚不能依据Oracle强响应确定Tag的性能价值。
现有1024Tag/physical640的NO_FREE_LINE安全HOLD继续有效。先在独立合同下明确可达状态、回收条件、Ref/generation保护和外部公平返回假设。有限fixture的通过不等于无条件证明完整GPU前进性。
主要反证：仍存在合法状态下无法回收且无法完成的循环依赖，或修复依赖无限搜索、无成本端口/仲裁和未经声明的顺序保证。
