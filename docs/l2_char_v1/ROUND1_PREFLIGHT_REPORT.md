## Executive answers

* **A — pool width:** there are **159 physical trace roots**, representing
  **155 distinct `(suite, application, input, kernelslist SHA256)` assets**,
  **18,035 kernel-launch trace files**, and 483,226,416,225 bytes (450.04 GiB)
  when their listed trace trees are summed.  This is not merely a 10--20 item
  classic-suite pool.  It contains 66 public full pretraces, 47 derived
  1/10-or-1/40 variants, 27 V100/NVBit staged roots, plus historical copies.
  The byte sum is an asset sum, not a deduplicated disk-footprint claim.
* **B — input scale:** 78 roots contain usable trace-side `stats.csv` totals;
  they account for 5,654,684,409 reported instructions.  81 roots have missing,
  empty, or malformed trace statistics.  Therefore input scale is known for
  only part of the pool and cannot yet be used to call every trace stable.
  Every trimmed root is explicitly labelled `trimmed-derived`; its fraction is
  not silently treated as a full execution.
* **C — comparability:** the pool is **not presently one comparable trace
  population**.  No directly inventoried root records a per-trace SHA256.
  Only 17 roots have a `provenance.json`; public pretraces generally lack the
  exact NVBit/tracer/CUDA/capture-host record.  The formal campaign must first
  group assets by the `asset_family` and provenance columns in the TSV, then
  create a SHA256 manifest for every trace file actually selected.

## 2. Frozen QV100/L2 resource configuration

The table below is parsed from the effective base file
`gpgpu-sim/configs/tested-cfgs/SM7_QV100/gpgpusim.config` and checked against
the implementation where the configuration string alone is ambiguous.

| Resource | Effective value | Verification / interpretation |
|---|---|---|
| Memory channels | 32 | `-gpgpu_n_mem 32` |
| Subpartitions per channel | 2 | `-gpgpu_n_sub_partition_per_mchannel 2` |
| **L2 slices** | **64** | 32 × 2; one L2 cache per subpartition. |
| L2 sets / ways / line | **32 / 24 / 128 B** | `S:32:128:24,...` |
| Sectoring | `S`, 4 × 32 B sectors/line | 32 B sector is the simulator's fixed sector size. |
| Capacity per slice / total | **96 KiB / 6 MiB** | 32 × 24 × 128 B; ×64. |
| Replacement / write / allocation | LRU / back / on-miss / lazy | `L:B:m:L` in the L2 string. |
| L2 set hash | IPOLY (`P`) | `P` is the L2 `HASH_IPOLY_FUNCTION`, not an informal label. |
| MSHR entries / merge entries | **192 / 4** | `A:192:4`. |
| MissQ | **32** | `32:0` before data-port width in the L2 string. |
| DataPort | **32 B/cycle** | final `,32`; hit data and dirty-victim data cycles are `ceil(bytes/32)`. |
| FillPort | shared bandwidth model, **128 B / 32 B = 4 cycles per full-line fill** | no independent width option; implementation uses cache atom size / DataPort width. |
| Partition FIFOs | **64:64:64:64** | ICNT→L2, L2→DRAM, DRAM→L2, L2→ICNT, respectively. |
| ROP latency | **160 cycles** | `-gpgpu_l2_rop_latency 160`. |
| DRAM base latency | 100 cycles | `-dram_latency 100`. |
| DRAM scheduler / queue | FR-FCFS (`1`) / 64 entries | `-gpgpu_dram_scheduler 1`, `-gpgpu_frfcfs_dram_sched_queue_size 64`. |
| DRAM return queue | 192 entries | `-gpgpu_dram_return_queue_size 192`. |
| WB progress credit | 1 per memory channel | Core option default is 1; Round-1 overlay pins it to 1. |
| Partition/address mapping | IPOLY partition indexing (`2`), declared HBM `dramid@8;...` mapping | `addrdec.cc` uses IPOLY over the 64 subpartitions. |

Thus the expected values in the request all match the frozen QV100 base
configuration.  The only important semantic clarification is that
`192 × 4` means **192 MSHR entries with up to 4 merged requests per MSHR**, not
768 independent MSHRs.

### Configuration consistency status

There is not yet a formal broad-workload campaign, so it would be incorrect to
claim that historical Decoupled/TLS/C2P result directories all used this exact
configuration.  They did not necessarily do so and are historical evidence
only.  The new formal observation overlay is
[`qv100_round1_observation.config`](../../tests/l2_char/qv100_round1_observation.config):

```text
L2CHAR enabled; window=5000; set_detail=1; emit_windows=1
dram_issue_hold_cycles=0; dram_issue_hold_after_issues=0; returnq_hold_cycles=0
wb_progress_credit=1
```

It contains no Decoupled, LateBind, sensitivity, or capacity override.  The
base QV100 configuration plus the framework QV100 `trace.config` and this
overlay are the only configuration stack used by the two Round-1 pilots.
Formal campaign launch must hash all three files and reject any workload-level
override; this is a preflight gate, not a claim that it has already occurred.

## 4. Multi-kernel structure and historical execution evidence

`kernel_count` and `kernel_symbols` are exact per trace root in the TSV.  The
NVBit `stats.csv` total is reported whenever populated, but **per-kernel
instruction shares, cycle shares, and L2-access shares are not currently
available for every asset**.  Cycle and L2 shares require a per-kernel
natural-drain pilot or a deliberate per-kernel replay; they must not be
estimated by dividing application totals by kernel count.

Historical completion evidence is likewise heterogeneous.  The TSV's
`same_tree_historical_result` field points only to a result file beside the
identical trace tree; it never guesses a cross-campaign match.  Broader
historical data exists in:

* `accel-sim-decoupled-l2/docs/decoupled_l2_workload_roster_under_5h.md`
  (52 historically completed, prefiltered entries and rough host times);
* Decoupled-L2 `hw_run/decoupled-l2-functional`, archive, and fraction result
  directories;
* TLS/C2P workload catalogues and V100 provenance staging.

They establish that many assets have run before, but do not meet the new
single-SHA/single-config campaign contract.  No historical timing is promoted
to an authoritative current-baseline result in this report.
