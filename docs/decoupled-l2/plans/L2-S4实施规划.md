# Stage 4 LateBind MVP 实施规划

## 1. 定位与范围

本文档是 Stage 4 LateBind MVP 的实施合同草案。参考思路来自
`L2-S4.md`，并根据当前 QV100 sector L2、Stage 3 FRC 实现和实验
结果，修正物理粒度、容量核算与 forward-progress 方案。

Stage 4 只实现三个核心机制：

1. Read/fill 的 Transaction–Payload Decoupling；
2. Fill-time Physical Placement；
3. Dirty Victim 的 In-place Writeback Retirement。

暂不实现 bypass、store gather、atomic payload pool、动态池大小、WB
resurrection/forwarding 和容量 overcommit。

| 方案 | Miss 发出时 | Fill 返回时 | Dirty victim |
| --- | --- | --- | --- |
| Baseline | 立即绑定 RD way/payload | 填入已保留位置 | 传统 writeback |
| FRC | 分配专用 FRC payload | 选择 victim 并执行 FRC/L2 swap | victim 转移到 FRC |
| LateBind | 只分配 MSHR、metadata 和容量 credit | 此时选择 victim、绑定 physical slot | 原 slot 不动，转为 WB_PENDING |

核心研究命题为：

```text
Transaction exists before payload exists.
Dirty data retires in place without an FRC/L2 payload swap.
```

## 2. RD、PLP 与物理粒度

默认 QV100-like L2 每个 subpartition 为：

```text
32 sets × 24 ways × 128B
```

Resident Directory（RD）继续使用现有 tag array，set、associativity、
replacement policy 和最多 768 个 resident tag entries 均不变。LateBind
不增加逻辑 resident tag 容量。

RD entry 保留现有 tag、sector valid/dirty/readable、byte mask 和 replacement
metadata，新增按 sector 保存的映射：

```text
physical_id[SECTOR_CHUNCK_SIZE]
```

无效 sector 的 physical ID 必须为 `NONE`。

当前进入单个 QV100 L2 subpartition 的事务是一个 32B routed sector，FRC
也已按 32B entry 建模。因此 Stage 4 定义：

```text
1 Physical Slot = 1 routed 32B sector
```

每个 subpartition 的 baseline payload 为 96KiB，对应：

```text
N = 32 × 24 × 128B / 32B = 3072 physical sector slots
```

LateBind-H 的 Physical Line Pool（PLP）总容量为 `N+H`。所有 slot 进入
统一池，不预先划分 resident、fill 或 WB 专区。持久状态只需要：

```text
FREE
RESIDENT
WB_PENDING
```

`FILL_LANDING` 可作为统计事件或短暂流水状态，不作为长期占用状态。

## 3. 容量公平

| 配置 | 每 subpartition 额外 payload | 全部 64 slices 额外 payload |
| --- | ---: | ---: |
| FRC32 / LateBind32 | 1KiB | 64KiB |
| FRC64 / LateBind64 | 2KiB | 128KiB |
| FRC128 / LateBind128 | 4KiB | 256KiB |
| Baseline25 | 1 additional way = 4KiB | 256KiB |

最严格的 payload matched-capacity 对照固定为：

```text
Baseline25 vs FRC128 vs LateBind128
```

`H=32/64` 用于 FRC 与 LateBind 的等额机制比较；相对 Baseline24，它们
都拥有额外 payload，不能单独作为严格容量公平结论。

除 payload bytes 外，还必须独立报告 RD pointer、LateBind transaction、
landing credit、WB descriptor、FRC transaction/waiter 等 metadata bits，
以及增加或复用的端口。Payload matched 不等同于 equal area。

## 4. Landing Capacity Credit

MVP 不增加未计入 H 的 Emergency Spill Buffer。每个被接受的 LateBind
primary miss 必须先获得一个 landing capacity credit，但不绑定具体
physical ID：

```text
physical_id = NONE
landing_credit = true
```

系统始终保持：

```text
free + resident + wb_pending = N + H
free_physical_slots >= outstanding_fill_credits
```

状态变化如下：

- invalid placement：fill 消耗一个 credit 保证的 free slot；
- clean replacement：fill 复用 victim slot，释放 credit；
- dirty replacement：fill 消耗 free slot，旧 victim 原地转为 WB_PENDING；
- WB 被下层接受：对应 WB_PENDING slot 释放为 FREE。

因此每个已经发出的 lower read 都有确定落点，不会出现 fill 返回却无处
存放的结构性死锁。若 Stage 5 引入 overcommit/spill，其 payload 必须计入
H，例如 `H-1` 个共享 slot 加一个 spill slot。

## 5. 核心结构

### 5.1 Baseline MSHR

Stage 4 保留 baseline MSHR 的 entry 数、merge 上限、miss queue 和 response
ordering。LateBind 不建立类似 FRC 的第二套 waiter/transaction capacity。

每个 primary MSHR 只增加 placement metadata：

```cpp
LateBindTxn {
    block_addr;
    sector_mask;
    byte_mask;
    accept_time;
    physical_id = NONE;
    landing_credit = true;
    state;
}
```

这样性能变化才能归因于 late physical binding，而不是额外 MSHR。

### 5.2 Physical Pool Manager

建议新增独立 `latebind_pool`，负责：

- physical slot 状态；
- RD-sector 到 physical ID 的映射；
- transaction metadata 与 landing credit；
- writeback descriptor；
- ownership assertions；
- pool statistics。

现有 `tag_array` 继续承担 RD 和 replacement metadata，不重写整个 cache
框架。只为 L2 LateBind 增加明确接口：non-mutating probe、fill-time victim
selection、detach resident、install returned sector 和 flush mapping update。

### 5.3 Metadata-only Writeback

Dirty victim 从 RD detach 后，原 physical slot 不搬移：

```text
RESIDENT_DIRTY -> WB_PENDING
```

WB descriptor 至少保存：

```text
address
physical_id
dirty_sector_mask
dirty_byte_mask
enqueue_time
state
```

模拟器不保存真实 payload 值，但必须保持物理 ownership，并在 WB 真正
进入下层接口时计入 victim data read/data-port bandwidth。只有下层接受
writeback 后，slot 才能释放。

## 6. 数据流程与顺序

### 6.1 Read Miss

```text
Read miss
  -> allocate/merge baseline MSHR
  -> allocate LateBindTxn
  -> acquire landing credit
  -> physical_id = NONE
  -> issue lower read
```

此时不得 reserve RD、选择 victim、分配具体 PLP slot 或影响同 set 中
resident line 的可命中性。

### 6.2 Fill Placement

- Invalid RD：fill-time 选择 invalid entry，分配 credit-backed FREE slot。
- Clean victim：detach old RD mapping，直接复用同一 physical ID，再安装
  新映射；这是 metadata rename，internal copy 为零。
- Dirty victim：旧 slot 转 WB_PENDING，新 fill 使用 credit-backed FREE
  slot，安装新 RD mapping 并生成 metadata-only WB descriptor。

### 6.3 Write、Atomic 与同地址冲突

LB-R0 至 LB-R4 可只运行 read-only directed traces；若 write/atomic 暂走
baseline，必须断言该轮 trace 不含相关请求。

完整 MVP 中，所有可能改变 RD/PLP ownership 的路径必须经过同一 placement
manager，不能让 baseline write allocation 独立替换 RD entry。

- partial write 保留 baseline MSHR、byte mask 和 readability 语义；
- 需要 lower read 的 write allocate 使用 LateBind placement；
- atomic miss 使用 LateBind fetch/fill，compute/completion 沿用 baseline；
- atomic 完成后对应 sector 进入 MODIFIED；
- fetching 同地址请求 merge 或按 baseline 顺序阻塞；
- WB_PENDING 同地址请求在 MVP 中 stall/retry；
- 任一地址同一时刻最多一个 transient owner。

WB_PENDING hazard 的 release point 必须在实现合同中写清：只有当下层可
证明完成 ownership/order transfer 后，才能允许同地址新事务继续。

## 7. Progress Rule

每拍优先级固定为：

```text
1. Existing WB_PENDING progress
2. Returned fill placement
3. Existing lower-read issue
4. New request admission
```

新 primary miss 接受前必须同时取得 baseline MSHR credit、baseline
miss-queue credit、LateBind metadata credit 和 landing capacity credit。
不能先接受请求，再发现资源不足。

## 8. 实施轮次

### LB-R0：分支、合同与冻结基线

- 从 Stage 3 最终分支建立新的 core/experiment 分支；
- 固化合同、配置字段、容量表和 provenance；
- Baseline、FRC、LateBind 三种模式互斥；
- LateBind 默认关闭。

门禁：LateBind disabled 与当前 Baseline cycle-exact，FRC 与 Stage 3 最终
版本 cycle/stat exact，且本轮无行为改动。

### LB-R1：PLP/RD Mapping Skeleton

- 建立 `latebind_pool`、RD-sector pointer shadow、状态统计和断言；
- shadow on 不改变 timing；
- resident sector 与 physical owner 一一对应；
- invalidate/flush 正确更新映射。

### LB-R2：Read Miss Metadata-only

- read miss 使用 baseline MSHR；
- 分配 LateBindTxn 和 landing credit；
- 不调用 miss-time tag allocation；
- same-line read 使用 baseline merge；
- lower read 立即进入原下层通路。

门禁：miss-time RD reservation 和 physical binding 均为 0；每个 primary
恰好一个 lower read；merged request 不产生 duplicate lower read。

### LB-R3：Fill-time Invalid/Clean Placement

- fill-time probe/victim selection；
- invalid placement；
- clean victim physical reuse；
- fill port timing；
- baseline MSHR completion/reply ordering。

门禁：100% LateBind primary 在 fill-time 选择 victim；miss-time 和 fill-time
candidate 可以变化；clean replacement 的 swap/copy bytes 为 0。

### LB-R4：Dirty In-place Retirement

- dirty victim detach；
- 原 slot 转 WB_PENDING；
- metadata-only WB descriptor；
- returned fill 使用 free slot；
- WB data-port charge；
- lower acceptance 后释放 slot。

门禁：`wb_inplace > 0`；dirty ownership 唯一；writeback 恰好一次；地址、
sector mask、byte mask 正确；不产生 FRC-style swap copy。

### LB-R5：Finite Resource 与 Forward Progress

- landing-credit admission gate；
- WB/fill/read/new request 优先级；
- lower-port arbitration；
- full-pool state dump；
- flush drain。

门禁：全 dirty、credit exhaustion、lower write 长期阻塞后恢复等测试均无
deadlock；已接受 fill 永远可 placement；终态 txn/WB/credit 全为零。

### LB-R6：Sector、Partial Write、Atomic 与 Ordering

- sector mask、dirty/readable byte mask；
- partial write allocate；
- atomic miss/fill/completion；
- RAW/WAR/WAW；
- WB_PENDING 同地址冲突。

门禁：sector/byte/atomic 行为与 baseline 一致；没有 duplicate fill、lost
dirty data、第二 transient owner 或提前释放 slot。

### LB-R7：Matched-capacity Evaluation

- 固化 Baseline/FRC/LateBind 实验矩阵；
- directed、smoke、dev、完整 workload 分层运行；
- 汇总性能、容量、metadata 和内部数据移动；
- 对异常结果做 causal analysis；
- 保存 provenance、raw result 和失败诊断。

每个 Round 必须形成窄提交，并在前一轮门禁通过后再继续。

## 9. Directed Regression

| Case | 必须观察到的行为 |
| --- | --- |
| cold invalid fill | fill 前无 binding，fill 时消耗 free slot |
| resident hit while fetching | fill 前 resident victim 继续命中 |
| fill-time candidate change | 使用当前 replacement state |
| clean replacement | physical ID 复用，internal copy 为 0 |
| dirty replacement | 原 slot 转 WB_PENDING，新 fill 使用 free slot |
| same-line read burst | 一个 MSHR、一个 lower read，其余 merge |
| credit exhaustion | 无 credit 的请求不得被接受 |
| lower WB blocked | WB owner 保留，恢复后最终释放 |
| WB_PENDING reaccess | stall/retry，不创建第二 owner |
| partial write | byte mask/readability 与 baseline 一致 |
| atomic miss | LateBind fill 后执行 baseline atomic completion |
| RAW/WAR/WAW | 请求顺序和最终 dirty 状态正确 |
| flush | resident dirty、WB、txn 和 credit 全部收敛 |

## 10. 在线不变量与失败诊断

Development build 至少断言：

```text
每个有效 RD sector 恰好映射一个 RESIDENT physical slot
每个 physical slot 最多一个 owner
无效 RD sector 的 physical_id 为 NONE
每个 primary miss 恰好一个 lower read
每个 lower read 恰好一个 fill 或显式 cancellation
free + resident + wb_pending = N + H
free >= outstanding landing credits
dirty payload 属于 RD、WB_PENDING 或 lower ownership 三者之一
同一地址最多一个 transient owner
WB descriptor 与 WB_PENDING slot 一一对应
slot 只在可证明的 lower ownership transfer 后释放
模拟结束时 txn、WB、credits 和 transient states 全为零
```

Timeout 不能单独作为 deadlock 证据。失败时打印 MSHR、LateBind txn、PLP
状态、credits、WB descriptors、lower queue/port 和最老事务的停滞原因。

### Transaction–Payload Decoupling

```text

txn_without_payload_peak
landing_credit_alloc
landing_credit_stall
```

Metadata-only lifetime 定义为：

```text
first physical binding time - primary miss acceptance time
```

### PLP 与 Placement

```text
plp_free_sector_cycles
plp_resident_sector_cycles
plp_wb_pending_sector_cycles
plp_peak_wb_pending
plp_full_stall
fill_use_invalid_rd
fill_reuse_clean_phys
fill_use_free_phys_for_dirty
fill_time_victim_change
fill_wait_cycles
```

### Dirty Retirement

```text
wb_inplace
wb_inplace_wait_cycles
wb_lower_accepted
wb_pending_peak
```

### Internal Data Movement

```text
fill_write_bytes
wb_payload_read_bytes
lower_read_bytes
lower_write_bytes
frc_swap_data_bytes
latebind_internal_copy_bytes
```

必要的 fill write 和 dirty WB read 不属于额外 internal copy。核心比较为：

```text
LateBind internal copy bytes < FRC swap data bytes
```

不能通过漏计 WB data-port bandwidth 得到虚假收益。

## 12. 实验矩阵

机制对照：

```text
Baseline24
FRC32 / LateBind32
FRC64 / LateBind64
```

严格 payload matched-capacity：

```text
Baseline25
FRC128
LateBind128
```

核心矩阵完成后再运行 `H=4,8,16,32,64,128,256` 容量敏感性。

首先复用 Stage 3 的 FastWalshTransform、BlackScholes、MatrixTranspose、
ConvolutionSeparable 和 Scan；另加 dirty-WBQ、all-dirty replacement、
partial-write/refill、atomic、same-address ordering、credit exhaustion 和
lower-port blockage/recovery 定向 trace。

运行顺序固定为：

```text
unit/directed
  -> smoke
  -> short dev workload
  -> matched-capacity core matrix
  -> sensitivity
  -> expanded workload
```

## 13. Exit Criteria

### 正确性

| 项目 | 要求 |
| --- | --- |
| LateBind disabled | exact baseline |
| FRC preservation | exact Stage 3 FRC |
| Miss-time RD reservation | 0 |
| Miss-time physical binding | 0 |
| Fill-time victim selection | 100% LateBind primary misses |
| Clean physical reuse | PASS |
| Dirty in-place WB | PASS |
| Sector/byte correctness | PASS |
| Atomic correctness | PASS |
| Same-address ordering | PASS |
| Duplicate lower read/fill | 0 |
| Lost dirty data | 0 |
| Deadlock | 0 |
| Terminal transient ownership | 0 |

### 机制证据

```text
metadata-only lifetime > 0
latebound miss count > 0
clean physical reuse > 0
dirty in-place WB > 0 on dirty stress
LateBind internal copy bytes < FRC swap data bytes
```

### 公平性

- FRC-H 与 LateBind-H 的 payload bytes 相同；
- Baseline25/FRC128/LateBind128 严格 payload match；
- metadata bits 独立列出；
- spill payload 为 0，未来若启用则计入 H；
- 新端口与复用端口明确说明。

Stage 4 不预设固定 IPC 提升阈值。若结果不符合预期，必须定位到 tag
reservation、MSHR/merge、landing credit、PLP/WB、fill/data port、lower
arbitration、miss/locality/writeback 或 DRAM/interconnect 等具体原因，不能
只通过扩大测试规模代替机制解释。

## 14. 分支与 Worktree

保留已有 Phase 1/2 分支作为独立证据：

```text
hrl/l2-latebind-char-v1
hrl/l2-latebind-oracle-v1
hrl/l2-latebind-exp-v1
```

Stage 4 从已完成并推送的 Stage 3 分支新建：

```text
GPGPU-Sim:
fork/hrl/l2-frc-baseline-v1
  -> hrl/l2-latebind-mvp-v1

Accel-Sim:
origin/hrl/l2-frc-exp-v1
  -> hrl/l2-latebind-mvp-exp-v1
```

建议使用新的独立 worktree：

```text
/workspace/worktrees/gpgpu-sim-latebind-mvp-v1
/workspace/worktrees/accel-sim-latebind-mvp-v1
```

这样不改动 Stage 3 冻结分支，并能在同一 core binary 中互斥选择
Baseline/FRC/LateBind，保持共同统计和下层时序。

每个 Round 分别提交 core 与 experiment 变更，提交信息中明确 Round、
行为变化和已通过门禁。未经用户明确授权不推送新分支。
