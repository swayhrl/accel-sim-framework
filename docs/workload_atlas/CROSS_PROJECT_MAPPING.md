# Cross-project workload mapping - V1

This review independently resolves EP-L2's historical frozen input contract before comparing it with DTC-L1. **Seven EP inputs match complete DTC registered trace-member identities; only three match DTC's selected representatives.** This is an identity audit, not source-to-capture or numerical certification.

## Authority and reproducible identity check

EP authority is the eight actual registrations at frozen E2 commit `7c2f830175f40e16651eab4a3cd3a7af73e9927b`, adopted by EP-MAIN's `ep_main_native_takeover_20261023_v1/INPUT_ASSET_REQUIREMENTS.json` and `ACCEPTED_RESULT_AND_PAIR_INDEX.json`. Seven inputs belong to the original MAIN roster; SGEMM remains an independent exploratory cohort and never replaces Btree. The takeover's `draft_selectors` describe asset availability and proposed migration, not a fresh scientific promotion. This scope is distinct from later shared-library/capture candidate inventories.

DTC authority is [REPRESENTATIVE_FREEZE.json](../dtc_l1/review_packs/DTC_PAPER42_HASH_REVIEW_20261027_V1/REPRESENTATIVE_FREEZE.json), specifically `programs_44_to_42` and `mapping_72_to_42`. It freezes 35 ordinary identities and leaves seven ordinary programs unresolved; Btree is derived-only.

The two projects use different top-level digests. EP hashes a lexicographically name-sorted list of `{name, sha256, bytes}` with SHA256 over JSON encoded using `sort_keys=True`, separators `(',', ':')`, `ensure_ascii=False`, and `allow_nan=False`. This follows E2 `util/ep_l2/ft_lane5/run.py:57-73` and `registry.py:56-58`; exact Git-blob excerpts are retained in [contributions/ep_mapping](contributions/ep_mapping/). Reconstructing that EP digest from each DTC frozen `source_members_sha256` proves the registered member set, including command-list bytes, matches for seven inputs. Five matches additionally have identical independently recorded EP qualification per-member lists (Conv, DWT, CFD, Vector, SGEMM). FWT and SAD are verified by reconstructed complete-set digest.

No current trace body was rehashed. Only small command lists and bounded kernel header fields were read. Equality therefore means **same registered trace content under the recorded SHA256 evidence**, not a fresh body integrity scan, a common capture ELF, or a complete original application. Full digests, bundle IDs, all candidate differences, EP qualification scope, simulator identities, and accepted pair IDs are in [EP_FROZEN_INPUT_MAPPING.json](contributions/ep_mapping/EP_FROZEN_INPUT_MAPPING.json); the compact index is [EP_DTC_DIFFERENCES.tsv](contributions/ep_mapping/EP_DTC_DIFFERENCES.tsv). Launch fields are preserved in [DTC_CANDIDATE_COMMANDLIST_HEADERS.json](contributions/ep_mapping/DTC_CANDIDATE_COMMANDLIST_HEADERS.json).

## What can transfer

The source analyses for [CUDA Samples](programs/cuda_samples/), [Parboil](programs/parboil/), and [Rodinia](programs/rodinia/) explain reusable algorithms and address structures. For exactly matched registered traces, their recorded kernel order and lane addresses are shared evidence; runtime occupancy, cache hits, merging, latency, queues, physical bank timing, and performance remain model- and configuration-dependent. A shared trace never makes the EP and DTC simulator binaries equivalent.

Application source revisions and capture-ELF SHA are UNKNOWN for all eight EP registrations. CUDA9.1/10.1/11.0 labels are capture/toolchain path evidence, not source revisions. CFD even has a 9.1 storage path but a recorded CUDA10.1 capture command. EP's native main61, observer r4, and observer r5 are separate simulator lineages, not application binaries. DTC `MODEL_COMPARABILITY.json` applies to DTC's own reviewed models and does not certify EP cross-model equivalence.

## Independent cross-review findings

1. **Identity pass with scope limits:** seven reconstructed member-set digests match; three selected, three alternates, one unresolved. This independently checks the cross-project link without relying on workload names or current performance.
2. **CFD completeness discrepancy:** a fully consumed accepted command list can still omit most standard-source work. Record the conflict; do not rewrite accepted EP evidence or promote DTC CFD.
3. **Convolution host mismatch:** the two-launch 3072^2 trace is identical across projects, but fixed source host parsing/iteration behavior is not bound. Shared device formulas do not solve capture-host provenance.
4. **DWT/FWT/Vector representative differences:** same program family and sometimes same symbol do not justify carrying measured counters between different selected inputs.
5. **Btree derivation is a real identity boundary:** neither model-conditioned DTC input nor SGEMM exploration repairs EP's original Btree HOLD.

Useful future questions, requiring separately authorized runtime evidence, are whether DWT's larger per-channel levels change L1 pending-line pressure and L2 phase residency; whether FWT's larger transform changes cross-stage dirty reuse; and whether the exact shared SGEMM/SAD/Conv traces produce different queue/bank constraints under DTC and EP. Static reuse establishes an opportunity, not a hit, merge, or speedup.
