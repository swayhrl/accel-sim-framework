# kmeans - CPU-controlled Lloyd iterations; conditional data semantics

## 1. Program and algorithm
GPU assigns every feature vector to the nearest squared-Euclidean cluster center. CPU counts membership changes, sums points, replaces each nonempty center with its mean, and decides termination. Default kmin=kmax5, threshold0.001, one trial; CLI allows cluster-range/trial sweeps ([3.1/cuda/kmeans/kmeans.c:111](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans.c#L111)). Threshold compares **raw changed-point count**, not normalized fraction.

## 3. Host and complete launch sequence
For each k in min..max (stop k>N), CPU allocates device buffers and launches `invert_mapping` once. For each trial, CPU initializes centers/membership then do-while launches `kmeansPoint`, D2H membership, CPU reduce/update, continues while delta>threshold and `loop++<500`. This postincrement allows **up to501 assignment launches per trial**, not500. Total launches `sum_k(1+sum_trial I(k,trial))`. CPU input/parse errors exit before allocation; actual iteration count depends on data and floating-point behavior ([3.1/cuda/kmeans/cluster.c:105](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/cluster.c#L105), [3.1/cuda/kmeans/kmeans_clustering.c:145](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans_clustering.c#L145)).

## 4. Unique kernel implementations
`invert_mapping`: one thread/point, loops all features to transpose row-major input to feature-major output. Grid uses `s^2` blocks where `s=ceil(sqrt(ceil(N/256)))`; block256. `kmeansPoint` grid `(s,s)`, block256, flattened point id `(gridDim.x*by+bx)*256+tx`; loops centers then features, reads `tex1Dfetch(t_features, point+j*N)` and broadcast `c_clusters[center*F+j]`, writes membership. Nearest-center selection is per-thread; default no GPU reductions, atomics or shared memory. Optional GPU_DELTA uses shared integer tree+block scalar; optional GPU_NEW_CENTER loops256 original AoS points per assigned center-feature thread and writes block sums ([3.1/cuda/kmeans/kmeans_cuda.cu:49](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans_cuda.cu#L49), [3.1/cuda/kmeans/kmeans_cuda_kernel.cu:34](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans_cuda_kernel.cu#L34), [3.1/cuda/kmeans/kmeans_cuda_kernel.cu:57](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans_cuda_kernel.cu#L57), [3.1/cuda/kmeans/kmeans_cuda_kernel.cu:105](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans_cuda_kernel.cu#L105)).

## 5. Threads and address formulas
Transpose load `I+4*(p*F+j)` has lane stride4F; store `O+4*(p+N*j)` has lane stride4B. Same thread next feature advances4B in input and4N in output. Assignment feature texture address `O+4*(p+j*N)` has adjacent lanes contiguous; center constant address `C+4*(k*F+j)` is warp uniform. Membership store `M+4*p`. Optional block sum store is `B+4*(block_id*k*F+tx)`; optional original-feature read stride4F across its inner point loop. Citation: [3.1/cuda/kmeans/kmeans_cuda_kernel.cu:39](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans_cuda_kernel.cu#L39), [3.1/cuda/kmeans/kmeans_cuda_kernel.cu:82](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans_cuda_kernel.cu#L82), [3.1/cuda/kmeans/kmeans_cuda_kernel.cu:164](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/kmeans/kmeans_cuda_kernel.cu#L164).

## 6. Locality, coalescing and concurrency
For any issued scalar access set A, the exact source-level geometry is `lines={floor(a/128):a in A}` and `sectors={floor(a/32):a in A}` (include all bytes for multi-byte words). An aligned full warp of 32 adjacent 4-byte words needs one 128B line/four 32B sectors; shifting its base can require two lines/five sectors. These are address coverage bounds, not measured requests, misses, MSHR merges, reuse distances or DRAM transfers. Compiler instruction splitting and active masks matter.

Transpose source is strided and becomes poor per-instruction coverage as F grows; feature-major output and assignment texture reads are contiguous. Each assignment revisits the same point features for every center and all iterations, with constant-center broadcast across warps/CTAs. Texture/constant behavior cannot automatically be modeled as ordinary L1D loads. CTA count is rounded square; extra threads guard p<N. CPU update and transfers serialize each iteration, so there is no independent GPU launch overlap implied. Feature-to-distance accumulation is a loop-carried dependency; different point CTAs are independent.

## 8. Source-established architecture features
GPU assignment is read-heavy texture+constant plus contiguous membership writes. CPU center reduction is not GPU atomic traffic. Transpose is a one-time different access pattern and cannot be omitted when counting unique kernels.
