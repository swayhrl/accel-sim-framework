# nw - tiled Needleman-Wunsch wavefront; conditional size/version

## 1. Program and algorithm
CPU initializes two random sequences with seed7, forms BLOSUM62 reference scores and gap-penalty boundary. GPU solves `D[r,c]=max(D[r-1,c-1]+S[r,c],D[r,c-1]-p,D[r-1,c]-p)` over an N*N interior. Data is an `(N+1)^2` int32 matrix. CPU optionally emits/tracebacks output; GPU computes all interior DP cells without data-dependent convergence.

## 3. Host and complete launch sequence
Wrong argc or nonmultiple-of16 exits before allocation. For B16 and Q=N/B, top-left loop i1..Q launches `needle_cuda_shared_1` with i CTAs; bottom-right iQ-1..1 launches `_2` with i CTAs. Total **2Q-1 launches**, sum CTA count Q^2; each CTA computes one16x16 tile, block16. Thus N128->15 launches/64 tiles; N2048->255/16384. CPU uploads full score/matrix then final D2H; optional traceback occurs after GPU completion ([3.1/cuda/nw/needle.cu:83](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle.cu#L83), [3.1/cuda/nw/needle.cu:149](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle.cu#L149), [3.1/cuda/nw/needle.cu:171](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle.cu#L171)).

## 4. Unique kernel implementations
The two kernels have the same tile work and differ in tile-coordinate assignment: `_1`: `(tile_x,tile_y)=(bx,i-1-bx)`; `_2`: `(bx+Q-i,Q-bx-1)`. Each CTA loads a16x16 score tile, north/west/northwest DP boundary into shared `ref[16][16]` and `temp[17][17]`. Two internal diagonal sweeps of16 and15 rounds compute DP with a barrier each round, then store16 cells/thread. No atomics, texture or constant reads in the DP kernels; BLOSUM lookup was CPU preprocessing ([3.1/cuda/nw/needle_kernel.cu:34](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle_kernel.cu#L34), [3.1/cuda/nw/needle_kernel.cu:66](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle_kernel.cu#L66), [3.1/cuda/nw/needle_kernel.cu:117](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle_kernel.cu#L117)).

## 5. Threads and address formulas
Let C=N+1, B16, tile coordinates (u,v), thread t0..15. `index=C*B*v+B*u+t+C+1`; score load and final store row y use `base+4*(index+C*y)`. North `D+4*(C*B*v+B*u+t+1)` contiguous across t; west `D+4*(C*B*v+B*u+C+C*t)` stride4C across t; northwest is one-thread scalar. Same-thread score/store row loop advances4C; adjacent tile CTAs move one tile right and one tile up along the diagonal, not contiguous raster tile order ([3.1/cuda/nw/needle_kernel.cu:40](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle_kernel.cu#L40), [3.1/cuda/nw/needle_kernel.cu:52](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle_kernel.cu#L52), [3.1/cuda/nw/needle_kernel.cu:101](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/nw/needle_kernel.cu#L101)).

## 6. Locality, coalescing and concurrency
Coverage is computed as sets of `floor(byte_address/128)` lines and `floor(byte_address/32)` sectors, including every byte of each word. A32-lane, contiguous FP32/int32 aligned access occupies one line/four sectors; shifted alignment can require two/five. Active masks, generated instruction width and base alignment must be retained. Coverage does not prove cache hits, pending merges, DRAM transfers or simultaneous requests.

Each block has16 active lanes, so a score/store row accesses64B, covering two aligned32B sectors or three if shifted, and one or two128B lines. C=N+1 means row pitch is4(N+1), shifting alignment by4B for N divisible32; do not assume every row aligned. West boundary has16 distant lines/sectors when4C>=128, while north is contiguous. In-tile reuse is shared; neighboring tiles consume stored edges on the next wavefront launch. CTA count rises1..Q then falls; very first/last launches offer little parallelism. Dependencies require launch order; barriers enforce shared DP wavefronts. No source fact determines actual shared bank conflicts after compilation or SM residency.

## 8. Source-established architecture features
Repeated shared-memory DP dominates intra-tile reuse; global boundary dependence crosses kernels. North and west boundary accesses differ sharply in spatial use. Tiny launch ends are concurrency boundary cases rather than uniformly high-bandwidth streaming.
