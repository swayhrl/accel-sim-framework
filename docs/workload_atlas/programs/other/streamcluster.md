# streamcluster - CPU facility-location search with GPU gain; truncated-scope evidence

## 1. Program and algorithm
Streaming approximate k-median reads chunks, searches a facility cost z yielding kmin..kmax centers, consolidates chunk centers and finally clusters accumulated weighted centers. CPU performs initial speedy seeding, shuffles, candidate selection, objective reduction and center reassignment. GPU only computes per-point cost changes for opening one candidate x. Positive n creates synthetic coordinates with srand48(seed1); n<=0 reads binary float input ([3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp:887](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp#L887), [3.1/cuda/streamcluster/streamcluster_header.cu:73](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_header.cu#L73)).

## 3. Host and complete launch sequence
`streamCluster` reads a chunk, localSearch->pkmedian->pFL->pgain, consolidates/copies centers, stops on EOF and finally repeats localSearch on intermediate centers. Read errors, memory failure or center capacity exhaustion exit. `pkmedian` returns with **zero GPU gain launches if num<=kmax**. Otherwise speedy CPU seeding precedes pFL; cost z search terminates when k in range or loz>=0.999*hiz. `pFL` repeats while change/cost>e, each pass loops `i < L`, `L=(long)(3*kmax*log(kmax))`; every pgain launches exactly one kernel. Rough e0.1, and optional accurate e0.001 search. Total GPU launch count is sum of pFL pass counts times L over all chunk/final searches; data, seed, thresholds and k bounds determine it, not n alone ([3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp:332](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp#L332), [3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp:493](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp#L493), [3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp:568](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp#L568), [3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp:790](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda_cpu.cpp#L790)).

## 4. Unique kernel implementation
Only `kernel_compute_cost`: t maps one point; loops D dimensions to squared distance from point t to candidate x, multiplies by weight. If candidate cheaper than current assignment, set switch_membership[t] and accumulate `lower[K]`; otherwise accumulate `lower[center_table[p[t].assign]]`. Each thread owns its own lower row, so `+=` is ordinary read-modify-write **not atomic**. CPU prezeros work/switch, downloads both after each launch, reduces gains and updates point assignments/center table. Per-pgain work allocation/free and sync serialize candidates. Grid is 2D factorization of ceil(num/512) blocks ([3.1/cuda/streamcluster/streamcluster_cuda.cu:48](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda.cu#L48), [3.1/cuda/streamcluster/streamcluster_cuda.cu:62](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda.cu#L62), [3.1/cuda/streamcluster/streamcluster_cuda.cu:146](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda.cu#L146), [3.1/cuda/streamcluster/streamcluster_cuda.cu:245](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda.cu#L245), [3.1/cuda/streamcluster/streamcluster_cuda.cu:294](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda.cu#L294)).

## 5. Threads and address formulas
Flatten `t=512*(bx+gridDim.x*by)+tx`, N=num, D=dim, s=K+1. Coordinate loads `C+4*(d*N+t)` and candidate `C+4*(d*N+x)` for d0..D-1. Per-thread next-d stride4N; adjacent lanes first operand stride4B, second identical. Point fields `P+t*sizeof(Point)+offsetof(field)`; assign load then table `T+4*assign` then work slot is a dependent chain. Work RMW address `W+4*(t*s+j)`, j=K or loaded center_table[assign]. Switch byte `S+t`. No coord pointer dereference on GPU; separate transposed coord_d supplies data ([3.1/cuda/streamcluster/streamcluster_cuda.cu:53](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda.cu#L53), [3.1/cuda/streamcluster/streamcluster_cuda.cu:72](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda.cu#L72), [3.1/cuda/streamcluster/streamcluster_cuda.cu:172](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/streamcluster/streamcluster_cuda.cu#L172)).

## 6. Locality, coalescing and concurrency
Coverage is computed as sets of `floor(byte_address/128)` lines and `floor(byte_address/32)` sectors, including every byte of each word. A32-lane, contiguous FP32/int32 aligned access occupies one line/four sectors; shifted alignment can require two/five. Active masks, generated instruction width and base alignment must be retained. Coverage does not prove cache hits, pending merges, DRAM transfers or simultaneous requests.

Coordinates are coalesced SoA streams and candidate coordinates are warp/CTA-shared broadcasts. Candidate x changes across launches; all candidates revisit point coordinates. Point fields have ABI-dependent AoS stride; do not equate copy size with guaranteed compiler instruction width. Work rows are disjoint per point, but stride4*(K+1) creates sparse per-instruction stores and larger tag/sector coverage than contiguous coordinates; branch/data-dependent j precludes exact line counts without point assignments. Center-table indices can duplicate across lanes; no atomic contention follows. N65536 gives128 CTAs/launch. Cost accumulation and assign->table->work dependencies constrain ILP, and CPU completion gates the next candidate; occupancy/inflight counts are unmeasured.
