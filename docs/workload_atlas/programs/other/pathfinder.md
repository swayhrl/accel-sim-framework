# pathfinder - temporal pyramid dynamic programming; conditional version/shape

## 1. Program and algorithm
For each wall row r and column c compute `cost[r,c]=wall[r,c]+min(cost[r-1,c-1],cost[r-1,c],cost[r-1,c+1])`, clamped at left/right edges. CPU generates `rows*cols` integer costs `rand()%10` with seed9. First row seeds GPU result; GPU processes remaining rows in pyramids of up to H temporal steps.

## 4. Unique kernel implementation
Only `dynproc_kernel`: one CTA covers256 columns including temporal halo. Shared `prev[256]`/`result[256]`; x=`S*bx-H+tx`, clamp west/east shared indices to valid edge. Each round narrows active interval to `[i+1,254-i]`, adds current wall cost to min of three shared previous values, synchronizes, copies computed results to prev unless final round. Only last-round computed threads store final results. No atomics, textures, constant arrays or cross-CTA synchronization ([3.1/cuda/pathfinder/pathfinder.cu:103](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/pathfinder/pathfinder.cu#L103), [3.1/cuda/pathfinder/pathfinder.cu:155](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/pathfinder/pathfinder.cu#L155)).

## 5. Threads and address formulas
Source row load `Rsrc+4*x`; per temporal round i wall load `W+4*(cols*(t+i)+x)` because gpuWall begins at CPU row1. Final `Rdst+4*x`. Adjacent active lanes differ4B; same thread next round differs4*cols in wall. Neighbor shared reads are prev[tx-1],prev[tx],prev[tx+1] after edge clamp. Next CTA x-origin differsS; full initial footprints overlap2H columns, not256. Last shortened temporal launch retains border/grid computed from H, with a wider surviving interval and possible overlapping final writes across neighboring CTAs; source alone does not prove scheduling/values after an unbound build ([3.1/cuda/pathfinder/pathfinder.cu:125](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/pathfinder/pathfinder.cu#L125), [3.1/cuda/pathfinder/pathfinder.cu:165](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/pathfinder/pathfinder.cu#L165), [3.1/cuda/pathfinder/pathfinder.cu:199](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/pathfinder/pathfinder.cu#L199)).

## 6. Locality, coalescing and concurrency
Coverage is computed as sets of `floor(byte_address/128)` lines and `floor(byte_address/32)` sectors, including every byte of each word. A32-lane, contiguous FP32/int32 aligned access occupies one line/four sectors; shifted alignment can require two/five. Active masks, generated instruction width and base alignment must be retained. Coverage does not prove cache hits, pending merges, DRAM transfers or simultaneous requests.

Wall/result accesses are contiguous but shrinking active masks reduce utilization, and x-origin/row pitch shift alignment. Inner temporal reuse is shared memory, so source's three-neighbor operations are not three global loads. Halo columns duplicate work/global wall loads across adjacent CTAs and have potential L1/L2/pending-line reuse; count exact sectors from active lane sets. Each launch consumes previous result and writes ping-pong buffer; immutable wall is streamed by temporal rows. Grid5 for cols1000,H5 versus463 for cols100000,H20 (S246/216) changes available CTA supply profoundly. Barriers and dependency min-to-result dominate local temporal progress; no kernel concurrency is implied.

## 8. Source-established architecture features
Temporal blocking trades redundant halo computation for shared-memory reuse. H changes grid size, masks, useful stores and temporal distance together; it cannot be treated merely as a scalar workload size.2.0-ft missing barriers are a real semantic difference requiring recorded evidence, not silent source repair.
