# backprop - one hybrid CPU/GPU training step; conditional identity

## 1. Program and algorithm
A three-layer network fixes 16 hidden units and one output. CPU generates/loads inputs and weights with seed7. Forward hidden activation is `sigmoid(sum_i input_i*w_ij+bias_j)`, followed by output/error/backprop and momentum weight updates. This executable performs **one training iteration**, not training until convergence ([3.1/cuda/backprop/facetrain.c:19](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/facetrain.c#L19)). Inputs must be a multiple of16; argument or divisibility checks exit before GPU work.

## 3. Host and complete launch sequence
CPU flattens `(in+1)*(hid+1)` weights, copies input/weights, launches `bpnn_layerforward_CUDA` once, synchronizes and downloads partial sums. CPU sums across input tiles, adds bias and sigmoid, calculates output/hidden deltas and updates hidden-to-output weights. CPU uploads deltas and original flattened weights again, then launches `bpnn_adjust_weights_cuda` once. Thus **two launches regardless of input size**, each grid `(1,in/16)`, block `(16,16)`;2.0-ft4096 gives256 CTAs/launch,3.1 65536 gives4096. Error check can terminate after first kernel ([3.1/cuda/backprop/backprop_cuda.cu:80](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda.cu#L80), [3.1/cuda/backprop/backprop_cuda.cu:123](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda.cu#L123), [3.1/cuda/backprop/backprop_cuda.cu:138](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda.cu#L138), [3.1/cuda/backprop/backprop_cuda.cu:172](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda.cu#L172)). ## 4. Unique kernel implementations
`bpnn_layerforward_CUDA` stages16 input scalars and16x16 weights in shared memory, multiplies, reduces along y through four synchronized tree stages, writes intermediate weights back to global memory and emits16 partial sums/CTA. `output_hidden_cuda` is passed but unused. `bpnn_adjust_weights_cuda` does elementwise `w += ETA*delta*ly+MOMENTUM*oldw`, updates momentum and handles bias only in block y0/thread y0. There are no atomics, texture or constant-memory declarations in these kernels ([3.1/cuda/backprop/backprop_cuda_kernel.cu:12](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda_kernel.cu#L12), [3.1/cuda/backprop/backprop_cuda_kernel.cu:81](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda_kernel.cu#L81)).

## 5. Threads and address formulas
Let `b=blockIdx.y`, `x=threadIdx.x`, `y=threadIdx.y`, `h=16`. Weight float address is `W+4*((h+1)*(16*b+y+1)+x+1)`; input is `I+4*(16*b+y+1)`, read only by x0 in first kernel. Partial store uses `P+4*(b*h+y)` at x0 and reads shared `weight_matrix[0][y]` (the apparent transpose is intentional indexing of the reduced row). Update delta address `D+4*(x+1)` and ly `I+4*(16*b+y+1)`; bias `W+4*(x+1)` ([3.1/cuda/backprop/backprop_cuda_kernel.cu:24](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda_kernel.cu#L24), [3.1/cuda/backprop/backprop_cuda_kernel.cu:74](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda_kernel.cu#L74), [3.1/cuda/backprop/backprop_cuda_kernel.cu:95](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/backprop/backprop_cuda_kernel.cu#L95)).

## 6. Locality, coalescing and concurrency
For any issued scalar access set A, the exact source-level geometry is `lines={floor(a/128):a in A}` and `sectors={floor(a/32):a in A}` (include all bytes for multi-byte words). An aligned full warp of 32 adjacent 4-byte words needs one 128B line/four 32B sectors; shifting its base can require two lines/five sectors. These are address coverage bounds, not measured requests, misses, MSHR merges, reuse distances or DRAM transfers. Compiler instruction splitting and active masks matter.

CUDA x is fastest: a warp covers two16-lane rows. Each half warp reads16 adjacent floats, but the rows' starting addresses differ68B, leaving a4B gap. Exact 128B/32B coverage follows the set formula; treating the warp as32 gapless words is wrong. Consecutive warps advance two rows=136B; successive CTAs advance16*17*4=1088B. Input/ly is reused among16 x lanes; deltas are shared across all CTAs. Shared reduction creates barrier/computation dependencies; weight/oldw/input are otherwise independent load sources. CTA count grows with input size; concurrent residency is not established.

## 8. Source-established architecture features
Hybrid reduction and CPU intervention separate the two GPU phases; input-weight producer data is not simply consumed by the second kernel because host reuploads original weights. Repeated deltas/inputs are opportunities for cache retention, while the streamed weight matrices dominate address coverage. No GPU atomic reduction exists.
