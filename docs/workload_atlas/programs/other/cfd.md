# cfd - Euler finite-volume solver; five-kernel capture scope gap

## 1. Program and algorithm
Cell-centered unstructured3D Euler finite volumes maintain density, three momenta and density-energy per cell. CPU reads area, four neighbor indices and12 face-normal components. GPU computes local stable step factors, fluxes over four neighbors and three Runge-Kutta updates per iteration. Source termination is fixed **2000 iterations**, with no convergence/CPU numerical early exit ([3.1/cuda/cfd/euler3d.cu:17](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L17), [3.1/cuda/cfd/euler3d.cu:581](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L581)).

## 3. Host and complete launch sequence
Missing data argument returns before GPU. CPU reads mesh, converts Fortran neighbor indices, negates normals and pads `nelr=192*ceil(nel/192)` for defaults. Three initialize launches fill `variables`, `old_variables`, `fluxes`; memset initializes step_factors. Each iteration D2D copies current to old variables, launches one `cuda_compute_step_factor`, then repeats `cuda_compute_flux -> cuda_time_step(j)` for j0..2. Total **3+2000*(1+3+3)=14003 launches**: initialize3, step2000, flux6000, time_step6000. Final CPU dump downloads solution ([3.1/cuda/cfd/euler3d.cu:502](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L502), [3.1/cuda/cfd/euler3d.cu:555](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L555), [3.1/cuda/cfd/euler3d.cu:581](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L581)).

## 4. Unique kernel implementations
All four use one thread/cell `i=b*blockDim.x+t`, grids `nelr/BLOCK_SIZE_k` without bounds guards. Initialize loops five fields and broadcasts far-field constants. Step reads five state fields+area and writes one factor. Flux reads own state, then neighbor/normal, branches on nb>=0 (gather neighbor state), nb=-1 wing pressure boundary or nb=-2 far-field constants, accumulating in registers before five flux stores. Time-step reads old state+flux+step factor and writes five updated fields. Device helpers are arithmetic inline functions, not additional launches; no shared memory, barriers or atomics ([3.1/cuda/cfd/euler3d.cu:178](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L178), [3.1/cuda/cfd/euler3d.cu:234](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L234), [3.1/cuda/cfd/euler3d.cu:265](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L265), [3.1/cuda/cfd/euler3d.cu:402](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L402)).

## 5. Threads and address formulas
With padded count R, state/flux field q is `V+4*(i+q*R)`, q0..4; area/step `A+4*i`. Neighbor face j: `E+4*(i+j*R)`; normal component k: `N+4*(i+(j+4*k)*R)`. Loaded `nb=E[i+j*R]` then selects `V+4*(nb+q*R)`, a true dependent gather. Same-thread face progression changes neighbor address by4R and normal plane by4R, whereas neighbor-state deltas are input-dependent. These formulas are directly in lines274-320 and389-412 ([3.1/cuda/cfd/euler3d.cu:274](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L274), [3.1/cuda/cfd/euler3d.cu:305](https://github.com/accel-sim/gpu-app-collection/blob/dad09cb0487845edc7524ded814c6cde9f0ef6a1/src/cuda/rodinia/3.1/cuda/cfd/euler3d.cu#L305)).

## 6. Locality, coalescing and concurrency
For any issued scalar access set A, the exact source-level geometry is `lines={floor(a/128):a in A}` and `sectors={floor(a/32):a in A}` (include all bytes for multi-byte words). An aligned full warp of 32 adjacent 4-byte words needs one 128B line/four 32B sectors; shifting its base can require two lines/five sectors. These are address coverage bounds, not measured requests, misses, MSHR merges, reuse distances or DRAM transfers. Compiler instruction splitting and active masks matter.

Own-cell and mesh planes have lane stride4B and adjacent warps/CTAs continue the same stream. Neighbor-state gathers may duplicate or scatter across lanes, warps and CTAs; mesh SHA/topology is required for exact coverage. Five state planes, four neighbors and12 normals provide independent plane loads, but nb-to-state and density-to-pressure create dependent chains. No inter-CTA in-kernel synchronization; launch boundaries enforce flux/time-step ordering. Geometry immutable across all iterations; variables/fluxes/old state repeatedly read and written. Source alone cannot establish SM overlap, queue occupancy or latency.
