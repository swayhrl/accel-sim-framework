\begin{abstract}
A fixed-partition L2 may relocate a dirty victim into a writeback buffer before reusing its resident slot. Elastic Payload L2 (EP-L2) replaces this relocation with an ownership transfer: the victim retains its physical slot, the incoming resident receives a distinct bank-compatible slot, and writeback ordering remains tracked independently. We compare this WB-only organization with a fixed-partition reference under equal resident-tag, payload-capacity, and modeled bank-service budgets. Across five non-atomic trace-driven workloads, EP-L2 removes all measured resident-to-writeback copies but achieves a geometric-mean speedup of 1.0016, including one slowdown. Three workloads eliminate writeback-data-full admission denials while exhibiting more downstream queue-admission denials. The results demonstrate copy removal without isolating an application-performance benefit from dynamic sharing. Validation covers symbolic sector versions and transaction lifecycles rather than numerical SASS outputs; physical implementation costs remain to be measured.
\end{abstract}

We evaluate three distinct effects: elimination of resident-to-writeback copying, relief of fixed writeback-data quotas, and changes in application execution time. The five-workload reference configuration shows that these effects need not scale together: all measured copies are removed, while the geometric-mean speedup is 1.0016. Downstream-service sensitivity tests address whether the relative benefit changes with the surrounding memory system. Equal-total-capacity static controls are additionally needed to isolate dynamic sharing from the particular reference partition.
