# Candidate host initialization scope — not runtime qualified

The consumed Lane5 warmup prototype correctly targets the sole allocator, but its original dirty-victim release and address-only Tag update need review with TVD. Lane2 adds source-level protections, all uncompiled:

- Actual memory_sub_partition::force_l2_tag_update checks the real requester tracker is idle before host modification. l2_cache additionally requires drained FT WB/refs, shared WAD0, no directory read lease or unfinished lookup, and exactly one declared sector. Untimed host initialization performs no payload bank service and does not advance physical GPU time.
- Probe the actual native Tag victim/index; reject reserved, dirty or pinned/pending resident data before changing any allocator/directory/Tag state. A dirty selected victim or dirty same-owner host overwrite is explicitly unsupported: no silent discard, no invented untimed WB. Timed ordinary GPU replacement still uses the existing real WB/forward/set_done path.
- Same-owner clean sector warmups reuse the exact handle and preserve other ready/sector versions; only declared sectors acquire explicit symbolic zero. On MISS, a clean old resident can reuse its sole allocation with a new generation; no optional TVD insertion is charged to untimed host warming.
- If the host address is already optional in TVD, remove only that exact unpinned, nonmandatory entry and release it through the same allocator before installing the new Tag owner. Do not leave an old detached copy visible for a host-overwritten line. Preview landing/bank resources before the first release. A mandatory WB alias cannot pass the global drained/shared-WAD check.
- Native host fill retains the original memcpy-offset Tag timestamp. Reprobe immediately afterward and assert actual chosen index equals the reserved/bound index. No dirty-state assertion is removed. The test source covers same-line repeated/multi-sector warmups, clean victim replacement, detached alias reinitialization, subsequent timed GPU writes/WB and a new idle epoch after invalidate.

Local-idle initialization is the supported candidate scope; concurrent host mutation of active GPU data or dirty resident overwrite requires a separately modeled protocol and is rejected here. No full-byte/numerical atomic semantics are claimed. There is no extra physical payload array, address CAM, descriptor pool, port or capacity. Existing directory/handle fields implement guards and identity; technology-specific area/timing remains unknown.
