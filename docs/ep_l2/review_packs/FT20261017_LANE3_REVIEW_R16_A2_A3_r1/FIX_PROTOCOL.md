# A2 and A3 are distinct fixes

A2: store_port::tag_ready continues to expose ready Tag sectors but keeps the landing in RO_FILL_ATTACHED / role RO while its one transaction pin is live. Its per-role Bank request key therefore remains unchanged through partial fills, a queued last fill and all pending response reads. transactions::retire_if_done already requires no waiter, no prepared response and all required/issued sectors ready. Only after the last actual response commit does store_port::unpin require sole pin/no pending sectors, unpin and promote an attached landing to RESIDENT_VALID. Detached landings stay RO until the existing release path. Physical id and generation remain stable while pinned. This is an ordering protocol, not migration/cancellation of arbitrary shared tokens. The A2-only executions demonstrate its fix without A3.

A3: the pre-existing reply.transaction is now an identity reservation. Invalid=none; valid with selected=false=waiting for Bank; selected=true=real grant in response_cycle. Denial never changes that candidate, so a newly ready lower-index transaction cannot steal it. No reply packet/version copy is exposed before grant. Cross-cycle retry after an unaccepted granted response invalidates its transaction-local preparation and rereads the shared RAM; the old data field is not a free completion buffer. Successful enqueue advances cursor and invalidates the identity. ft_response_ready also honors an already waiting/granted RO identity before normal native/RO preference, covering a later native response that would otherwise park the old RO grant. The A3-only executions keep each denied candidate's role stable and still pass without the A2 role fix.

Both: one requester descriptor is released only after accepted commit; pin/role retirement follows its existing transaction closure. No whole-Bank clear, lost age, fabricated port, second allocator, address CAM, new metadata field or data array is introduced. gpu-cache.h, including request/cancel/pending arbitration, is byte-identical to the Lane3 r14 parent. Runtime field declarations are byte-identical. RO-OFF ft_response_ready tail is byte-identical. Core patches apply only to the RO-capable Lane3 parent, not directly to a producer that lacks RO. Lane1 remains integrator for any public R2.
