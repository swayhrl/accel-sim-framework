# Five-input qualification builder

`build_final_qualifications.py` is ready for root E review and invocation. This agent checked its AST and the actual root `QUALIFICATION_CONSTRUCTION_INTAKE.json` interface, but did not execute it, register a qualification or run native/app work.

Run with `--construction-input` naming that real intake and explicit `--build-after-real-e-native-and-owner-seals`. The construction schema is `E2_CAPACITY_QUALIFICATION_CONSTRUCTION_INTAKE_V1`; its six references are `source_identity_document`, `native_replay_result`, `gate_assertion_review`, `parser_seal`, `input_bindings_index` and `producer_remote_readback`. All current fields match.

The builder reads the current original Coordinator's11 gates and capacity policy's8 affected gates. Each gate must already have a real E PASS assertion, production-driven case IDs, evidence references and rationale. It checks actual direct-ELF normal exit/wait0, native identities and durable exit bytes. It never promotes a producer receipt, proposal or missing counter into PASS.

The parser owner seal supplies exact parser bytes/source map, independently reviewed normalized capacity profiles, actual E decoder evidence, engineering controls, counter coverage and the qualified source-constructor interpretation of OFF FIFO capacities. Unknown counter coverage, including MissQ refusal coverage=false, remains unchanged and can yield UNKNOWN classification; it does not become an assumed zero.

The builder derives producer release/vector/build provenance/native evidence references from the actual remote readback. A real successful `cmake --build` log is selected from the producer build receipt. Each Q then gets its own full-input selection/instruction/termination scope, E-config effective dictionaries and new normalized feature/resource values. The binary and common vector remain identical across all five. No main61 Q or old application anchor is read.

Only after all checks pass are five `final_qualifications/<workload>/QUALIFICATION.json` files written, together with `E2_CAPACITY_MATERIALIZATION_INPUTS.json` and a construction receipt. Output is a new child here; existing Qs are never overwritten. The index matches `materialize.py` directly. Root remains responsible for publishing/readback, original central registration/runtime freeze, final inspect/resource gates and the sole controller dispatch. Qualification construction does not add an application start or change execution order.
