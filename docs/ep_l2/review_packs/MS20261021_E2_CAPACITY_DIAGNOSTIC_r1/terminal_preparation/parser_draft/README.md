# New-capacity terminal parser draft

This is source-driven engineering preparation for Core `2aa0ee802e2cdd79d79e352e74522f8b6ae96699` and runtime Framework `9dd1ee57a83d83b56b7874bc7c716185ab52c8f7`. It is **not a native-qualified parser**. No complete positive raw or native application was fabricated or accepted. Nineteen bounded synthetic field/negative controls and syntax/AST checks passed; actual new-runtime native/schema review is pending.

`parse_capacity_terminal.py` copies the retained main61 parser's exact `numbers` field decoder and17 wait-reason names, recording the old source digest. It does not invoke the old parser, fixed geometry decoder, old qualification or legacy validator. The new decoder keeps final-clock exact64 FT SUMMARY/TERMINAL/B0 INVARIANT, observer/wait/local-service, STRUCT geometry/bank/quota and actual large CONFIG records. It validates full kernel launch/completion UID closure using `spec.expected_kernel_count`, exact cumulative instructions, traditional-S flags and scaled role/native geometry. Required counters, ownership/drain and service fields are normalized for the already bound new `capacity_validation` module.

The unchanged CLI is `--raw PATH --out PATH`. `main()` reads the runner-persisted `input_spec.json`, then the original read-only central qualification index. It requires spec QID=registered qualification SHA=file SHA, parser SHA, new E qualification and exact new producer-driven evidence hashes. Scope is read from that Q's `capacity_diagnostic.validation_scope`. Thus Q can hash the parser, without the parser embedding or hashing the Q: there is no circular identity. Production owner must remotely publish and bind the final parser and all five actual Qs after the formal producer event.

Only `S` and `S_L2_DATA_FREE_LARGE_CAPACITY` are supported. A later Core/framework/source print revision requires explicit source-mapping review and updated mapping constants before binding; the Framework handoff HEAD is distinct from runtime Framework9dd.

`RESOURCE_MAP` uses actual source names and distinguishes event highwaters, conservative upper bounds and source-proven S nonapplicability. Raw `coverage` or `near_nonbinding` alone never grants coverage. Q must include `capacity_diagnostic.counter_coverage_review[normalized_resource] = {status: INDEPENDENTLY_REVIEWED, native_coverage: <exact source literal>, capacity_refusal_coverage_complete: true}` based on independent source/new-native evidence. Absent coverage/counter fields remain UNKNOWN, with no synthetic zero. Native full-check counts retain their actual semantics, rather than being called unique failed requests. Near-label classification is performed by the new pure validator.

The actual add789 ROP telemetry is an `EPL2LARGEV1|UNCHANGED` record with `ROP_storage=NATIVE_DYNAMIC`, `ROP_highwater` and zero native capacity-denial checks, alongside fixed ROP latency/copy-latch and unchanged DRAM/ICNT scope. It is decoded, preserved and explicitly excluded from the enlarged finite vector. No hardcoded15-row count excludes extra unchanged telemetry; an actual new RESOURCE enum still requires source review.

OFF does not emit the four FIFO RESOURCE records in this revision. The exact requested option is **`-gpgpu_dram_partition_queues`**, registered to internal variable `gpgpu_L2_queue_config` (gpu-sim.cc246-247), then parsed by memory_sub_partition constructor (l2cache.cc986) as ICNT→L2, L2→DRAM, DRAM→L2, L2→ICNT. OFF identity can use that actual native option dump plus explicit independent source/new-archive getter evidence in `capacity_diagnostic.off_fifo_capacity_review`: `status=INDEPENDENTLY_REVIEWED`, `requested_native_queue_config`, `actual_new_archive_native_getter_capacities`, and `new_archive_native_getter_evidence:{path,sha256}`. The CLI verifies that evidence hash. This establishes capacity identity only; OFF highwater/refusal fields remain unknown. No new production mechanism or full application is required by this review.

The production owner must independently compare normalized capacities/configurations against the final producer manifest, bind kernel count/full input identity, and review the complete affected new native evidence. Normal durable exit/wait status, runtime/input hashes, resource leases and result ceilings remain original runner responsibilities. A normal-exit text line alone cannot establish actual exit0.
