# Scoped terminal route patch for E2 capacity diagnostic

`TERMINAL_ROUTE.patch` is a reviewable proposed patch against the exact file hashes in `PATCH_BASE.json`. It has **not** been applied to util, bound to CLIENT, committed, published or used for native/application execution by this worker. `git apply --check` passed; candidate Python syntax checks and21 bounded pure route controls passed. All fixture data are synthetic engineering controls, with no registry, lease, build or simulator action.

The patch adds `util/ep_l2/mechanism_e/capacity_validation.py` as a new pure validator and leaves every pinned legacy decoder/validator source unchanged. The earlier published `acceptance_preparation` candidate is untouched. Public interfaces are `validate_scope(scope, source_identity, supported_profiles=None)` and `validate_summary(summary, identity, scope)`.

Original runner execution still verifies actual durable native exit, full instructions, parser SHA and full before/after identity. Its new helper routes only an explicit dedicated-capacity condition to an immutable registered new Q whose SHA equals the spec QID and original input-audit qualification SHA. That Q must have the exact new capacity contract, valid manifest/effective scope and exact input selection. Contractless legacy conditions retain their original `validate_summary(summary, identity)` call. A capacity condition without the contract, a contract on a legacy bucket, or an attempted new-scope summary through the legacy path is rejected. main61 is rejected in both scope validation and summary validation.

`capacity_policy.qualification` now requires the complete explicit `validation_scope`: approved authority, exact four-field new source identity, hashed capacity manifest, one approved selection and exact full instructions/termination, and exactly `S` plus `S_L2_DATA_FREE_LARGE_CAPACITY`. Each profile has scalar actual-native configuration, finite role capacities with exact payload conservation, Tag set/way consistency, unchanged traditional-S organization and bank/copy geometry, actual master-derived data-free and P1 flags, named enlarged resources and mandatory drained resources. Default/OFF uses original1024/128/16 payload-role split,128 line-MSHRs/WAD,512 descriptors and32 per-address cap. ON must not contract any resource. The normalized configuration and native cache geometry must agree with the reviewed scope; the manifest reference must hash to the exact reviewed producer-vector bytes. The existing eight capacity production gates and original11 registered native gates remain required elsewhere; no synthetic test grants them.

Additional E qualification contract fields are:

- `capacity_manifest: {path, sha256}` references the exact producer vector file; `common_capacity_vector` is its parsed JSON.
- `validation_scope` follows `E2_CAPACITY_VALIDATION_SCOPE_V1`, one input per Q; all5 Qs share the same source and vector.
- `normalized_capacity_profiles` maps both names to their exact `{capacities, configuration}` values in `validation_scope.profiles`. This is the E-reviewed normalization of the producer manifest, not a new mechanism or an assumption that A2 emits these names directly.
- `native_cache_geometry` maps both names to scalar `native_tag_sets`, `native_tag_ways`, `native_line_bytes` values, identical to the normalized actual-native configuration.

The producer's actual output schema and manifest layout are still pending. A dedicated review-pack parser will map those actual fields into this normalization after formal delivery; this patch does not fabricate counters or require A to implement an additional production mechanism. That adaptation and producer-vector-to-normalized-scope comparison must be independently reviewed before qualification. Per-input expected instructions are bound during Q registration; formal configs remain master-switch-only differences.

The pure summary validator checks exact64 final-slice capacity/config/resource/closure records, full instructions, payload conservation, real requester/WB/drain identities and source-specific flags. Near-unbounded labeling is separate: true capacity refusals or highwater above50% yield valid `LARGE_FINITE`, missing observational coverage yields `UNKNOWN`; neither causes hidden result rejection or automatic rerun. Native parser/qualification gates must establish actual source-specific coverage and numeric data correctness. The pure validator cannot infer native exit, data values, source file hashes or lease status from counters.

`controller.py` gains only a capacity-scoped admission block: when a capacity result is `FAILED`, set local `blocked=True`. Current workers drain naturally; no STOP event, signal or kill is added. Legacy `FAILED` scheduling behavior remains unchanged. An engineering parser repair may replay retained raw through the exact repaired parser without repeating the full application, following explicit evidence review.
