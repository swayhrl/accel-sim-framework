# r3 current scientific acceptance contract

This revision is the current consumer. r2 remains an immutable historical tool
and must not be used to emit current formal figures.

1. Require explicit current_acceptance: exact Lane-5 publication, matrix release_key,
   SHA256 of APPLICATION_ACCEPTANCE.json, VALIDATION_MATRIX.json, RECEIPT.json,
   and supersession_SHA256SUMS. Paths are fixed Lane-5 report paths. The acceptance
   table's evidence_pack must be named by the Lane-5 receipt. Every checksummed
   supersession file is read from that same Git commit and rehashed. Matrix repair
   manifests must be within that closure. The commit must descend from b134f76d.
2. Resolve fixed GitHub Lane-5 execution ref online, with bounded timeout. A cached
   remote-tracking ref, local packet or old pinned receipt cannot establish current
   authority. Pinned commit must equal the live ref at intake and before emission;
   movement or inability to resolve fails closed. Fetch/rebind a new revision when
   it advances. No offline/current flag, timestamp TTL or manual plot-disable switch.
3. Require one exact row per original canonical run_key, matching Core, producing
   Framework, binary, ordered config/aux/env digest, trace digest, workload/mode,
   raw hash and native totals. Require row scientific_acceptance CURRENT_ACCEPTED,
   table CURRENT_ACCEPTED, selected release matrix CURRENT_ACCEPTED and matching
   matrix formal_run entry. Original COMPLETE_VALID stays distinct. Suspended,
   NOT_RUN, missing, duplicate or mismatched records cannot enter accepted plots.
4. Explicitly revoked R0/R1 source or binary cannot be resurrected by relabelling
   an old certificate. Repair uses new identities/key/paths. Qualification needs
   the original nine production gates AND physical_bank_clock plus
   memcpy_payload_identity, all production-driven PASS with exact evidence hashes.
5. Native adapter requires explicit qualification_publication/path and exact
   producer_publication/contract_path. No old R0 defaults. Existing producer CSV,
   PAIR_RECEIPT, original feature vectors/keys and raw paths are consumed unchanged.
   A new R0.1 adapter must be authored from the actual repaired release schema.
   An unrecognized producer schema fails closed and requires an explicit mapping;
   these tools do not claim an unbuilt R0.1 schema is already integrated.
6. Native raw/config/executable and qualification evidence checks remain in place.
   Normalized packets additionally retain Lane-5 receipt/bundle/payload hashes.
   Dataless SASS numerical output remains unavailable; symbolic version, identity,
   lifecycles and physical-cycle checks are explicitly scoped, not full-byte PASS.
7. Partial CURRENT_ACCEPTED pairs may publish; preserve failure/pending rows and
   no cohort mean until all five predeclared workloads. A completed single side
   is validated even without its mate. Zero accepted pairs emits no formal plot.
   A supersession change vetoes a previous accepted packet, including at the last
   check before any output directory is created. There is no automatic mutation
   of already frozen published plots: future revisions audit/withdraw them.

The strict CURRENT_ACCEPTED vocabulary is a consumer condition, not a request to
rewrite old Lane-5 records. Current suspended native schema is consumed directly.
The production runner/registry, repair gates, budgets and scientific CSVs are not
modified here. Future ideal intake additionally needs matched repaired R1.1
binary and separate diagnostic qualification; implementation plotting rejects ideals.
