## New findings and minimal changes

**F1 — confirmed TVD eligibility bug, fixed in source.** In `ab413:src/gpgpu-sim/l2cache.cc:1191–1203`, TVD executes before the ordinary texture-only eligibility test at 1211–1214. A global read of a clean victim originally loaded by a texture instruction can receive TVD data even though texture-only L2 requires that global read to bypass. The real call to `mem_fetch::istexture()` uses instruction space (`mem_fetch.cc:127`), not merely `TEXTURE_ACC_R`. The new TVD gate uses the same eligibility predicate as the ordinary path. Primary all-access-L2 traffic is unaffected by this predicate. Regression source constructs actual texture instructions, then proves global bypass and subsequent texture TVD service using the real subpartition/DRAM/response queues. No runtime reproduction is claimed.

**F2 — confirmed common FT bypass audit omission, fixed in this isolated branch.** The ordinary bypass branch enqueues to `m_L2_dram_queue` without `ft_record_admission`, while the actual return branch unconditionally calls `ft_record_response` (`ab413:l2cache.cc:1171`). In FT mode a bypassed global read consequently lacks the live UID token required by `ft_record_response` (2578–2581). This is independent of F1: fixing routing alone exposes the missing token. The minimal change records admission at the existing bypass enqueue; disabled-L2/non-FT behavior follows the existing no-op audit guard. No common release or Lane1 worktree is modified. The new route regression also checks exact-once closure via `l2_char_no_resource_leak()`; its dataless bypass return is checked for routing/identity, not fabricated numerical values.

**F3 — clean cost instrumentation gap, filled without changing dirty metric semantics.** `ep-l2-tvd-directory.h::advance()` accounts WB_STAGED separately and only WB_INFLIGHT/WB_COMPLETE in `tvd_extra_retention_slot_cycles`. CLEAN victims therefore had no integrated slot-cycle cost, and the printed `retention_slot_cycles` could be misread as total TVD cost. Preserve that legacy field as **dirty post-lower-accept cost**; add `clean_retention_slot_cycles` and `total_retention_slot_cycles = clean + dirty`. All use physical-cycle deltas; neither memcpy offset nor WB staging belongs to this total. This is instrumentation, not a change to capacity, arbitration, or science. A new gate holds one real clean victim for seven idle physical cycles after 4096 host-prefill offset increments, then removes the exact host alias with no fabricated cycles. All new metrics remain unvalidated at runtime.

**New uncovered boundary prepared:** a production gate first occupies all 128 shared WAD/TVD entries with CLEAN victims, then promotes one while evicting a dirty resident. It checks reuse of the source directory index with a fresh incarnation, the same promoted Payload handle, mandatory dirty ownership, fixed 1168 physical slots, version service and eventual WB_COMPLETE/drain. This differs from the old gate that filled all 128 entries with mandatory WADs. It exercises the actual `preview_dirty_promotion`/`commit_dirty_promotion` integration, not another standalone directory fixture.
