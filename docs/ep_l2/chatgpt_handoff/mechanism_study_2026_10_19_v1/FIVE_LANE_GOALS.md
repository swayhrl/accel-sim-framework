# 五个Codex窗口：独立Goal、共享规划、连续交付

所有窗口首先从用户给定的不可变Framework协调HEAD完整读取本目录MASTER_PLAN.md、EXPERIMENTS.md及本文件自己的段落。严格以本轮新任务EPL2_MECHANISM_STUDY_20261019_V1登记；旧Lane1/3/4/5、R19和迁移任务不重启、不reset、不覆写。默认原174环境，不冒用174-new身份。

新建独立分支/工作树，不复制大输入目录；借用既有只读输入与必要构建资产须核路径、所有者和hash。B/C只维护模块和测试，不与A同时改公共cache/partition文件。E唯一启动完整应用；D可做离线分析，不自行启动完整模拟。

## A — 公共实现、局部L2诊断与唯一集成者

建议新分支：hrl/ep-l2-ms20261019-a-core-v1（Framework/Core各自记录实际起点）。

目标：最早交付一套可运行、可独立验证的正常旧/新结构＋两类局部L2诊断，随后分批接入B、C。不要等两个新机制全部完成才发布第一版。

1. 核Core84359d4、运行Framework197741b、vendor及当前接口；读取旧Lane1发布/11项资格和Lane4未编译host-prefill修正。只按实际代码缺口适配，不能整体合入未资格历史分支。保存原mode全关行为。
2. 先冻结一个小型INTERFACE.md：payload句柄/sector/version、tag attach/detach、victim目录、已有WAD和请求描述符池的预算、响应与回滚接口、B/C模块挂接点。负责一切公共文件整合；B/C给适配patch，由你接入。
3. 按EXPERIMENTS.md实现S_COPY_FREE、S_L2_DATA_FREE和U_L2_DATA_FREE，开关相互隔离、默认OFF；只理想化命名的L2数据服务，不能旁路L2、取消实际miss或给免费显存。固定基本延迟，列明仍存在的本地容量/前端限制。无争用模式只改变服务模型，不伪造正常单端口断言PASS。
4. 接D提出的最小汇总计数：按真实request id区分不同请求和重试，首等待到解除的时间分布，copy操作，实际数据槽/请求记录占用，lower读写字节；观察不得改正常时序或替换状态。用定向案例验证observer ON/OFF不改变语义及模拟周期。
5. 每个发布先跑受影响的生产路径测试；构建仅在E确认资源后执行，最多-j2。不反复重跑未变模块全部资格；每个发布保留准确编译命令、来源/可执行文件hash、默认OFF结果和支持组合表。至少一个旧已知输入的完整正常对照安排由E计入24次，不自行另跑。
6. B/C谁先交正确候选就先集成谁。可以发布R1局部诊断、R2-victim、R2-RO等独立版本；不把未经验证的两机制组合捆绑发布。新版本比较必须有同binary父模式对照。缺必要输入或科学协议变化才暂停相关候选。

交付压缩为：INTERFACE.md、SUPPORTED_PROFILES.json、RELEASE.json、受影响测试记录、给E的唯一可运行版本入口。实际未编译/未运行如实标注。普通编译、脚本和路径包装问题自行修复继续；不修改资源底线，不等待稿件/PPA完工。

## B — 动态淘汰数据缓存实现与验证

建议新分支：hrl/ep-l2-ms20261019-b-victim-v1。

目标：先证明共享池保留的淘汰数据真的能服务后续读、减少显存读取，再做真实应用。不是只增加命中计数。

1. 读取原始架构和当前WB-only释放路径，快速盘点历史TVD实现、资格和失败记录。向A报告哪些可复用、哪些未实现；不把旧开关、影子模型、撤回结果当实际功能。
2. 在A接口上独立实现/恢复CLEAN_ONLY模块与同预算固定victim对照，按EXPERIMENTS.md计入目录项、额外查询周期和bank读取。共享总1168数据槽、128 WAD/TVD目录预算；mandatory返回和写回优先于可选干净victim，不能新增无预算数据RAM。
3. 先提交生产路径循环复用正例、流式无复用负例、容量回收与同地址写/sector数据正确性小测试。随后补原设计脏WB pending/inflight读取、写/atomic等待、promotion、完成后保留或释放语义。每个已完成子集独立命名，未完成部分列缺口；不让完整脏路径拖住已经合格的干净子集实验。
4. 数据值或版本必须来自被测真实缓存路径，独立参考模型只用来比对。特别测试发送后本地继续保留、槽位复用、晚到响应、目录满/下游满解除后可排空。保留旧packet快照，不读取已释放槽。
5. 交模块、定向测试、资源/延迟表和小适配patch给A；不修改公共文件，不自行编译全模拟器或启动完整应用。D负责确认哪个真实应用有机会，E独立资格后安排应用；无加速不视为功能失败。

出错时先修局部，不新建另一套victim框架。只有必须改变原始语义/总预算或无法证明数据正确才停止相关模式。完成的模块应持续交付而不是等整条线结束。

## C — 只读标签提前释放与请求跟踪分解

建议新分支：hrl/ep-l2-ms20261019-c-ro-v1。

目标：分别验证标签被未返回请求占用、传统缺失地址记录不足两种限制，不能把两个改动混成一个开关。

1. 查历史RO相关候选（含30c2920a）、原始架构和撤回/失败原因。现84359d4默认拒绝这些功能；不能只放开校验。Lane4的8ff56eb0是host-prefill/ideal集成候选，不能误认RO生产版本。
2. 与D确定完整epoch的只读资格清单。明确oracle性质；排除任何store/atomic/host更新/别名未覆盖line，无法证明的请求回退正常路径。不改trace opcode以制造触发。
3. 按A接口实现T标签脱离、M不使用传统line-MSHR两个独立开关和00/10/01/11四格。T-only仍保留正常line-MSHR，M-only仍等待标签；如某格不支持，明确未实现而不是冒名给结果。四格共享原512请求描述符和实际数据槽预算，新增控制字段/查找成本记录在案。
4. 用真实cache输入做多个独立只读miss映射同组的压力正例，并测试旧tag被新地址重用后旧返回、同地址重复miss、四sector乱序、描述符满、响应背压、host prefill和写/atomic回退。请求恰好完成一次，旧返回不污染新tag，数据槽不早释放。
5. 输出实际detach、避免MSHR分配、有用独立在途、重复读、lower字节及等待统计，交给A/E。不得用在途数量上升代替吞吐或性能。只读证明来自全epoch，不因短片段未发现write就授予完整应用资格。

C可与B并行写独立模块和小测试，公共修改由A整合；不自行启动完整应用。需要新binary对照由E统筹24次预算。某一真实应用没有标签或MSHR压力，是应保留的负/零机会结果，不应无限改小容量去制造。
