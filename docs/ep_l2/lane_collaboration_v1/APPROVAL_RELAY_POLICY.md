# E2批准后通知约定

用户已请求将“E2报告具体问题/方案→用户批准→E2通知受影响lane→本人ACK/交付”固化为脚本流程。E2负责录入与转发，不成为新的批准者。用户直接指令和已有授权继续有效；普通已授权工程不重复问批准。新科学范围/条件/重试等仍按原合同审批与中央准入，通知不等于启动授权。

流程：任务包先发布并钉commit/path/SHA；需要用户批准的方案在本窗口汇报，批准原话由E2如实记录并绑定准确packet SHA、recipients、task_ids与scope；脚本只校验引用/结构完整性，不能认证真人或理解批准语义。随后一次前台调用完成不可变REQUEST、原Git发布/回读、三个原收件目录提示与E2投递回执。

本人ACK、WORKING、结果DELIVERY各自独立，不由发送成功推断。失败或缺ACK保留pending；不静默加任务、不重发应用，不建第二controller/后台poller，不改中央资源或CLIENT/生产源。原科学身份、历史计费与结果累计政策不变。

实际边界：当前已接入工具与已知协作路径未发现独立lane窗口的唤醒入口。脚本保证元数据投递与追踪，不声称能唤醒IDLE/已结束窗口。活跃lane在既定安全边界消费；如果真正卡在不可唤醒窗口，E2报告准确依赖，只需一句恢复，不要求用户再复制材料。

本次通知只采用上述转发约定，不批准任何未来完整应用/native/build或输入/资格/预算变更。现有合并准备批次r2继续既有准备范围，B无新增研究任务，Conv ON原执行继续。当前各lane无需用户重复转发本约定，E2会通过原通道投递。
