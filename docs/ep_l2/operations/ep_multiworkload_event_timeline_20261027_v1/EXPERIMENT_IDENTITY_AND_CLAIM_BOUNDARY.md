## Reading the Tag funnel correctly

The terminal Tag counters have two different populations:

1. The production preview invokes the actual Tag-array probe for the current ingress head. A full set of RESERVED ways produces real `RESERVATION_FAIL` here. The Frontend can deny the head before `ft_access` is attempted.
2. `raw_tag_fail_commit`/LIFE `PROD_TAGFAIL` cover the later actual access probe, restricted to admitted accesses. They can be zero when preview has already blocked all full-set requests.

The historical name `pressure_prod_probe_reached` refers to the production **preview**, not an actual access commit. Never interpret its name as proof of an access invocation. Conv's exact raw/source/joint audit is in `CONV_S_PRESSURE_TO_PRODUCTION_AUDIT.md`. The cohort tables retain both counters rather than rewriting the accepted point or treating either as the other's value.

`new_unique_reserved[0..8]` counts distinct NEW requests once; repeated NEW head observations count repeated checks while the request waits. Occupancy histogram duration counts physical-set × L2 ticks; its occupancy-weighted sum counts RESERVED-Tag × L2 ticks. These are distinct units. Maxima are maxima over per-set records, never summed across sets. A full-set time area is not global elapsed GPU stall time. RO issued-but-unready exposure is not pure DRAM latency. Independently measured marginal counts are never multiplied to infer simultaneous pressure and detach eligibility.
