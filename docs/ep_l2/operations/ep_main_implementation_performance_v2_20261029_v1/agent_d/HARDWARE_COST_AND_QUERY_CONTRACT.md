# Costed ordinary RO Tag relief contract

Status: ENGINEERING MODEL CANDIDATE. Native/application qualification is NOT_QUALIFIED. Physical timing, layout, area and power remain UNKNOWN.

The correction is default OFF (`-gpgpu_ep_l2_ordinary_ro_tag_relief 0`). It is inert when T is OFF. S/W/WV do not acquire RO runtime or RO resources merely because this flag exists. Legacy-F and corrected-F share a new ELF. Correction ON does not weaken any transaction, certificate, identity or allocator predicate.

The paid operation is a new *set-eligibility opcode* on the already modeled RO frontend metadata query port. The existing ordinary Tag probe supplies its raw failure and target set. Pure preview never launches the operation, reserves state, increments its counters or performs another Tag probe. Only the real post-preview frontend callback can issue a ticket when correction+T are enabled, the ordinary exact plan is raw-full, and lookup is not mature. The query shares `query_issue_cycle/query_uid/query_ready_at` with normal RO lookup: one issue per slice per physical GPU cycle, ready no earlier than issue+1 physical GPU cycle. Repeated callback for a pending UID neither reissues nor repeatedly charges the same waiting cycle. A competing UID in the same physical cycle is denied. On a slower L2 clock the next opportunity is the next L2 frontend tick satisfying this deadline.

A mature ticket permits evaluating the unchanged same-set `detachable` predicate: live transaction, attached, not reuse_seen, required sector not ready, T enabled. Selection preserves first eligible way order. Actual backend `relieve`/`detach` revalidates transaction, payload owner, Tag generation and identity before mutation. Query readiness alone does not allocate a descriptor, Line-MSHR, Payload, WAD, MissQ or response slot. Existing frontend and backend guards remain authoritative. Corrected direct backend callers cannot skip the paid ticket. Legacy OFF preserves the previous direct backend contract.

This is not a proof that software scans are free hardware. A possible implementation reads way-to-payload handles from the already accessed Tag control view, obtains attached/reuse/required/ready from RO transaction metadata indexed by these handles, compares eligibility, and encodes first eligible way. These fields are already maintained by admit, merge, lower response, detach and retirement. Extending the query opcode still needs metadata read layout, way parallelism or serialization, comparators, a priority encoder, coherence of the held control view, routing and arbitration. Their exact implementation and ability to complete in one physical cycle have NOT been synthesized or timed. The one-cycle shared-port service is an explicit finite modeling assumption; it is not V100 timing evidence, an extra unpriced port, an SRAM area claim or a guaranteed implementable clock target.

The inherited RO model reuses a mature head ticket while the requester waits for downstream resources; safety predicates are refreshed/revalidated from current transaction control state. The metadata/coherence and critical-path cost of this held view remains part of the hardware-model boundary. A more detailed implementation may require re-query or pipelining and must use a separately identified Source and controlled comparison.

`EPL2P1V2|SET_ELIGIBILITY_QUERY` reports successful ordinary query issues, paid physical-GPU wait cycles (deduplicated per head per physical cycle), and denied shared-port attempts. Population is ordinary raw-full frontend heads under correction+T. They are not DRAM cycles, exclusive application stalls, unique ingress arrivals, or whole-program critical-path cycles. Shared `EPL2ROC1|RESOURCE` query totals include this opcode as well as RO-address queries. Raw TagFAIL, virtual preview relief, actual backend relief/detach and final request acceptance remain separate diagnostic populations. Diagnostic query waiting is classified as existing early=3/primary_query in the final integrated Source.

CPU evidence proves ticket timing/arbitration, callback deduplication, preview non-mutation, resource guard preservation and symbolic-sector identity/drain. It does not establish application NI or performance benefit. C/B measures the net corrected mechanism including this service cost; it is not a comparison against the prior uncosted engineering patch.
