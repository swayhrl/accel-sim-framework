## Physical budget versus effective role availability

All three instantiate1168×128B=149504B data slots per slice,4 banks×292 slots, P1 one operation per physical L2 cycle, and the same explicitly costed128B copy latch. Nominal region anchors are1024 Resident+128 Bypass+16 WB, with512 descriptors,128 line-MSHRs and128 shared WAD/TVD addresses. Logical Tags are32×8=256 per slice. These are fixed modeled resource budgets, not proof of equal silicon area.

**S:** gpu-cache.h2547–2554 and2839–2842 enforce FT1 role ranges: Resident[0,1024), Bypass[1024,1152), WB[1152,1168). `ep-l2-ft-cache.inc424–425,443–445,504–511` places a static Resident at its actual Tagindex. Consequently only256 Resident locations (64/bank) are addressable by attached Tags at this geometry; the remaining nominal768 Resident slots are not borrowed as WB/TVD/RO. Bypass remains its fixed128 and WB fixed16 (4/bank). This unused nominal capacity is a real consequence of direct static binding under the requested reduced-Tag geometry, not an implicit reduction of the allocated data array. S has no TVD/RO lookup/retention runtime. Native miss/descriptor paths still enforce their finite budgets.

**F−T and F:** FT2 scans all1168 slots with bank=id%4; the Tag sidecar is256 entries and does not cap physical IDs (`gpu-cache.h2941–2945,3442ff`). All292 locations/bank can serve dynamic roles under current ownership/protocol limits. Clean victims can reuse the existing payload or retain through TVD; dirty victims transfer in place to WB, then receive a separately bank-compatible landing (`ft-cache.inc389–410,498–511`). The reported legacy static_wb_capacity16 is an anchor, **not a hard dynamic WB occupancy quota** when FT2 and wb_local_cap0 are used. WB/TVD remain bounded by pool ownership and the128 shared directory/WAD entries; retaining victims competes with required WB identities in that same finite directory.

S dirty eviction really reads its source and writes the reserved static WB through the one-cycle costed copy latch (`ft-cache.inc459–485`), while FT2 changes role without data copy. Both consume actual bank service for native response/fill/WB operations; equal P1 caps do not imply equal logical operation counts. S/F thus measures the combined W/V/T/M organization and usable role allocation. **Only F−T/F isolates T.** Giving S a new arbitraryTag→fullResident allocator to make all nominal Resident slots usable would change formal S and requires a new named mechanism/control; it is not a routine correctness fix.

TVD is created only when clean/dirty flags request it, with128 entries (`gpu-cache.h2960–2963`, tvd-directory.h115–119). F pays real one-port frontend CAM pipeline timing (`tvd-cache.inc89–90`) and completion CAM cost; `tvd-cache.inc247` expressly emits metadata_PPA=UNKNOWN and metadata_clock_closure=UNKNOWN. S retains its WAD capacity but does not instantiate the extra TVD feature. Therefore data-slot/entry-budget fairness is PROVEN; bit-exact metadata area and physical clock closure equality are UNKNOWN.

M is an allocation policy, not an extra128-entry hardware grant. `ro-runtime.inc219–231,289–291` preserves shared512 descriptors and per-address admission while skipping ordinary line-MSHR allocation for certified RO when M=1. With M=0, the original128-line probe/capacity gate applies. `ro_init`373–377 enables the RO runtime whenever T or M is on; F−T keeps the same oracle/RO query and responses because M=1, with one-cycle/one-port RO queries (`109–119,438`). T-only scans actual8-way same-set candidates and existing can_detach (`233–250`), with no relaxed reuse/sector protection. Turning T0 does not disable RO requests or M.
