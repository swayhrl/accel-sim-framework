实际L0是100 CORE cycles。282项有效回显与D/config-0覆盖值均为100，注册默认30不等于有效值。因此用户的“若L0=30则改60”条件不成立，本轮保留原授权L1=200。没有运行60，也没有扩大200以上。200是敏感性扰动，不能称为原始GPU硬件延迟或默认配置收益。

F100→F200：cycles 77237→77767（+530，0.686200%），RO平均owner时间1218.580858→1317.807776 L2 ticks；未ready状态暴露872.636958→995.097940。各点分别用完整退休人口做均值，跨点RO人口不同，不能当作逐事务配对延迟。NEW到达时R≥4占比增加，R7/R8仍为0，真实TagFAIL/relieve/detach和detach后接受均为0。详见附加联合分析。

结论等级：PROVEN是本已接受六点的数值与受控配置差异；LIKELY是有限上游注入、分散Set和排队反馈共同使Tag压力不足的解释；UNKNOWN是逐packet固定队列真实驻留、核心/全访存路径独占损失分解、跨负载泛化与数值SASS输出；HYPOTHESIS是换负载可能出现真实Tag压力。不能从本轮零触发推导T错误，也不能证明T在所有负载无用。

报告边界：模拟器与CPU fixture验证协议/身份/完整drain；既有trace没有DtoH数值输出，numeric_SASS_output_validation=UNKNOWN。flushL2=0，完整在飞事务drain不等于末端脏行全部写回。因此DRAM写字节随调度改变可能不同，保留各点实际WB/column数量，不写成全应用最终内存流量守恒证明。

三项已证实的资源约束观察是L2 MissQ、L2→DRAM FIFO和DRAM Scheduler曾达到128并发生相应full/拒绝；它们是路径上的实际拥塞点，当前计数人口不同，无法形成端到端瓶颈的严格排名。Credit和ReturnQ的现有阻断观测为零，Tag分配和T未饱和/未触发。S100→S200的cycles变化也保留，微小非单调变化不能解释为硬件普遍受益。

下一项最值得考虑的是被动固定延迟队列时间戳分解及定向非干扰fixture，候选设计保留未执行。只有未来独立授权的新Core/预算才可运行。当前论文应写：“在同几何正式模式配对及预调度固定延迟100→200的受控敏感性中，预约重叠增加但独立NEW未遇到8路全部RESERVED，生产TagFAIL与T触发均为零；T独立cycles收益为0。高延迟结果仅为敏感性结论。”
