## Minimal production ordering

The old CLEAN-retention hook runs after successful data_cache::access. Putting a HOLD there would risk repeating already visible Native effects. This implementation instead pays row READ/COMMIT in the existing ft_pending replacement transaction before tag-handle or old-payload mutation.

The existing landing/control reservations retain real payload capacity while the transaction waits. The original Native victim/tag and displaced directory row remain intact. Before Native commit the helper checks incoming/displaced owner and generation, reader pins, pending sectors, landing ownership, selected tag state, lower issue space and MSHR availability. Generation/incarnation exhaustion fails before destructive publication. If its selected directory opportunity becomes unavailable, it HOLDs and cancels only its owner4 metadata ticket.

On successful Native access, the just-validated directory plan commits in the same synchronous call, with no post-Native HOLD. Only then are displaced payload data released and the incoming victim transferred to TVD. A pre-Native abort uses the real existing ft_rollback, with new owner4 ticket cancellation before source restoration. No directory mutation has occurred at that abort point. The CPU abort test checks this new wiring; it does not newly certify every possible Native failure.

Directory validation is now nonmutating and separately reusable before Native. commit_install publishes one count_target assignment: +1 into a free row, net0 when replacing CLEAN, or -1 when a different caller replaces CLEAN by WB. Net0 no longer performs a decrement followed by increment. Other callers receiving this arithmetic change do not automatically acquire paid row service.

## Costs and incomplete scope

No persistent field, data array, packet bits, queue or hidden capacity is added. The existing transaction holds a real landing reservation; this can backpressure other work. K1/K2 row service and one count publication are paid, including net0. Incoming/displaced payload metadata validation, role-transfer/release control muxes and physical port timing are not free and remain hardware-qualification gaps.

The timed prototype is restricted to dynamic retention, WV both classes, ROoff. Fixed-retention64 is rejected for this new timed combination; its previous-source artifacts remain available and untouched. Other DIRTY installs, general reclaim/promotion, reader lifetime/response service, complete rollback/cleanup, all-producer count-lane arbitration, CDC, RTL and PPA remain incomplete.
