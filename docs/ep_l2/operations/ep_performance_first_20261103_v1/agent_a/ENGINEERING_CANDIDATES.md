# W/V performance-first candidates

Priority: use the existing Source78 retention-class switches first. FWT and GEMM have accepted W/WV cycle reductions of about1.48%, while W alone is near zero. Two additional class points per input can expose a useful configuration quickly without new Core. This is performance exploration, not a claim that class decomposition itself increases performance. All starts still require Main scope authorization.

1. **CLEAN_ONLY / DIRTY_ONLY**, keeping U16/P1/1168Payload/D512/WAD128/LineMSHR128. Exact option values and inputs are in WV_PARAMETER_FAMILIES.json. Existing W=(0,0), WV=(1,1) and S reuse requires full Source5/input/observer/config identity. FWT first2points, GEMM conditional2. Source mode guards permit the classes, but named Host/native/parser profiles are NOT_QUALIFIED. Real header CPU four-class tests PASS; full production path is still required. FWT remains RO disabled.
2. **P1/P2 bank service**, currently usable in S/W-only engineering. This is four same-observer new points/input, not just two P2 points: accepted P1 uses MS observerON while P2 forbids it. S/W both get identical P2 hardware. WV/F P2 is explicitly prohibited by present source guards, so it needs a separately validated new Source. Additional service capacity is not an equal-area result.
3. **Directory128/256**, physicalPayload1168 and mandatoryWB128 unchanged. A header-only template candidate and three actual UBSan runs exist. Default outcome matches original header for the directed sequence; extended256fills, mandatory128, reader pins, generations, pure preview, stale plans, promotion cap and drain PASS. Full integration is PARTIAL. Merely changing constructor128to256 would silently remove the current shared-directory WB bound and can violate later m_ft_wb<128. The candidate therefore separates mandatory_limit. No assertions were removed. A maintained finite mandatory counter or explicitly costed status reduction is still required before production integration.
4. **Dirty-install cross-class event-age**, retain the existing Main candidate narrow scope. This is one candidate among several, not a promised best policy. Existing age already updates on real service, and same-head lookup ticket reuse already exists; neither is a new missing function.
5. **Per-bank optional admission/reservation**, lower priority until actual same-color pressure evidence warrants it. Keep real color placement and mandatory progress; global free slots are insufficient evidence.

# Source constraints that affect the authorization package

Source78 gpu-sim.cc:280-346 registers WBUF8/16, bank_ops1/2 and retention switches, but registration is not all-mode support. gpu-cache.h:3347 constrains RO to U16/P1/D512/line128/WAD128;3351-3365 constrains MS observer to P1;3371-3381 constrains TVD to U16/P1/WAD128 and finite pools. The actual directory is constructed at128 in gpu-cache.h:2962 and typedef3080; ep-l2-tvd-directory.h has128 sentinels and array capacity. WAD-only or descriptor-only parameter changes in WV/F cannot be declared ready merely because an option exists.
