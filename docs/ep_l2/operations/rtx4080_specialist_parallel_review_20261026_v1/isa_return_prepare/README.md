## Confirmed source boundary

Audited frozen ada_semantics.h SHA3177287d... (same source in saved JIT producer) branches on CALL.REL.NOINC opcode, extracts the first hexadecimal token, and clears all PLR src/dst as ABI summaries. This is safe to reuse only within its explicitly measured operand scope.

Real newdelete maps contain CALL.REL.NOINC R8 0x0 and R12 0x0. The isolated old expression resolves0, discarding the physical target-pair distinction. We found13 such static sites across the two selected newdelete binaries. This is a demonstrated helper/operand-admission gap, NOT proof that any historical trace was wrong. These jobs were held by the ordinary static gate.

Only three frozen map manifests were read: Gaussian and two newdelete images, with exact manifest/TSV/PLR hashes retained. No asset sweep or trace-body SHA pass occurred. Gaussian is direct CALL0x280 -> owner0x2f0; return0x960 uses R6:R7 with zero anchor. PLR explicitly contains6/7, and preceding SASS clears R7. Do not truncate or assume that high halves are universally zero.

## Candidate scope

The Python candidate uses anchored full operands, numeric same-owner nonzero aligned direct CALL targets, exact zero-anchor even GPR64 return pairs, checked full64 PC arithmetic, retained pair/guard dependencies and separate ABI summary metadata. Relative register-indirect, ABS, unknown suffixes, nonzero anchors, missing/cross-owner targets and pair boundaries reject.

Twenty-nine CPU positive/negative grammar and synthetic lane-flow tests pass, including first-hex/register target confusion, full high-half preservation, predicates, zero-mask effects, next-active successor, owner mismatch, target0, overflow and return-pair limits. Static classification across the selected maps:7 direct CALL,113 zero-anchor RET candidates;13 relative-indirect and66 ABS sites fail closed. These counts grant no whole-program eligibility.

The first future GPU scope is the unpredicated single CALL/RET Gaussian16 owner only. Predicated CPU plans retain P/UP tokens, while the frozen ADA8 consumer forbids CALL sources; supporting those plans therefore needs an explicit producer+consumer contract revision, not silent schema reuse.

No NVBit/CUDA producer has been built or patched here. CONTRACT_CPU_CANDIDATE_V1.json describes the unapplied fail-closed integration guard. The indirect .cu file is an uncompiled plan, not evidence that a compiler emits a particular opcode.
