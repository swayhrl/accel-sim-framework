## Preferred conditional direction

Prepare one bounded service-aware optional-V reclaim design, using actual served status rather than workload names or future knowledge. A minimal served bit is set on real service commit and cleared on allocation/generation reuse. Select within a finite existing bank-compatible eligible window, prefer a legally reclaimable unserved optional entry, and retain baseline fallback and mandatory progress. Mandatory/in-flight WB, WAD ownership, readers/pins, pending sectors/returns, directory and Payload identity/generation remain protected. The extra-retention statistic includes WB_INFLIGHT; it must not be treated as entirely optional reclaimable space.

This is not a proven benefit: an unserved entry can become useful and a previously served entry can become dead. Specify served-state aging/lifetime, tie fallback, bounded selection depth, bank-color behavior, metadata writes/read ports, comparison/arbitration costs and modeled latency. Do not introduce an uncharged global associative scan or indefinitely protect ever-served entries. Extra bits alone do not prove physical area/timing feasibility. Default old behavior must remain available in a new independent Source/ELF; accepted code is not automatically modified.

Production already caches completed same-head Victim lookup via m_tvd_lookup/m_tvd_lookup_done/ticket. Reimplementing it is excluded as a new proposal. A negative filter remains lower priority until negative-query incidence beyond that token and update/port/no-false-negative guarantees are established. Arbitration changes also need a specific service/fairness observation, not just a full-queue maximum.
