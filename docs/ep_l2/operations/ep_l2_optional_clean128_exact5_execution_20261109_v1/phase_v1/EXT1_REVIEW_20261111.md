# EP-L2 Stencil EXT1 单点申请审查

**审查结论：建议按草案批准恰好一个 Stencil EXT1 完整应用点，用于机制归因；执行授权仍待用户明确给出。**本审查本身没有登记、预算消费、模型启动或第二 dispatcher。当前 EXT0→EXT2 已证明该结构在 Stencil 上净慢 17,534 cycles；EXT1 的信息价值是判定迁移包与启用 CLEAN 策略包各占什么方向，不能预先承诺最终结构加速或物理成本可接受。

审查中修正了三处表述/校验：草案改用正式消费的 `FROZEN_SPEC.json`；将 `C2−C1` 明确为 CLEAN **策略包**的净效应；阶段表把来自 TVDV2 的 lookup wait 正确标为 TVDV2。脚本新增 B0/M0 每 kernel slice 唯一性与 Ext segment 模式/容量校验，结果未变。

## 可批准的精确范围

新授权应只覆盖同 Source5、同 Stencil 输入、同有序 100 kernel、`WV_ZERO_RO`、850MHz、G32×8、L100、完整 283 项中仅 extension 从 2 改为 1 的**一次**完整应用启动。新的 request/cohort ID、Spec/Host/Native pin、预算一次消费与资源准入须由唯一 Main 正式绑定；旧五点余额为零。复用已有 CPU/Input/Host/consumer 工程资格，不重跑历史 Goal，不新扫 Trace。验收沿原五点的人口、实际配置、排空、lossless raw、真164全 SHA 与两个不同 Native 目标的独立恢复。

判读以 `C0=4,768,893`、`C2=4,786,427`、新测 `C1` 为准：`C1−C0` 是迁移包净差，`C2−C1` 是 CLEAN 策略包净差。若 CLEAN 包改善但整体仍比 C0 慢，应优先针对迁移成本提出新工程假设；若 CLEAN 包使结果更慢，应停止本输入的同结构 CLEAN 扩点。任何情形均不能从一个新点推出跨负载稳健收益或物理 PPA 价值。
