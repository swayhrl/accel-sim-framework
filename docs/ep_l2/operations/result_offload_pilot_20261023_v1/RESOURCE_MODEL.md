## Network failure cannot make copy-only reclaim space

Let Q(t) be newly completed but still retained bytes, G(t) newly completed bytes since an outage begins and D(t) owner-authorized actual local reclaim. Then `Q(t)=Q(0)+G(t)-D(t)`. In this pilot D(t)=0, even after successful archive/restore. During a network failure no new result may be admitted to the storage stream, at most the one bounded stage/control/fault allowance remains, and the worker exits/HOLDs; it cannot stop the science controller or delete originals.

Finite uninterrupted-compute support requires a finite owner budget for all output that can be produced before a human/authorized controller's next decision. If completions are bounded by N remaining authorized attempts each with cap L, provision at least their sum (plus active write/metadata peaks) independently of network availability. An average rate g times outage duration T is only a planning approximation; bursts/largest unfinished member must also be bounded. Unlimited computation plus an unlimited outage has no finite-disk solution here. The proposed outbox does not create a new admission backchannel or modify current controllers to mask that fact.

Initial real-result pilot should copy already-completed owner-selected files without initiating any new application or freeing disk. This proves storage reliability, not disk-space recovery. A later source-retention/reclaim policy is an independent authorization task.
