### Agent B：跨时钟Completion-CAM P1修复

这是本轮最高优先级工程任务之一。

现有证据：

- Vector4M F1275已正式技术失败，不重跑、不退款。
- Source78在`gpu-cache.cc:2724`触发写回完成CAM每核心周期一次的断言。
- DRAM>CORE时同一核心周期可能出现多次合法的L2写回完成。
- 当前路径没有对完成CAM实行跨时钟有限排队或背压。
- 1275/1700MHz未消费候选保持HOLD。

立即在独立Core工作树开展修复。

优先研究：

1. 在DRAM完成侧与Core完成CAM之间建立有限且真实的事务交接。
2. 保持每Slice每Core周期一次的CAM服务限制。
3. 正确保留原始UID、地址、Directory incarnation、Payload generation和Writeback身份。
4. 明确何时归还credit、何时释放mem_fetch或已复制的完成记录。
5. 禁止丢包、重复完成、提前释放和指向已删除对象的引用。
6. 队列满时必须具有合法背压和最终前进能力。
7. 正确处理多个Slice、相同Slice竞争及跨时钟日历。

不能通过删除断言、允许无限CAM访问、修改为DRAM时钟计费或免费增加端口来掩盖问题。

先制作真实生产路径CPU复现：

- 850/1020/1132/1275/1700MHz。
- 相邻DRAM ticks的两次同Slice L2 WB完成。
- 部分dirty sector写回。
- 相同/不同地址、UID、generation。
- Queue full、连续到达、ReturnQ背压。
- stale completion、pin与完整drain。
- 默认850MHz原行为不退化。

需要的话可准备两个实现方案比较，但只选正确性和真实硬件成本更明确的一个进入新Source。

工程PASS后，形成新的Core/ELF与完整来源绑定。

未来性能实验要求同一个新Source下的S和EP公平配对，保留850MHz参考资格，不能直接用旧Source78的Vector S1275填充新Source对照。

交付：

`CROSS_CLOCK_COMPLETION_CAM_REPAIR_V1`

`CPU_PROTOCOL_AND_FREQUENCY_MATRIX`

`NEW_SOURCE_AND_ELF_QUALIFICATION`

`HIGH_CLOCK_REQUALIFICATION_PLAN`

### Agent C：850MHz下的系统参数与结构组合探索

不等待Agent B修复，继续利用已接受Source78和可靠850MHz基线。

目标是发现：哪些合理的上下游资源配置能够提高EP的绝对性能，哪些配置可扩大EP相对S的有效优势。

考虑参数族：

- L2 Miss Queue。
- Line-MSHR entries和merge能力。
- Descriptor与WAD/TVD资源容量。
- Payload Bank服务端口、吞吐及仲裁。
- L2与NoC接口缓冲。
- NoC注入/返回通道及队列。
- DRAM scheduler、FR-FCFS容量及下游排队。

先检查此前已执行的参数实验，尤其已完成的G64/W16、MissQ256、ICNT1024及其他负结果，不重复盲扫。

将新探索分为：

**真实可实现配置：** 有明确容量、端口、时序和面积成本的结构变化。

**诊断性宽松配置：** 用于发现性能上界，不直接排名为可实现硬件。

优先使用代表性输入：

- FWT、GEMM、3MM：已有机制增量收益。
- Stencil：历史完整F强收益。
- Scan、Conv：已知负例和资源压力。
- Vector：RO/并发与内存行为不同。

根据当前已接受输入身份和仿真时长，选择短程序初筛、中长程序验证。

对每一项资源改变，必须保持S与EP硬件背景可比，记录：

- S绝对cycles。
- EP绝对cycles。
- 同配置S/EP。
- 与原850MHz参考相比的绝对改善。
- 资源增量及硬件可实现性。
- 不利输入和失败结果。

不要只追求让S退化更多而产生较高的相对加速比。

采用自适应筛选，允许对有潜力的参数族继续扩展、组合及复核，不要求停留在任意固定的两点试验。

交付：

`SYSTEM_PARAMETER_FAMILY_V2`

`EP_ABSOLUTE_PERFORMANCE_FRONTIER`

`MATCHED_S_EP_CONFIG_MATRIX`

`RESOURCE_RELAXATION_UPPER_BOUND`
