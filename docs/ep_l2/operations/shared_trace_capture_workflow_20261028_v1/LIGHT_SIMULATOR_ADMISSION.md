# trace轻量模拟器验收标准

默认目标是验证精确trace能够由指定消费者和4080配置加载、解码并执行代表性工作。每个程序不再默认完整重放；已经完成的完整回放作为更强的现存证据复用。

## 三层验收

| 层级 | 必要检查 | 通过后可报告 |
|---|---|---|
| 契约准入 | binary与argv和输入来源、producer/profile、命令索引、全部kernel头、registry与实际consumer和配置身份一致 | 精确契约匹配 |
| 格式和特征覆盖 | 复用POST记录校验及特征索引，检查真实opcode、RF、地址和常量模式及有效CFI；无支持或覆盖不足项明确列出 | 指定特征已检查 |
| 有界执行 | 用真实消费者、核心和4080配置运行少量来源明确的完整CTA；确认加载、解码、调度及非零指令退休，正常完成所选小输入 | SIMULATOR_ADMISSION_SMOKE_PASS |

只加载头部或进程启动成功不足以证明第三层。达到时间或周期上限、异常退出、未知opcode或解码错误，均不能标为冒烟通过。

## 代表性小输入

优先使用已有裁剪资产及POST保存的完整CTA见证。选择少量能够覆盖该资产实际格式和指令特征的CTA，保留父文件、原始坐标、完整记录和选择映射。不要从指令序列中间截断，也不为验证改写原始trace。

新格式、新opcode族、特殊RF或有效CALL/RET出现时，增加覆盖该特性的针对性CTA；可复用同producer与格式族的公共回归。有效CALL/RET需要选到实际包含该行为的完整CTA。没有执行到的分支不能获得通用CALL/RET资格，也不应因此阻止其他已支持路径的精确输入准入。

某个资产找不到满足覆盖要求的小输入时，标出具体缺口，定向补验证。不要自动升级为整应用重放、穷尽所有输入或全配置组合。

## 默认边界

一次冒烟应有明确的小输入清单、时间和周期上限、实际硬内存限制、只属于自身的进程清理以及原始返回值。建议从1至8个完整CTA和至多3个代表kernel开始；复杂特性可以有经过说明的精确例外。具体预算随已审查入口签发，不把建议值当作已部署硬限额。

初始目标为60秒墙钟和250000周期以内完成所选小输入。需要调整时说明具体特性和预期工作，不自动扩大到全程序。缓存、已合格后处理和既有兼容回执直接复用。

## 结果和归档关系

新回执使用显式冒烟资格，至少记录父资产与子集SHA、consumer和核心SHA、配置SHA、实际代表CTA和特征、退休计数、退出原因及未覆盖项。

- 冒烟结果只支持所声明消费者、配置和特征范围。
- 完整功能回放、独立数值验证、性能及科研资格分别保留。
- 161项的采集、归档、公共目录和消费者四个交付要求继续成立。消费者可以按新的精确冒烟标准验收；不能为了增加完成数把归档或公共发布改成不需要。
- Gaussian64已有126个kernel完整回放，直接复用；其归档和公共发布仍需实际完成。

本规范改变默认验收要求。配套执行适配器在取得实际运行回执前，不应被报告为已经部署或已经通过。
