## 2. State machine

```text
CAPTURING
-> LOCAL_CLOSED
-> READY_TO_TRANSFER
-> TRANSFERRING
-> REMOTE_HASH_VERIFIED
-> TRANSFER_ACKED
-> ANALYSIS_READY
-> PARSED
-> FEATURED
-> DATASET_ADMITTED
```

No transition may be inferred from file existence alone.

## 3. RUN_ID

RUN_ID is generated by code, not free-form user input.

Human-readable minimum fields:

```text
C16R_<modelslug>_<scenario>_<phase>_<instrument>_<targetslug>_<UTC>_<nonce>
```

RUN_ID is a locator only. Scientific identity is authoritative in `RUN_MANIFEST.json`.

## 5. Producer finalize contract

`finalize_capture` must:

1. refuse an active/incomplete capture;
2. refuse missing required artifacts;
3. refuse symlinks unless explicitly whitelisted by schema;
4. create deterministic artifact inventory;
5. compute size + SHA256 for every regular artifact;
6. write `RUN_MANIFEST.json` atomically;
7. write a local close receipt;
8. create READY marker only after all previous steps PASS;
9. promote staging -> ready without overwrite.

## 6. Transfer contract

Source:

```text
109 ready/<RUN_ID>/
```

Destination staging:

```text
164 inbox/<RUN_ID>.partial/
```

Requirements:

```text
copy-not-move
resume capable
no overwrite of admitted raw
source manifest preserved
independent destination hash
```

Transport may use rsync over `ssh hrl174new`, but correctness is defined by the manifest/hash/ACK protocol, not by rsync exit status.

## 7. Destination verify/admit contract

174-new must:

1. read source `RUN_MANIFEST.json`;
2. reject duplicate RUN_ID with conflicting manifest;
3. independently enumerate destination regular files;
4. recompute size + SHA256;
5. compare exact artifact set;
6. reject extra/missing files except transport metadata explicitly excluded by schema;
7. on PASS, promote `.partial` to final immutable `raw/<RUN_ID>` using the Phase-B approved no-overwrite method;
8. write destination-side verification receipt;
9. write immutable catalog entry;
10. write `TRANSFER_ACK.json` only after catalog registration succeeds.

On failure, keep data in inbox/quarantine and do not ACK.

## 8. TRANSFER_ACK.json

Required fields:

```text
schema_version
run_id
source_manifest_sha256
destination_manifest_or_verification_sha256
file_count
total_bytes
destination_raw_path
verified_at_utc
verification_status
catalog_entry_sha256
```

Only `verification_status=PASS` authorizes 109 to mark the run transferred.

## 9. 109 ACK verification

109 must independently verify:

```text
run_id
source manifest SHA
expected destination identity
ACK schema
PASS status
```

Then move/mark `ready/<RUN_ID>` -> `transferred/<RUN_ID>` without deleting artifacts.

Deletion is a separate, explicitly authorized cleanup operation.

## 11. Filesystem portability

164 is visible through SSHFS/FUSE. Phase B determines actual filesystem capabilities.

The implementation must not assume:

```text
directory fsync support
renameat2(RENAME_NOREPLACE)
local-ext4 semantics
```

If Phase B records limitations, Pipeline V1 must use the recorded fallback while preserving no-overwrite and fail-closed behavior.

## 12. Legacy imports

Legacy scientific artifacts are imported by inventorying existing files; they are never rewritten to imitate a new capture.

Required metadata:

```text
legacy=true
original_path
original_campaign
producer identity
source scientific authority commit/receipt
source size/SHA
archive destination size/SHA
```

## 13. Safety / non-authorizations

Pipeline implementation does not authorize:

```text
scientific workload rerun
retokenization
model mutation
deleting source raw
rewriting old receipts
bulk recovery-root migration
host/root mutation on 109
```

## 14. Pipeline V1 end-to-end PASS

All must PASS:

```text

producer finalize fail-closed tests
small cross-node transfer
medium/large bounded cross-node transfer
partial/resume
```

Only then may real scientific artifacts be imported through Pipeline V1.
