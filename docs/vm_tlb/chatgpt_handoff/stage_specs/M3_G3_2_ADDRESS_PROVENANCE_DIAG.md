# M3 G3-2A — Address Provenance Diagnostic Before Any VA-Width Change

Ownership: ChatGPT

Status: AUTHORIZED DIAGNOSTIC ONLY

## Why this gate exists

G3-2 has already demonstrated that physical, non-recursive `PTE_ACC_R` requests can traverse the real interconnect/L2/DRAM path and return to the correct walker. A later BFS kernel then reached a translation key whose VPN violates the current G3-1 generic backend's hardcoded 49-bit virtual-address contract.

Do not infer from this alone that the correct fix is to widen, mask, truncate, canonicalize, or bypass the address. The M1 contract names the simulator transaction address `SimVA` and preserves identity-like `SimPA == SimVA`; it did not independently prove that all in-scope trace/simulator addresses fit 49 bits. The Segmentation paper's 49-bit VA is paper-specific evidence, not by itself a generic Accel-Sim trace-width proof.

This gate determines what the offending address actually is before changing accepted semantics.

## Absolute prohibitions

During G3-2A, do **not**:

- change `virtual_address_bits`;
- mask/truncate/canonicalize the offending address;
- alter `SimVA` or identity-like `SimPA` semantics;
- change the PTE namespace, reserved range, page size, ASID semantics, or page-table hierarchy;
- bypass VM translation for a memory-space class merely to make BFS pass;
- restore/pop/drop the historical `stash@{0}`;
- enter G3-3/PWC;
- call an observed >49-bit value a valid GPU VA, invalid trace, or local-memory artifact before proving its provenance.

Temporary diagnostic instrumentation is allowed. Keep it minimal and either revert it before the diagnostic closeout or clearly isolate it as diagnostic-only evidence; do not silently turn diagnostics into architecture semantics.

## D0 — Reproduce and print the exact offender

Using the same BFS trace/config/path that produced the assertion, capture at the first offending translation request:

- exact `SimVA` in hex and decimal;
- page size;
- VPN in hex and decimal;
- highest set bit / minimum width required;
- request UID;
- SID / TPC / WID where available;
- kernel sequence index and kernel name;
- PC / instruction identity where available;
- load/store/atomic;
- `mem_access_type`;
- instruction memory space: global / local / param-local / other;
- whether the address was taken directly from the trace or was transformed by simulator local/generic-address mapping before coalescing;
- transaction size and page-crossing result.

The evidence must include the exact line immediately before the assertion, not only the assertion text.

## D1 — Address provenance by memory space

For the available LUD and BFS traces, collect a bounded summary of every in-scope transaction reaching the VM hook:

- count by memory-space class;
- min/max `SimVA` by class;
- count with `SimVA >= 2^49` by class;
- maximum required address width by class;
- first N examples above 49 bits with kernel/PC/request identity;
- whether each example is raw trace-derived or simulator-generated/linearized.

Do not dump giant raw logs into Git. Put compact CSV/TSV summaries in the review pack and index raw logs externally.

## D2 — Trace address versus simulator-transformed address

If the failing instruction is `local_space` or `param_space_local`, explicitly trace the address through the existing local-memory path:

`raw lane address -> translate_local_memaddr()/equivalent -> coalesced mem_access_t SimVA -> VM hook`

Record both the pre-transform and post-transform values and the relevant simulator namespace/window constants.

If the failing instruction is `global_space`, prove whether the offending `SimVA` is the raw NVBit/trace address (modulo ordinary coalescing alignment) rather than a simulator-generated special address.

## D3 — Same address without functional VM

Run the same BFS workload far enough to cover the failing kernel in:

1. `VM_DISABLED`;
2. `VM_IDEAL_IDENTITY`;
3. functional VM only as needed to reproduce the stop.

For the offending request/address, establish whether disabled/ideal execution accepts the same numerical downstream data address and whether the run progresses beyond that kernel.

This test is about provenance, not about declaring the address architecturally valid.

## D4 — Rule out sentinel/corruption/classification errors

Check that the offending request:

- belongs to an active memory transaction;
- is not an all-ones/sentinel/uninitialized address;
- was generated by a real active lane / valid memory instruction;
- is not a PTE request recursively re-entering translation;
- has a stable/reproducible value on repeated runs;
- has a coherent memory-space classification.

If this fails, document the exact bug. Do not widen the address space as a workaround.

## D5 — Produce a decision table, but do not implement the decision

Classify the result into exactly one of these evidence-backed cases:

### Case A — legitimate raw/global SimVA exceeds 49 bits

Evidence must show a real global data request whose raw trace-derived `SimVA` exceeds 49 bits and is accepted in disabled/ideal paths.

Recommendation may state that the generic VM contract needs an address-width/backend revision, while the target Segmentation reproduction may still use a paper-specific 49-bit configuration. **STOP for ChatGPT architecture review before implementation.**

### Case B — simulator-generated local/param-local namespace exceeds 49 bits

Evidence must show the high bits arise from local/generic-memory linearization rather than a raw global VA.

Recommendation must compare at least:

- making the generic backend 64-bit/opaque-address safe;
- separating/canonicalizing the simulator-local namespace before page translation;
- intentionally removing local/param-local from functional VM scope.

Do **not** choose one during this gate. **STOP for ChatGPT architecture review.**

### Case C — malformed/sentinel/out-of-scope request

Prove the precise provenance bug/classification error. Recommend the minimal correction, but **STOP before changing accepted architecture semantics** unless the correction is purely diagnostic plumbing and cannot affect valid requests.

### Case D — evidence remains ambiguous

Report `BLOCKED` and STOP.
