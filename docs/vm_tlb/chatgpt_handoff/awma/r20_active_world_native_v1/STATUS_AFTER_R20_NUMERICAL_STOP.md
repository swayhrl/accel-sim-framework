## Why the Goal correctly stopped

Five complete 32-step B0 replays restored the same 138 Data arrays and used bitwise-identical controls, yet trajectories diverged in:
- physical state
- nefc
- solver_niter
- overflow

A same-entry one-step diagnostic was much more informative:
- sorted per-world semantic contact set: identical
- sorted per-world semantic constraint set: identical
- nefc/niter/overflow: identical
- pooled atomic contact order: different
- qpos max difference <= 5.66e-7 at one step
- qvel max difference <= 1.11e-4 at one step
- qacc_warmstart max difference <= 0.03244 at one step

These small immediate differences then amplify over a 32-step closed-loop rollout.

Therefore the whole-window divergence cannot be used to define a candidate correctness tolerance without risking acceptance of a broken scheduler.

No S1/performance result exists.

## Important source interpretation

Pinned MuJoCo Warp uses atomic allocation for pooled contacts and EFC rows.

The project's own constraint/forward tests compare EFC/contact-related quantities after sorting/canonicalization rather than requiring raw row identity in relevant tests.

This supports the interpretation that raw pooled row order is not itself the physical semantic contract.

It does NOT prove that all numerical divergence comes only from row order.
