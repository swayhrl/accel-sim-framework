# Strong software/system boundaries before any mechanism claim

1. **Execution overlap:** compare against [NanoFlow OSDI25](https://www.usenix.org/system/files/osdi25-zhu-kan.pdf) for heterogeneous nano-batch overlap, [Bullet](https://arxiv.org/html/2504.19516) for adaptive prefill/decode partition, and [MPK OSDI26](https://www.usenix.org/system/files/osdi26-cheng.pdf) for mega-kernel launch/sync removal. Each has a different model/precision/platform; none is a direct numeric C16 baseline. Bullet’s own naive/fixed controls rule out “two streams imply gain.”
2. **Fusion/dataflow:** [VTC OSDI26](https://www.usenix.org/system/files/osdi26-hu-muyan.pdf) compares the best of PyTorch compilation, ONNX Runtime, XLA and TensorRT; [ComFuse](https://arxiv.org/html/2608.03537v1) uses static max-autotune TorchInductor and TensorRT under CUDA Graph replay; [Kitsune](https://arxiv.org/html/2502.18403v1) compares PyTorch and modeled vertical fusion in a modified simulator. Check graph identity, numerical semantics, synchronization and whole-run latency before treating removed bytes as benefit.
3. **Quantized GEMM:** [StreamDQ](https://arxiv.org/html/2607.08993v1) explicitly tunes GPTQ/AWQ fused-vs-split by batch and includes AWQ-v2; its small-batch exception is a hard warning against extrapolating the modeled high-batch gain to C16 W4 B1. Prior LR06 MARLIN/QUICK/FLUTE are also in-scope neighbors. A new design needs a semantically matched AWQ fast-kernel baseline, not generic FP16 GEMM.
4. **Shared cache:** first compare software tile/group ordering and [PASCAL v1’s](https://arxiv.org/html/2609.10515v1) policy-independent traffic bound. [TileSight](https://arxiv.org/html/2607.22432v1) makes progress skew a measured failure mode for synchronized tile models. A cache policy with less traffic but no exposed time is not a performance mechanism.
5. **Serving memory:** [BOOST](https://arxiv.org/html/2609.13592) separates capacity from parallel bandwidth on GH200, demonstrating that a headline throughput gain can mostly be a larger runnable batch. Discrete RTX4080 does not inherit GH200 host-coherent properties. Generic KV prefetch and MoE expert locality also have strong LR11 neighbors (PRESERVE/SMOOTH/ReMoE/Oracle-MoE/KTransformers).
6. **Kernel utilization:** [Hopper utilization study](https://arxiv.org/html/2609.12923) supplies a multi-denominator diagnostic, not an Ada numerical result. A shape/CTA change must beat tuned cuBLASLt/FlashAttention or AWQ-specific kernels and preserve all parent semantics.

All reported gains above are authors’ claims at their own experimental points. `LITERATURE_EXPERIMENT_AUDIT.tsv` records exactly what was checked and what was not. Author code/artifacts: **NOT_RUN** across this map.
