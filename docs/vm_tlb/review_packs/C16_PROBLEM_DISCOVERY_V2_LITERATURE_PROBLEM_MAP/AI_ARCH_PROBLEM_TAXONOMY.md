Snapshot: 2026-10-01. This taxonomy is constructed from primary papers **before** consulting the C16 closure map. Cross-cutting discipline: a traffic reduction is not a cycle reduction; an oracle gap is not a realizable mechanism; a modeled speedup is not measured silicon; a strong baseline must preserve model, precision, input, process state and target identity. [NanoFlow](https://www.usenix.org/system/files/osdi25-zhu-kan.pdf), [MPK](https://www.usenix.org/system/files/osdi26-cheng.pdf), [Kitsune](https://arxiv.org/html/2502.18403v1), [VTC](https://www.usenix.org/system/files/osdi26-hu-muyan.pdf), [StreamDQ](https://arxiv.org/html/2607.08993v1), [TileSight](https://arxiv.org/html/2607.22432v1), [PASCAL v1](https://arxiv.org/html/2609.10515v1), [BOOST](https://arxiv.org/html/2609.13592) are primary source anchors.

## Scope and minimum architecture bar by family

| Family | Independent observation? | Generation/LLM specificity | Hardware gap and nearest-neighbor crowding | Minimum architecture evidence |
|---|---|---|---|---|
| Resource overlap | Yes: NanoFlow/Bullet/MPK see different boundary costs. | Not one GPU generation; serving policy and precision vary. | Generic overlap is crowded; hardware case needs software-resistant interference or control gap. | Native co-run timeline, identical workload, no-contention oracle, NanoFlow/Bullet/MPK-like control. |
| Data handoff | Yes: Kitsune/VTC/ComFuse/MPK, with different graphs. | Generic DNN DAG issue; LLM decode benefit is shape-dependent. | Compiler/runtime space crowded; Kitsune requires scheduler hardware in its model. | Exact source/sink bytes, sync cost, output equivalence, strong compiler, whole-model ceiling. |
| Representation conversion | Yes: StreamDQ and LR06 QUICK/FLUTE/MARLIN, but quantization formats differ. | Strongly format and batch dependent, not just architecture generation. | Software kernels mature; custom HBM remains a distinct hardware claim. | Same-format numerical equivalence, best fused/split kernel, native cost split and simulation qualification if hardware proposed. |
| Shared cache/progress | Yes: PASCAL and TileSight expose phase/skew effects. | Shared-scan geometry is not LLM-only; exact assumptions critical. | Replacement is crowded; progress-aware policy remains conditional on oracle. | Recover true worker phase, policy-independent traffic gap, measured timing exposure, software ordering baseline. |
| Low-batch utilization | Hopper study dissects multiple dimensions; MPK sees dispatch effects independently. | Published numbers are Hopper BF16; diagnostic concept broader. | Kernel/software shape tuning very crowded. | Platform-matched CTA/fragment/warp/stall/traffic view plus end-to-end zero-cost ceiling. |
| Tiered memory/translation | BOOST GH200 and reverse-translation modeled UALink are distinct, not independent evidence of one platform phenomenon. | Strongly platform-specific; not generic LLM GPU L2/TLB. | Host-tier placement already developed; fabric MMU gap not silicon verified here. | Real tier/fabric authority, capacity-only control, equal runnable batch and explicit translation-time sensitivity. |
| MoE movement | ReMoE/Patterns/SpecMD (LR06) point to expert locality but current round has uneven reading depth. | MoE-specific and dependent on routing/quality/offload tier. | Very crowded; full-text identity-matched residual needed. | Natural routing sequence, quality constraint, actual tier traffic, software placement/routing oracle. |

## Research-path distinction

**Phenomenon → diagnostic → headroom → strong baseline → mechanism:** PASCAL first derives phase/gap miss laws and a policy-independent bound; Hopper utilization first separates counter denominators; BOOST first identifies prefetch-induced HBM write contention and then tests capacity-only versus concurrent service. These are the most relevant templates for a C16 discovery gate.

**Mechanism → retrospective characterization/evaluation:** StreamDQ starts from custom-HBM dequant architecture and evaluates with calibrated simulation; Kitsune adds queue/scheduler primitives and then studies application coverage; ComFuse proposes a stage-stream execution model and reports shape-specific microbenchmarks. This path can still be rigorous, but its gain cannot be used as proof that the same mechanism is needed on C16. The two styles are not an objective paper ranking.
