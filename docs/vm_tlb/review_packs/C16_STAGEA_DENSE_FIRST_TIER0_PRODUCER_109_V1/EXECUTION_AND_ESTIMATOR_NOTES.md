The project authorizes **only** the exact `C16_STAGEA_DENSE_FIRST_TIER0_109_CONTRACT_V1.json` for a future Lane7/109 run. This CPU-only finalization executes no GPU work. The runtime canaries are qualification evidence, not Stage A samples. MP04/06/07/08, Tier1, holdouts, mechanisms, NCU, NVBit, SASS and Accel-Sim are excluded.

The point order is MP01, MP02, MP03, MP05. Each point has a nontransferable reservation (120, 120, 120, 180 seconds; 540 seconds total GPU-active). A prospective 109 runner must acquire/release the existing lock, verify source/input/model SHAs and available remaining point time before initialization; count GPU-active loading, correctness, warmup, native and observed capture against its point. No sample-count expansion after observing variance or outcome. A point that cannot fit its reservation stops; unused time cannot be lent to another.

For each point, execute Graph ON with instrumentation OFF and Graph OFF with instrumentation OFF as separate native arms. Each mode receives one warmup and exactly three measured requests. The campaign design did not freeze a stricter compatible Stage A repetition rule; the AWQ V2 canary's three-per-arm rows qualified its observer and are **not** reused as Tier0 samples. Preserve every measured CUDA-event request duration and use the median of the three as the primary request-level native timing estimator. Host wall may be retained for diagnosis, not substituted. The observed Graph OFF arm uses the accepted semantic observer (BF16 V1, AWQ V2); it receives one warmup and one structural request, with at most one lightweight NSYS `cuda,nvtx` capture. Neither its wall time nor NSYS wall enters native timing. Graph ON is the mature software whole-request control; Graph OFF contributes semantic chronology and native counterpart, not an architecture result in isolation.

Correctness, input token identity, shapes, semantic/operator order, actual backend/kernel and (for MP05) W4 quantization/Marlin identity must hold before timing and at point close. AWQ observed order/shapes and kernel inventory must continue to match accepted V2. The accepted three-per-arm V2 canary is the neutrality authority; one Tier0 observed request cannot recompute that median gate. A changed source/runtime/observer identity invalidates the accepted qualification and stops the point. No extra samples or tolerance change are allowed.

## Estimators and boundaries

- DQ1: report Graph ON native request median as the natural whole-request control. Correlate Graph OFF observed candidate CUDA intervals with the same Graph OFF observed parent; compute `f = |union(candidate)| / |union(parent)|` and `S_zero_screen = 1/(1-f)`. This is an optimistic **Graph-OFF CUDA-parent screening** number. It is not by itself the candidate's Graph-ON whole-run contribution. A disjoint/overlapping module duration sum is never a legal parent wall union.
- DQ2: report native request medians separately for MP02 B1 and MP03 B4, with effective M, shapes and actual backend/kernel. A B4/B1 time ratio is not utilization. MP05 is a cross-representation strong-baseline control, not a strict single-variable precision A/B.
- DQ3: output only `MEMORY_SERVICE_CANDIDATE` or `NO_MEMORY_SERVICE_CANDIDATE` at Tier0, requiring material native timing exposure plus a kernel/source bytes/layout clue. No L1/L2/DRAM bottleneck attribution without the separately gated Tier1 evidence.
- DQ4a: report dense producer-consumer order, boundary gaps and parent fraction; chronology alone does not establish a cache handoff benefit or materialization mechanism.

The 85% Graph-control rule has one prospectively named denominator. For the frozen DQ2 B1/B4 ladder, take each mode's three-sample native median and normalize by the **actual 32 and 128 generated tokens** respectively: `G_OFF = median(MP02,OFF)/32 - median(MP03,OFF)/128`, `G_ON = median(MP02,ON)/32 - median(MP03,ON)/128` (ms per generated token). Only with exact outputs/shapes and `G_OFF > 0` compute `absorption = (G_OFF-G_ON)/G_OFF`; ≥0.85 stops this direction. This is a batch-ladder *throughput-time* contrast, not a local-kernel gap or pure occupancy estimate. MP01, MP05, DQ1, DQ3 and DQ4a lack a prospectively matched pair; mark `GRAPH_CONTROL_GAP_NOT_IDENTIFIABLE` rather than manufacturing the ratio. Graph OFF local interval and Graph ON whole request are never directly subtracted.

Retain the <3% local-weight STOP, <2% zero-cost whole-run incremental-ceiling STOP, and traffic-without-native-exposure STOP. The Graph-OFF `S_zero_screen` may discard an unpromising diagnostic line, but a surviving line does **not** pass the whole-run ceiling gate until a commensurate whole-run fraction is established. Where it is not, write `WHOLE_RUN_CEILING_NOT_IDENTIFIABLE` and do not promote; do not lower 2%. No result of this Tier0 alone is an architecture mechanism claim.

Every raw sample, trace index, interval and decision table specified in `RESULT_SCHEMA.json` must be durably published with raw/review SHA manifests and copyback verification. Stage A produces no holdout output. After the 174 consumer analyzes only Stage A data, a committed `DISCOVERY_FREEZE_RECEIPT.json` and separately reviewed Stage B contract are required before any holdout execution.
