# R101R1 source and closest-work audit

The arithmetic authority is pinned [`tang0389/himuon@af89eda9a0176effed99e1fe19cc1f8a1a2c9588`](https://github.com/tang0389/himuon/tree/af89eda9a0176effed99e1fe19cc1f8a1a2c9588). Exact file SHA256 values are inherited in `R101R1_BASELINE_IDENTITY.json`. HiMuon already batches tiled gradients across parameters, caches plans/buffers, supports optimizer CUDA Graph capture, skips symmetric half-work in XXT/BA, and fuses polynomial/add epilogues. R101R1 changed none of those arithmetic kernels. The D1 wrapper differs only by ordered last-use discard calls, and D2 by a preallocated contiguous A/B arena plus existing CUDA L2 graph-node access-policy attributes; both were exact-output gated.

NVIDIA's [PTX ISA discard specification](https://docs.nvidia.com/cuda/archive/13.0.0/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-discard) defines `discard.global.L2 [ptr], 128` for aligned 128-byte ranges on sm_80+, as a destructive hint whose subsequent reads are indeterminate until overwrite. The [CUDA L2 control guide](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/l2-cache-control.html) exposes persisting set-aside and graph-kernel access-policy windows, but calls persistence preferential retention rather than a guaranteed reservation. R101R1 measured these existing capabilities before considering architecture mechanisms; `R101R1_L2_CAPABILITY_RECEIPT.json` closes PTX/SASS/runtime and device capacity.

The accepted Round12 closest-work authority is `hrl/awma-chatgpt-literature-notes-v1@002020ca5d1b486c1143c8a64d5ebd9f391d337b`. It pins [Flash-Muon](https://github.com/nil0x9/flash-muon) at `80ac87fb49afc792b84eccb393d051b1ed8eee32`, [fused-muon](https://github.com/StarrickLiu/fused-muon) at `740a4d76253e7277da4fd7cf911bed7bd482b31f`, and [Gram Newton–Schulz](https://github.com/Dao-AILab/gram-newton-schulz) at `e45d0aca7083cb275c9a303220c05c4abecd9187`. Flash-Muon optimizes symmetric products but retains global intermediates; fused-muon uses SYRK and a fused epilogue but still has global A/B workspace and X/X_new ping-pong, with multi-step pipeline listed as future work. Gram NS changes algebra for rectangular inputs and selects standard NS for square tiles like R101 L512. These are relevant strong software alternatives, not R101R1-tested exact batched 512×512 retained-intermediate substitutes. Hopper DSMEM/clusters are not an SM89 capability. No novelty is claimed from symmetry, epilogue fusion, discard, persistence, or graph launch itself.
