# R101 scientific decision

**State: `R101_INTERMEDIATE_RETENTION_READY_FOR_ARCH_REVIEW_V1`.** This is a bounded problem-qualification result only. It does not authorize an architecture mechanism, node174, or Accel-Sim.

The exact accepted Qwen2.5-0.5B-Instruct weights and R53 raw prompt authority produced two independent BF16 first-step next-token gradients. A zero-momentum HiMuon first step gave `G=1.95×grad`; no model parameter was updated. Discovery is layer0 q/up/down; holdout is layer12 q/up/down. Input, model, source, environment, tensor, and tile hashes are closed in the receipts and node164 raw index.

Same-map S128 control: 581 identical BF16 tiles, identical five-step polynomial, author F128 fused vs author compiled K128 three-kernel. Finite and FP32 cosine were recorded; F128/K128 satisfy the author's predeclared `rtol=atol=1e-2` comparison. Seven formal GPU-event repetitions give eager medians 0.5544 vs 0.6502 ms, a 14.73% improvement (>5%, effect/noise 5.06×). With legal CUDA Graph replay, medians are 0.4934 vs 0.6235 ms, a 20.86% improvement (effect/noise 50.26×), so ordinary repeated-call host launch overhead is not sufficient to explain the response. NSYS verified one fused kernel versus five each of XXT/BA/BMM-add, including graph-node tracing.

For separate, non-equivalent L256/L512 maps, the author path remains 15 NS kernels under full selected-parameter optimizer CUDA Graph replay. Complete layer0 selected optimizer medians are 1.2032 ms (L256) and 1.8214 ms (L512). Profiled NS-family kernel-duration fractions are 65.8% and 75.6% of the summed kernel durations respectively; these are descriptive profiler observations, not primary event timing or a predicted removable fraction. Source accounting shows reused X/C ping-pong plus A/B storage. For L512, A/B/C logical writes total 346.03 MB across five iterations; NCU reports 344.72 MB NS-family DRAM writes and 3556.57 MB L2 requested bytes on the frozen discovery input. L2 requested bytes are not HBM bytes, NCU replay time is not primary, and the source-derived write count is not labeled measured HBM.

Independent layer12 holdout, frozen before execution, preserves S128 response: eager F128/K128 0.5572/0.6695 ms (16.77%, effect/noise 7.05×), graph 0.4991/0.6245 ms (20.09%, effect/noise 14.85×). The same L512 map costs 1.6662 ms in standalone graph replay; the author's full layer12 selected optimizer graph costs 2.0132 ms. Their ratio 82.76% is descriptive and **not** a realizable speedup estimate. Holdout numerical gate and first-state author graph/eager update comparison passed.

The evidence localizes material *GPU-side intermediate materialization* in the current author three-kernel path: source-proven per-iteration A/B/C global outputs, NSYS 15-kernel recurrence under CUDA Graph, NCU DRAM writes near the source logical-write count, and a same-map on-chip fused response that persists with graph replay. It does **not** isolate the marginal DRAM contribution from compute scheduling, occupancy, or instruction differences between F128 and K128, nor does it prove a realizable large-tile fused speedup. These are mandatory questions for a later architecture review. Closest software approaches are acknowledged in the source audit.

Excluded from scientific medians: pre-path-qualified timing, NSYS graph-granularity attempt, the zero-kernel NCU selector attempt, and the unused CPU-only holdout L256 tile build. All are retained as raw provenance, not silently discarded. No new tile size, NS step count, coefficients, alternate model, or holdout tuning was introduced.
