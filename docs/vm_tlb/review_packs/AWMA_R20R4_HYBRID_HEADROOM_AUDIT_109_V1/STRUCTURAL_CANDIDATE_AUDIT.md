# Accepted fixed-304 candidate source audit (CPU-only)

Source authority: accepted R20R3P1 candidate `solver.py` SHA256 `868cf9b0420d61656b3698ba7ddc93b6aa3d6a031d825c939a9868adf916a8e3`; the accepted source diff is unchanged. This audit does not run S1 or profile it.

The opt-in `_r20r3p1_build_active_ids` (`solver.py:50–64`) runs one device thread, scans all 1024 `ctx.done` flags in ascending logical-world order and writes the active-ID list/count. The candidate launches 304 worker coordinates for both sparse incremental H and blocked Cholesky. Their kernel bodies (`:2188–2189`, `:3036–3037`) use `for active_slot in range(worker, active_count_in[0], worker_count)` with `worker_count=304`.

Consequently, when `active_count>304`, at least some worker coordinates execute multiple worlds sequentially. For example, the accepted t128 post-run active counts are 1024, 983, 876, 673, 404 before falling to 180; at 1024, each worker handles roughly three or four world IDs. When `active_count<=304`, no worker needs a second world from that loop. This source fact is classified **`STRUCTURAL_EARLY_PHASE_SERIALIZATION_PRESENT`**. It is not evidence that serialization alone caused the measured 66.6% complete-solver slowdown: S1 was not profiled, and list construction, changed launch scheduling, worker-loop overhead and other effects remain unseparated.

The original solver `_solve` allocates a one-element device `nsolving` initialized to `d.nworld` (`solver.py:3975` in pinned source; shifted near `:4147` in candidate source) and passes it to the device conditional `capture_while` body. `_solver_iteration` receives it, runs line-search, constraint update and `_update_gradient_incremental`, then calls `_solve_done` which atomically decrements `nsolving` for newly completed worlds. Thus at selected-stage entry `nsolving[0]` represents the **current online** active count and has not yet been changed by this iteration's done update. It can potentially gate a future early/late path without future niter or a host read. This is a source-level design fact, not a tested hybrid implementation.
