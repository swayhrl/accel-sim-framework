- `_update_gradient_zero_grad_dot` (`solver.py:2209–2253`): for active worlds, either rescales the stable-ray gradient/decrement using `grad_scale` and the current line-search alpha, or resets `grad_dot=0`, `newton_decrement=0`, `grad_scale=1`. It may set `search_unchanged` for a completed world, but returns before modifying that world's three residual values.
- `_update_gradient_grad` (`:2258–2288`) computes the world-local gradient from `efc.Ma - qfrc_smooth - qfrc_constraint` and accumulates `grad_dot`, but returns for `ctx.done` worlds. `_update_gradient_incremental` (`:3492–3565`) then updates the same world's H/factor/search and Newton decrement; unchanged-state fast paths are still within the same solver iteration. Completed worlds do not receive another active-world residual update.
- `_solver_iteration` (`:3768–3855`) runs line search, counter reset, constraint update, incremental gradient, and only then `_solve_done`. Thus the latter reads the residuals produced for this active iteration.
- Newton `_solve_done` (`:3685–3738`) returns immediately if already done. Otherwise it increments `solver_niter`, reads alpha and rescaled improvement, gradient=`sqrt(ctx.grad_dot)/(meaninertia*nv)`, model improvement=`0.5*ctx.newton_decrement/(meaninertia*nv)`, and checks exactly: `alpha==0` OR (`improvement>0` AND `improvement<tolerance`) OR `gradient<tolerance` OR `model_improvement<tolerance`. If this predicate is true or `solver_niter==iterations`, it sets `ctx.done`, decrements the global active count, and (only when the predicate is false at the iteration limit) ORs `ITERATIONS` into `d.overflow`.
- `_solve` (`:3939–4010`) repeats `_solver_iteration` under the device conditional graph until the active count is zero. Its post-loop `_qfrc_constraint_from_grad` reads `ctx.grad`/`ctx.grad_scale` to recover a public force output; it does **not** write `ctx.alpha`, `ctx.improvement`, `ctx.grad_dot`, or `ctx.newton_decrement`. The physical integrator consumes Data outputs, not these SolverContext residual arrays as independent public physical state.

Therefore graph-end `ctx.alpha/improvement/grad_dot/newton_decrement` for each completed world are the values seen by that world's last active `_solve_done`, absent a source writer outside these paths. A separate diagnostic kernel can recompute the four Boolean predicates after complete solver replay using the same Warp float32 operations; it need not insert an observer into the timed solver. `ctx.done` at graph end alone does **not** prove mathematical convergence: a world can be limit-stopped when the source predicate is false. An inherited `ITERATIONS` bit in the entry is not, by itself, evidence that this solve newly hit the limit; entry and exit bitmasks must be distinguished.
