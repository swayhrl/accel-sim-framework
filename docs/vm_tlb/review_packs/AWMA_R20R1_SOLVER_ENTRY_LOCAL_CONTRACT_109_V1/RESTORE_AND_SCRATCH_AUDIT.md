# Data restoration, SolverContext and source-local scratch audit

Input restoration was stronger than qpos/qvel: each solver entrance stores 138 nonempty nested MuJoCo Warp Data arrays in original order, with per-field raw byte SHA256. Every B0 repeat wrote the full snapshot back to the existing captured Data pointers and checked all 138 hashes before graph replay; 266 Model-array hashes matched the in-situ source Model. This preserves actual pooled contact/EFC IDs, effective parameters, sparse J/rowadr/rownnz/colind and solver input values. No CPU canonicalization fed the solver; sorted/canonical analyses are not a replay path.

The pinned `solver.py::_create_solver_context` allocates one context per graph capture. This path yielded 20 nonempty graph-local array fields. Source defaults include `wp.zeros` for `grad`/`ls_exhausted` and `wp.empty` for workspaces; `_solve` creates `nsolving=wp.full(nworld)` within the captured solve, `_solve_init_efc` resets `done`/solver_niter, and the incremental Newton path clears `search_unchanged` and per-iteration change counters. The actual `wp.capture_while` CUDA conditional branch was preserved. The full B0 function also pays `_solve_init_dof`, gradient/H initialization, every required conditional iteration and `_qfrc_constraint_from_grad` recovery. Capturing only the loop would omit legal work.

Do **not** infer that every graph-local `wp.empty` byte is initialized from the Data restore. An early audit wrapper attempted to call `.numpy()` on capture-owned scratch before its graph replay and exited before producing B0 samples; it was corrected to inspect metadata only, leaving source solver behavior unchanged. A later bounded audit read context residuals **after** replay: source `ctx.done` was true, the fixed t128 `solver_niter`/overflow signatures matched, and the normalized source identity `qfrc_constraint = efc.Ma - qfrc_smooth - ctx.grad_scale*ctx.grad` held within about `6.11e-7` across three B0 replays. This supports a local output check but is not proof that every hidden scratch dependency has been closed.

In the R2 continuous lineage, t128/t136/t144 passed the pre-frozen floating and exact-signature rules. At t152, the *same 138-field input*, Model and captured complete solver produced an extra `LS_ITERATIONS` bit for world 413 in one of five B0 runs. Entry overflow for that world was zero; nefc=46 and solver_niter=8 remained unchanged, with qacc world max difference `9.16e-5`. Thus this is a new line-search stop/limit signature difference, not inherited sticky overflow and not contact-buffer capacity loss. The exact source—order-sensitive arithmetic inside the solver versus an unclosed graph-local scratch dependence—remains `UNKNOWN`. Neither an added clear nor a modified solver was silently introduced to force deterministic output. The hard G1/G2 gate fails on this source behavior, regardless of the small floating error.
