# R19F1 frozen numerical and same-consumer contract

Parent `63de02aa82587680baca665d09101dc8c67222a2` and its **failed** B0-versus-FP8 allclose result remain unchanged. R19F1 is a separately labeled decomposition, not a reinterpretation of V1.

Scientific input: parent payload SHA256 `5ac9e6eb35ec2676926481d563628b80d528dac3dbdbe87bece26d21f4c54b48`, real Qwen2.5 layer0 `mlp.up_proj` BF16 input `[1,256,896]` and BF16 weight `[4864,896]`. Exact TE v2.19.0 source commit `5e52befd5262c06289106338c308079d6adb391f`, parent isolated environment, `Float8CurrentScaling(E4M3)` without power-of-two scales, SM89.

The primary matched-reference dtype is **FP32** `torch.nn.functional.linear`, with `torch.backends.cuda.matmul.allow_tf32=False`, applied to the *actual TE-quantized and then TE-dequantized* input and cached weight. This path has no FP8 compute. B0 is BF16 ordinary `F.linear` on the original input/weight. F0 is `te.Linear` on a public `Float8Tensor` whose bits and inverse scale must first match exactly the internal input representation captured from a normal online TE call, with the identical steady-state FP8 weight workspace. The internal `Float8TensorStorage` itself is not a public `te.Linear` input.

For audit only, one un-timed normal online call temporarily wraps TE's Python `Float8CurrentScalingQuantizer.quantize_impl` method; the wrapper returns the unmodified quantized object and retains the object for hashing. It is restored before F0/D0 calls. It does not change the consumer or form a timed arm. A separate public `te.Float8CurrentScalingQuantizer` call, configured to TE's source defaults, must yield identical FP8 bytes and inverse scale before that representation may be considered for D0. Both cached weight bits/scale and underlying device pointer must remain unchanged. Online/F0 and D0/F0 outputs must be bitwise identical before paired timing. If these exact identity checks fail, D0 is not qualified.

The sole numerical admission gate is F0 versus R0: all finite and `torch.allclose(F0.float(), R0.float(), atol=0.0675, rtol=0.125)`. TE v2.19.0 `tests/pytorch/utils.py::quantization_tols("fp8_current_scaling")` supplies these E4M3 tolerance values; the TE quantized-GEMM tests create reference tensors from represented values. This is an engineering gate, not a model accuracy claim. Record max/mean/RMSE/cosine/percentiles and SHA256s for B0/R0/F0 plus the exact quantized payloads/scales. B0 versus R0 is a separate representation-distortion measurement, **not** a pass/fail replacement for the V1 B0-versus-FP8 gate.

Consumer identity must be established from TE source dispatch and a runtime kernel/timeline witness (at most one NSYS capture). Float8Tensor metadata alone is insufficient. A1/D0 timing is forbidden until numeric, native consumer and D0 exact-safe gates all pass. If admitted, freeze 3 paired groups, each 2 warmups and 5 formal samples per arm, alternating order. Primary region is real input state at the arm boundary through synchronized FP8 output commitment: A1 creates current-scaling input representation online, D0 starts with the *same* public-API representation already ready; both use the same TE Linear consumer and cached weight. First-call/JIT is excluded and recorded separately. At most one timeline-selected NCU target, only if needed. No different recipe/model/shape, custom GEMM or FP4 claim.

Formal timing records both host-wall completion and CUDA-event elapsed time for every sample, without profiler instrumentation. The investment screen is a >=5% reduction in the complete **host-wall** measured region from A1 to D0, with the same reduction sign in each of the three paired-group medians and a combined median gap exceeding 3 times the larger arm MAD; CUDA-event and the single NSYS decomposition must support attribution to representation preparation rather than a changed consumer. A mixed wall/GPU or unstable result is review-only, not a positive residual. This criterion is frozen before timing and is not an application-level speedup claim.
