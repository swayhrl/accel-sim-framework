# C16 strong-baseline matrix V1

This is a comparison-design contract, not an authorization to build or run new full timing baselines. `MUST-HAVE` means the capability must be answered before a mechanism contribution is submitted; it does not require a long run during this prep goal. Freeze the same L2 physical capacity, admitted trace, workload, source/config identity and measurement scope for any later comparison. Native CUDA persistence remains an external accepted observation, not a cycle-matched simulator baseline.

The comparison is a 2×2 capability grid: all target vs stable subset, crossed with simple priority vs elastic hard quota. `PRIORITY_STABLE` is not an M1F duplicate: without the hard quota it may use more protected lines in a local subpartition even if the selected global footprint fits B16. Physical capacity, actual protection, resident+pending occupancy, ordinary displacement, local cycles and the 1565-kernel window must be reported separately.

## Future adaptation rules

- `PRIORITY_ALL` and `PRIORITY_STABLE` use a precise set-local, legal-victim rule and never claim to emulate undocumented RTX 4080/R580 behavior. MICRO 2025's reliable mixed-priority retention counts were measured under other GPU/driver conditions; they are not a C16 quota.
- DRRIP must distinguish a true same-sector reuse hit from first access to another sector of a large line, MSHR merge, retry or reservation. Its published RRPV/dueling state is the baseline; per-layer controllers would be a new C16 variant.
- SHiP-SW-style gets equal software-region information. Original SHiP learns reuse of the **insertion** signature, not the time until the next access. Any hard-quota hybrid is labeled separately; fixed-sequence DRAM traffic from AutoScratch is not native or simulator timing.
- All policies retain the baseline L2 capacity, associativity, transaction semantics, legal victims, request conservation and liveness. Future implementation must specify update events, metadata overhead, initialization, hash collisions and ordinary/writeback treatment before a comparison is admitted.
- A nonstable event-fractional control becomes `CLAIM-DEPENDENT` only if C3 specifically credits stable eligibility. Its event must be defined before execution; it is not called NVIDIA's actual hitRatio implementation.

## Related or conditional work, not automatic long runs

`DIP/BIP` informs insertion and scan tolerance; DRRIP currently covers the generic anti-thrash objection. `PIPP` and `Vantage` address allocation/borrowing but use different control contracts; full adaptation is claim-dependent. `Talus` is a stable subset/capacity-cliff neighbor, not reproduced by `PRIORITY_STABLE`. `Whirlpool`, `EVA` and MLP-aware replacement inform information value, opportunity cost and unequal miss cost; they do not establish a C16 causal offset or mandate three extra mechanisms. CPU cache-resident LLM work is a system problem neighbor, not a same-platform replacement baseline. These distinctions follow LR03–LR05 at literature commit `350e4a0d364d65812f379ebc69412696e2a4d82a`.
