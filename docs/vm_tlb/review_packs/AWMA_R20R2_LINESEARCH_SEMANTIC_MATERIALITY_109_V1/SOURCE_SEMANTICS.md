# R20R2 pinned-source semantics audit (before new GPU work)

Source: `mujoco_warp@3d537ea6b45eb88ce2ebeb97c57b8e9a220eb1c5`, `mujoco_warp/_src/solver.py` blob `090061796792f4d11408eaa69b4ef3c44465c705`. The source checkout is read-only. This audit concerns only the frozen t152/world413 solver entry.

`OverflowType.LS_ITERATIONS = 1 << 10` (`types.py:185`). In `solver.py:1207-1408`, the iterative line search first tests `initial_converged = abs(lo_in.derivative) < gtol_accept && lo_in.cost < 0`. Otherwise it tries up to the unchanged configured 20 inner iterations. In each, `conv_lo/hi/mid` test negative cost and derivative magnitude below `gtol_accept`; a separate `ls_done` may also arise from no bracket swap or a signed derivative below `gtol`. `gtol_accept = max(gtol, 8*float32_eps*q1_abs)`; the incremental stale-ray `noise_floor` is separately used for `ctx.ls_exhausted`. If no `ls_done` occurs before the bound, `ls_converged` remains false.

The selected `alpha` is applied to `qacc` and `efc.Ma`, then `ctx.Jaref`; thread 0 then stores `ctx.improvement`, `ctx.alpha`, and (incremental mode) `ctx.ls_exhausted`, and only after those writes ORs `LS_ITERATIONS` into `d.overflow` when `!ls_converged` (`solver.py:1384-1408`). Thus the flag records the line-search limit, not a veto of the already-selected step.

The fixed-source search found no `overflow_in` reader in `mujoco_warp/_src`, and no read of `d.overflow` in solver or integrator arithmetic. The source uses the array as an output/status accumulator: line-search and outer-iteration bits in `solver.py`; capacity/error/status ORs in collision, sensor, island and `forward.py`; reset-to-zero in `io.py`. `forward.py:_next_time` receives it as an output and ORs capacity bits; its numeric inputs do not include it. `solver.py:_solve_done` tests `ctx.alpha`, `ctx.improvement`, gradient and model decrement and writes `ITERATIONS` only on the outer limit; it does not read the LS bit. The `warn_overflow` mask controls optional printing, not the bit write or numerical control.

The official G1 descriptor (`benchmarks/unitree_g1/__init__.py:16,26,41`) masks `ITERATIONS|LS_ITERATIONS` from `warn_overflow`. This is evidence that warnings are silenced in the benchmark, **not** proof that flag changes are scientifically immaterial. Whether the set/clear outcomes differ in chosen alpha, solver trajectory, or final outputs is the bounded observer question; the R20R1 exact stop-signature failure remains frozen.
