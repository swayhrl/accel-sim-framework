# Why these observations and not another mechanism search

The frozen C16 V2 state has no qualified architecture problem. This design asks four questions about **natural inference execution** before selecting a local optimization. It starts with coverage axes and ends with a small 8-point plan; it is not a Cartesian product or a broad NCU campaign. `NO_NEW_ARCHITECTURAL_PHENOMENON_FOUND` is a valid future outcome.

The selected workload contrast is purposeful: one dense BF16 model for prefill/decode and a B1→B4→B16 decode ladder; its official W4/AWQ sibling for a representation *control*; one existing OLMoE family for natural MoE chronology; a different small Granite MoE family reserved as holdout; and one sealed long-context dense holdout. The Qwen BF16/W4 pair is proposed because official model cards exist for both [BF16](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct) and [AWQ](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-AWQ), not because a file is already downloaded. [OLMoE's model card](https://huggingface.co/allenai/OLMoE-1B-7B-0125-Instruct) and [Granite's model card](https://huggingface.co/ibm-granite/granite-3.1-1b-a400m-instruct) establish two public model families; the latter is proposed as an independent MoE-family holdout. Public [vLLM model-family listings](https://docs.vllm.ai/en/latest/models/supported_models/) are **not** evidence that a particular pinned build, quantized path or fused expert kernel works correctly on 109/SM89. Every revision/backend/VRAM and numerical identity remains `TO_BE_QUALIFIED`. No asset is downloaded here.

The short natural text source is proposed [WikiText-103 raw](https://huggingface.co/datasets/Salesforce/wikitext), with disjoint train prompt IDs frozen before measurement. The long sealed source is proposed [PG-19 validation books](https://github.com/google-deepmind/pg19); book ID, excerpt and UTF-8 SHA must be frozen before any performance result. These are source candidates, not acquired campaign inputs. Each model tokenizes the same text bytes independently, and actual effective token counts are recorded. No prompt is chosen after examining a metric.

The first gate is Tier0 natural whole-request/phase timing, correctness, backend/kernel inventory and chronology. A local kernel is never promoted without its natural parent wall-union weight and `S_zero=1/(1-f)` Amdahl-style **optimistic ceiling**. Tier1 is limited to at most three weighted points and a question-specific selected counter set. Tier2 address/tile/page capture is not default and needs a second project review. A VA-page proxy does not make translation timing observable. [Nsight Systems/NVTX](https://docs.nvidia.com/nsight-systems/UserGuide/) supports chronology; [Nsight Compute's profiling guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/) warns that metric selection and replay can perturb collection, so native timing and NCU profile durations remain separate.

The historical M1F, grouped Split-K, dequant-result cache, FFN materialization, plain concurrency/merge, generic Ada W4 and cache-policy directions remain closed. DeepSeek exact rereading is archived as same-warp software-kernel work assignment, not a point in this design. New data would need to establish a new phenomenon and residual after the strongest semantically legal software path; it does not inherit a C16 promotion claim.

Design status is review-ready, **not execution-ready**. If the pinned backend, correctness, source text, memory capacity or legal observable fails qualification, the affected point is dropped; no weak fallback is substituted to preserve coverage. If holdout loss destroys a primary question's independent check, that question cannot promote. If enough points fall away, the project must revise the design before any 109 run.
