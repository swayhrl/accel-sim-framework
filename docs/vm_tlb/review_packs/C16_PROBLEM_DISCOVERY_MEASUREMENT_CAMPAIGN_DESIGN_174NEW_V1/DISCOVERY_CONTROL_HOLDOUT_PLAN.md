# Pre-frozen split and leakage controls

## Sets

- `DISCOVERY_SET`: MP01 dense prefill, MP02 dense B1 decode, MP03 dense B4 transition, MP06 OLMoE natural decode. These select *candidate phenomena*, but never mechanisms.
- `CONTROL_SET`: MP05 same-family Qwen AWQ B1 representation control. It is **not** a strict same-kernel precision A/B if backend, layout or quantization semantics differ; label it `CROSS_RUNTIME_STRONG_BASELINE` whenever runtime differs. MP01 also controls phase for MP02, without claiming all other conditions match.
- `HOLDOUT_SET`: MP04 dense B16 batch/shape; MP07 Granite second MoE family; MP08 dense long-context natural request. Their identities are frozen in the design before discovery data. Their timing/counter rows stay sealed until the discovery question, direction, estimator, threshold and STOP rule are frozen in a signed analysis receipt. Tier0 can execute later in the same 20-minute reservation; analysts may not view the sealed output before freeze.

Future preflight must pin exact checkpoint revisions, runtime build/kernel identities, model-specific tokenizer revisions, sample/seed IDs, source text UTF-8 SHA, disjoint WikiText train A/B prompt IDs, PG-19 validation book/excerpt ID, and D0-D31 generation/warmup protocol before native measurements. MP04's B16 batch contains the MP02 anchor prompt plus 15 sealed B prompts, so the anchor request is matched while the *batch shape* remains unseen during rule selection; analysis must account for co-batched context. The B1→B4→B16 sequence is a *supply ladder*, not a claim that a backend threshold lies at B4. If a source audit reveals an actual threshold, a design revision—not post-hoc scanning—must pre-register any near-threshold point.

The heldout Granite family tests DQ1/DQ2/DQ4 cross-family transfer even though old OLMoE/DeepSeek selected-shard analyses existed; prior C16 traces are not rebranded as new holdouts. MP04 tests DQ2 at a batch not used to choose the low-M rule. MP08 tests DQ1/DQ3/DQ4 at a context and input source not used to choose discovery thresholds. A holdout must reproduce the **pre-frozen direction and minimum material effect** under its own legal parent wall weight; its role cannot be changed after results. If an asset/backend cannot pass strong-software and correctness qualification, record `HOLDOUT_UNAVAILABLE`, drop promotion for the dependent question and seek project review rather than substitute a convenient observed point.

Every comparison freezes tokens/outputs or predeclared tolerance, shapes, operator order, kernel identity where required, quantization qweight/qzeros/scales/group and packing, natural prompt bytes, warmup, graph/replay semantics, stream dependencies and exact timing endpoints. No performance result is admitted before correctness. BF16 versus AWQ is representation and potentially runtime contrast, never a one-variable causal estimate. Native CUDA-event module time, NSYS wall union and NCU profile kernel duration are separate measurement systems; no direct cross-system subtraction.
