# Proposed future capture ladder — no stage is authorized here

0. **CPU-only readiness review.** Pin source revisions, model weights/tokenizer, WikiText/PG-19 excerpts and SHA, runtime/backend/build, SM89 capacity, exact quantization/FP8 semantics, operator mapping, numerical tolerances and permitted tools. Verify candidate backend is a mature fused/shipping path, not eager/reference. Check each model's CUDA Graph/attention/MoE support from pinned source. If any point fails, mark `RUNTIME_UNQUALIFIED` or `ASSET_MISSING` and drop it; no substitute chosen from observed results. Project separately authorizes a precise 109 contract before proceeding.
1. **Tier0 identity and wall timing (≤20 minutes proposed).** Bounded canary for correctness and kernel inventory before timed requests. Record model/runtime/revision, natural input identity, token/output hashes, shapes, order, selected routing sequence, native request/phase timing and NSYS/NVTX correlated kernel intervals/gaps. Compute each local family `f` against its natural parent request wall union and the optimistic `S_zero=1/(1-f)`. Mark overlapping or unassignable intervals explicitly; never sum module durations into legal wall time. No NCU, NVBit or SASS by default.
2. **Freeze discovery; open controls/holdout.** Write signed receipt listing DQ ID, phenomenon, denominator, estimator, threshold, strong baseline, oracle status, STOP and exact holdout before seeing MP04/07/08 results. A negative or unavailable holdout blocks promotion. If the legitimate output is `NO_NEW_ARCHITECTURAL_PHENOMENON_FOUND`, close without heavier tools.
3. **Tier1 selected attribution (≤3 points, ≤30 minutes proposed).** For each admitted question, choose only metrics needed to distinguish CTA/wave supply, tile fill, L1/TEX/L2/DRAM service or specific stalls. Pin exact NCU metric names, replay/cache-control behavior and overhead on the 109 installation before use. Keep native timing separate from profile time. Reject traffic-only claims without timing exposure. Translation remains `UNKNOWN` unless a direct Ada TLB/PTW/blocked-time observable is proven valid.
4. **Tier2 question-bound chronology (separate review required).** At most 1–2 future points; only exact object/operand/warp or producer-consumer/page sequence needed for a surviving oracle. Require source-range identity, same-process chronology, capacity bound, correctness and an independent holdout. Existing C16 selected static shards cannot substitute. This design issues no NVBit/SASS/NCU capture instruction.
5. **Tier3 simulator/mechanism.** Explicitly outside DESIGN V1. Consider only after a material native phenomenon, legal whole-run oracle, strongest semantically matched software baseline and heldout replication all pass a new project review.

Any correctness mismatch, weak backend fallback, over-budget step, unqualified observable, insufficient whole-run ceiling, disappearance under software control, or failed holdout is a **STOP**, not an invitation to parameter-sweep a closed mechanism.
