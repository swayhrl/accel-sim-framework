# Exactly three prescribed implementation classes

| Class | Source changes required | Work/reuse/process consequence | Verdict under this Goal |
| --- | --- | --- | --- |
| P1 sampler-side first-layer fusion | Load/execute `SAGEConv` and first-layer weights in sampler, publish `[N1,256]` output through a new IPC handle, keep graph/labels and trainer's remaining layer | Sampler is a compiled C++ `sampling_server`, while DDP model and Adam live in the Python trainer. Training needs first-layer weight gradients and autograd context to cross back into sampler, or a second execution of the first layer in trainer. The first choice adds PyTorch/DGL embedding plus remote backward/optimizer protocol; the second restores original feature materialization/work. Original raw-feature IPC is replaced by first-layer-output IPC and new synchronization. | **Reject**: nonlocal model/gradient ownership and changed IPC topology prevent a bounded, boundary-only matched two-arm contrast. An inference-only shortcut changes the workload. |
| P2 finite tile/ring of dense raw features | Replace both full `[N2,602]` IPC feature buffers with bounded tile slots and per-tile ready/consumed handshakes; split trainer first-layer `fc_neigh` and destination `fc_self` over tiles, assemble full `Z[N2,256]` then use unchanged DGL g-SpMM | One decode per unique row and one `Z` per row can be preserved. But baseline `SAGEConv` accepts full `X` and launches whole-matrix linears. Tiling adds kernel launches, changes GEMM shapes/algorithm and autograd graph, and introduces per-tile cross-process waits. With only accepted B0 and D1, a loss or gain cannot isolate removal of the raw dense buffer from these changes. Leaving `X` full preserves semantics but does not test the boundary. | **Reject for causal diagnostic**: closest to a possible implementation, yet not a single-boundary intervention or interpretable negative falsification without an additional matched tiled-linear control, which is outside the frozen two-arm scope. |
| P3 decode inside a custom first-layer kernel | Replace DGL/PyTorch `fc_neigh`/`fc_self` data path with an IBP-aware kernel, handle GPU-cache hits and pinned-host misses, materialize/reuse `Z` by unique row, retain DGL mean and write a custom autograd backward | Per-edge decode duplicates work unless a full unique-row reuse structure is retained. A custom GEMM changes floating-point dot-product order and needs a matching backward for trainable first-layer weights. Reusing baseline DGL/PyTorch forward/backward after custom decode recreates raw dense `X`. GPU/PCIe scheduling and launch structure also change. | **Reject**: largest semantic and code change; no source-only proof of matched first-layer output/gradient or a bounded cost model. |

No fourth candidate is introduced. The already commented-out `cuda_get_next` `from_blob` path is a source fact about a **second** dense copy; it is not a P1/P2/P3 design and would not remove the sampler's full dense buffer.
