# R20R5 pinned conditional-source audit (before any R20R5 GPU work)

The scientific source is `mujoco_warp@3d537ea6b45eb88ce2ebeb97c57b8e9a220eb1c5`, `solver.py` blob `090061796792f4d11408eaa69b4ef3c44465c705`; the accepted P1 candidate overlay is SHA256 `868cf9b0420d61656b3698ba7ddc93b6aa3d6a031d825c939a9868adf916a8e3`. The installed isolated environment has Warp 1.15.0 and CUDA conditional-graph support was already used by the accepted B0 solver.

Installed Warp 1.15 source (`warp/_src/context.py:capture_if`) exposes `wp.capture_if(condition: one-element wp.int32 array, on_true, on_false)`, with both callback branches, and `wp.capture_while(condition: one-element wp.int32 array, while_body)`. The pinned MuJoCo Warp `collision_driver.py:903` already uses `wp.capture_if(cond, on_true=_launch)` in its captured graph path. The pinned solver uses `wp.capture_while(nsolving, while_body=_solver_iteration, ...)` (`solver.py:3994`). API presence alone does **not** prove a nested if inside this while body is executable; G1 separately tests that exact composition.

The solver creates `nsolving=wp.full((1,), d.nworld, dtype=int)` before the while capture (`solver.py:3975`) and passes that same device array into `_solver_iteration` (`:3768–3855`). `_solve_done` executes after line search, constraint update and `_update_gradient_incremental`, and atomically decrements `nsolving[0]` once for each world newly marked done (`:3685–3737`). Thus at the selected gradient-stage entry it is the **current**, not future, count of worlds not done. The candidate patch currently builds active IDs at `_update_gradient_incremental` entry; the sole authorized hybrid will instead use a device predicate derived from `nsolving[0]` to choose baseline for `>304` or worklist for `<=304`. No host per-iteration count/branch is permitted.
