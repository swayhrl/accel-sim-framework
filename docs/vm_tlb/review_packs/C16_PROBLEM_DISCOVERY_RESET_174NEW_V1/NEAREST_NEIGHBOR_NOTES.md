# Nearest neighbors at the experiment-group level

The primary-source experiment cells below come from the C16 LR12 `(source_id, group_id)` audit at literature commit `39c9a989...`; author artifacts were **not run**. They bound novelty and experiment design, not C16 performance. Paper platform, precision, baseline and metric remain attached to each claim.

| Experiment group | What the authors actually established | What remains different or missing for C16 |
|---|---|---|
| [Bullet §4/Fig14](https://arxiv.org/html/2504.19516), concurrent prefill/decode under SGLang/MPS | Naive overlap contends; partition and scheduler jointly matter for SLO/throughput. | C16's same-resource gate/up overlap was already negative. A new serving claim needs an accepted arrival/SLO trace and stronger co-scheduling baseline; merely adding streams is crowded. |
| [NanoFlow §6/Fig7](https://www.usenix.org/system/files/osdi25-zhu-kan.pdf), TP8 A100 serving | Nano-batch compute/memory/network overlap raises throughput over strong serving software; theoretical optimum not reached in every case. | Multi-GPU FP16 serving is not single-RTX4080 AWQ FFN. It blocks generic “intra-device overlap” novelty without granting C16 headroom. |
| [MPK §6.2–6.3/Fig9](https://www.usenix.org/system/files/osdi26-cheng.pdf), offline BF16 decode | Mega-kernel dispatch has reported benefit over vLLM/SGLang for some batch1–16 cases, with scheduler-SM and offline-arrival tradeoffs. | The C16 strong Mode A already uses compile+Graph; no accepted residual above it. Generic dispatch elimination is not a fresh C16 problem. |
| [Kitsune §6/LL-TOK](https://arxiv.org/html/2502.18403v1), spatial dataflow | High operator fusion coverage can yield only 0.07% traffic reduction in the LL-TOK case; queues/scheduling have costs. | Heterogeneous tile handoff needs a specific C16 pair, full-pair wall oracle and matched fast layouts. Existing work already provides queues as a capability. |
| [VTC §7/Table2](https://www.usenix.org/system/files/osdi26-hu-muyan.pdf), virtual tensors vs strong compiler/TensorRT | Eliminating physical movement can change compute-kernel choice; not every latency cell improves. | “One less transfer” is not a time oracle. The exact C16 producer/consumer layouts and semantically matched strongest compiler path are missing. |
| [ComFuse §VI/Fig7](https://arxiv.org/html/2608.03537v1), complex subgraph microbench | Staged fusion gives shape-dependent gains but finite work/phase imbalance limits small cases against Inductor/TensorRT. | This is a microbench, not C16 whole decode. Plain fusion and staging are not novel; GPU/platform and exact numeric contract must be requalified. |
| [StreamDQ §6.3–6.4](https://arxiv.org/html/2607.08993v1), custom-HBM simulated dequant | Its modeled large-batch wins coexist with a batch≤4 case where tuned AWQ-v2 is slightly faster. | The mechanism is a custom memory die in calibrated simulation, not an RTX4080 result. C16's dequant-cache headroom and local oracle already failed. |
| [TileSight §5.3](https://arxiv.org/html/2607.22432v1), persistent GEMM reuse model | A deep-K case predicted ~82% hit but measured ~43% under SM progress skew. | C16's grouped mapping is an accepted stronger software baseline. Static hit geometry alone cannot show a timing or replacement-policy residual. |
| [PASCAL v1 §3–5](https://arxiv.org/html/2609.10515v1), shared cyclic scan | Policy-independent traffic lower bound constrains replacement savings; overlap can decouple traffic and time. | C16 policy screen found small residual after grouped locality. The paper's regular-scan bound is not a C16 cycle oracle. |
| [Hopper utilization §3–5](https://arxiv.org/abs/2609.12923), H100 BF16 multi-view | SM activity, useful fragment fill, occupancy and stalls disagree at low batch; no single utilization scalar identifies cause. | RTX4080 W4 Marlin requires its own counter semantics; C16 Ada screen already found no second admitted target after two-stream. |
| [BOOST §5](https://arxiv.org/html/2609.13592), GH200 coherent host tier | Most reported throughput gain derives from runnable capacity; isolated bandwidth overlap is much smaller, and prefetch may hurt TPOT. | RTX4080 has no equivalent GH200 coherent host tier. Its benefit cannot be transferred to C16 translation/TLB. |

Literature route verdict: experiment groups reveal useful *rejection tests* (contention, traffic≠time, strong compiler and platform mismatch), but none supplies a missing C16 native phenomenon/headroom. LR12's original `NO_NEW_LITERATURE_DRIVEN_PROBLEM_QUALIFIED` is not overwritten by this reset.
