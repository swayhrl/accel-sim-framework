# Strong software baselines before any new question

The executable baseline is a **measured identity**, not the name of a library family. For Qwen2.5-3B BF16, accepted `9122fac5...` shows vLLM `VLLM_COMPILE`/Inductor, `FlashAttentionImpl`, `UnquantizedLinearMethod`, and Mode A CUDA Graph replay. In the pinned vLLM Qwen2 source (`vllm-project/vllm@ced6857afa0ea7b2e3f0846a62e1394e90f15607`, `vllm/model_executor/models/qwen2.py`), FFN uses `MergedColumnParallelLinear gate_up_proj → SiluAndMul → RowParallelLinear down_proj`; this is not a novel proposed fusion. The same source and `vllm/config/compilation.py` distinguish compilation from CUDA Graph mode. [Pinned Qwen2 source](https://github.com/vllm-project/vllm/blob/ced6857afa0ea7b2e3f0846a62e1394e90f15607/vllm/model_executor/models/qwen2.py), [PyTorch compile contract](https://docs.pytorch.org/docs/stable/generated/torch.compile).

For Qwen AWQ, accepted runtime uses `AutoAWQMarlinLinearMethod` / `MarlinLinearKernel` with same checkpoint bytes and no requantization. Marlin, QUICK and FLUTE already offer materially different low-bit packing, shared/register staging, decode work distribution and kernel selection; they are not automatically interchangeable with the same AWQ format. A BF16 RAW comparison or a predecoded proxy is not a same-format one-variable A/B. The historical E1 RAW input-recovery gate failed, so old RAW/AWQ shape interaction is not promoted into a new performance oracle. [MARLIN](https://arxiv.org/abs/2408.11743), [QUICK](https://arxiv.org/abs/2402.10076), [FLUTE](https://arxiv.org/abs/2407.10960).

For split/GEMM locality, classic grouped/swizzled CTA ordering is the C16 strong baseline: it restored split1 L2 read hit near 95.95% and removed most ROW-locality loss; the accepted residual M64 point favors split1. Stream-K already discusses load balance versus cache reuse, Stream-K++ shape selection, while Triton/CUTLASS expose grouped ordering and split/persistent options. A new split count or ROW fallback does not manufacture a residual. [Triton matmul tutorial](https://triton-lang.org/main/getting-started/tutorials/03-matrix-multiplication.html), [CUTLASS grouped scheduler](https://docs.nvidia.com/cutlass/4.3.3/media/docs/cpp/grouped_scheduler.html).

For FFN/serving, vLLM merged gate/up is mature; the project two-stream gate/up implementation was correctness-passing but slower. NanoFlow, Bullet and Resonator already exercise intra-GPU scheduling/phase overlap, including interference-aware controls. Their serving workloads and hardware do not predict a benefit for the current single-request Qwen FFN. A future serving question must compare against an actually qualified scheduler and real request/SLO distribution. [NanoFlow OSDI25](https://www.usenix.org/system/files/osdi25-zhu-kan.pdf), [Bullet experimental groups](https://arxiv.org/html/2504.19516).

For MoE, fused expert dispatch, expert alignment/placement and route-locality software are substantive neighbors (ReMoE/Oracle-MoE and systems work). E3's eight-expert synthetic hot-set is not a natural-routing, same-semantics oracle; OLMoE's Graph OFF/ON semantic equivalence also failed. For attention/KV and translation, FlashAttention/FlashDecoding-like kernels, KV prefetch and current runtime placement must be considered before claiming a hardware gap; no accepted direct Ada translation blocked-time denominator exists. [ReMoE](https://proceedings.mlr.press/v306/zhu26ab.html), [Oracle-MoE](https://proceedings.mlr.press/v267/zhou25b.html).

These are capability and current-identity guards, not a claim that every listed implementation is numerically interchangeable with C16's checkpoints. Library documentation or a new `main` revision cannot substitute for the exact installed 109 source/binary/backend/correctness receipts. No new model or runtime is loaded in this audit.
