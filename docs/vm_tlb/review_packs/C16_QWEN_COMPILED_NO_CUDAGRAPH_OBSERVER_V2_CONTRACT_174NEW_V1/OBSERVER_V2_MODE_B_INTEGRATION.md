# Mode B / Observer V2 CPU-source integration

This is an exact, Qwen-BF16-only qualification source and contract, not a new measurement. Authority `9122fac5c50dbf19706636fc03978a356ffd800f` closed free-running MODE_A/MODE_B correctness for MP02 and MP03, with MODE_B `VLLM_COMPILE`/`inductor`/`CUDAGraphMode.NONE`, zero capture/replay, `FlashAttentionImpl` and `UnquantizedLinearMethod`. That result **only admitted observer review**. Historical MP02/MP03 eager Graph-OFF correctness STOPs remain unchanged. AWQ Observer V2 runtime PASS at `9d5aa2f36e22a1a8fcc253d6df865160b5dba797` is evidence that the V2 design can be neutral in a different runtime; it is not BF16 compiled-Mode-B neutrality evidence.

The new source is `util/vm_tlb/c16/qwen_compiled_no_cudagraph_observer_v2/{runner.py,observer_v2.py,build_expected_sequence.py}`. Its base is the exact `9122fac5` Mode B runner (SHA256 `cc1fdad5b8401a3a9eea57e312e59079ce08abccf85cf660dda63880a0ce45c1`). It preserves the accepted Mode B model/input/sampling settings and only adds Qwen-scoped V2 semantic hooks and one request-level start/stop CUDA Event pair. `HookSession` has **zero** CUDA Event constructors, no synchronization, no per-module CUDA timing or tensor copy. Its pre/post hooks preserve NVTX push/pop and the accepted ordinal, module, positional first-tensor input shape, and first-tensor output shape semantics from `f63d39c8d90ced038445c264fa8242c524a1aa6f`. The observed arm alone installs semantic hooks; OFF runs the same Mode B configuration without them. Identity-only CUDA activity inventories are separate from the six native neutrality samples and their durations are discarded.

The frozen `EXPECTED_SEMANTIC_SEQUENCE.tsv` has 4,608 rows per point, 9,216 total. The pinned Qwen config has 36 layers, hidden size 2,048 and intermediate size 11,008. `vllm/model_executor/models/qwen2.py` calls, in each layer, `self_attn`, then MLP `gate_up_proj`, `act_fn`, `down_proj`. The accepted Mode A receipt shows 31 decode graph replays for a 32-token request; the remaining first forward is prefill producing D0. Pinned Mode B source dispatches with `CUDAGraphMode.NONE` and no graph padding, so the source-constrained token rows are 512/2,048 for the first MP02/MP03 forward and 1/4 for D1–D31. Ordinal is `forward_index*144 + layer*4 + role_index`, 0–4607 per request. This sequence is frozen **before** the future observer result; a mismatch is a gate failure, not an invitation to edit it.

One subtle but source-closed shape rule matters: Qwen's decoder calls `self_attn` with keyword arguments, while accepted V2's pre-hook observes only positional `args[0]`. Therefore `self_attn` expected input shape is JSON `null`; its output is `[T,2048]`. MLP expected inputs/outputs are `[T,2048]→[T,22016]`, `[T,22016]→[T,11008]`, and `[T,11008]→[T,2048]`. The TSV fixes these values for both points and every ordinal.

Static checks close source syntax, zero per-occurrence Event constructors, exactly two outer request Event constructors, V2 hook fields, 144 selected modules, deterministic 9,216-row sequence, and the pinned authority/results. They **cannot** prove that forward hooks still fire inside a compiled Qwen2Model or that the installed 109 runtime retains Inductor kernels. The future canary must fail closed if the observed sequence is missing, hooks trigger eager/`skip_compiled`, backend/kernel inventory differs, tokens/shapes/logprobs differ, or the original neutrality gate fails. A static PASS authorizes only that bounded qualification test, not acceptance of the instrumented identity.

Native order is fixed `OFF,ON,ON,OFF,OFF,ON`, after one warmup of each arm. The primary neutrality estimator is the request CUDA-event median (three per arm); host median is a cross-check under the same frozen `max(5 ms, 10% of OFF)` expression. The six samples are qualification only. One NSYS `--trace=cuda,nvtx` structural request per point is allowed **only after that point's native identity/correctness/neutrality PASS** and never enters either median. MP02 runs first; any failure stops and, by default, MP03 does not run. The wrapper must account all GPU-active work against 75 seconds for MP02, 105 seconds for MP03, 180 seconds total, with no point-to-point borrowing. The source runner additionally requires the wrapper's verified remaining-point-time argument and stops before exhausting it.

Even a full canary PASS only permits `STAGEA_V2_CONTRACT_REVIEW`. It does not reinstate historical Tier0 points, launch a Tier0 rerun, or establish any hardware/performance claim.
