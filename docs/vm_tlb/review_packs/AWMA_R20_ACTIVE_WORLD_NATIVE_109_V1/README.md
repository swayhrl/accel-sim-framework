# AWMA R20 Lane F — active-world solver Native qualification

The fixed RTX4080 MuJoCo Warp conditional-graph path ran on the real public Unitree G1 hfield replay at B1024, and the discovery window showed natural world-level solver heterogeneity. **We stopped before a candidate or formal speed comparison:** five replays from the same fully restored entry produced divergent 32-step physics trajectories, so no defensible full-window numerical gate could be frozen. Internal classification: `R20_INPUT_OR_BASELINE_NOT_QUALIFIED` (baseline repeatability, not an input or runtime failure).

What is established: MuJoCo Warp `3d537ea6b45eb88ce2ebeb97c57b8e9a220eb1c5`, lock-derived MuJoCo/Warp, exact hfield/NPZ/Menagerie assets, original world-specific Halton control, B1024 with >90% VRAM free after capture, true CUDA conditional-while capture and graph replay, no capacity overflow. The discovery window `[128,160)` has active-set shrinkage in all 32 steps, with mean derived active-slot fraction `0.3733`. This fraction is neither GPU utilization nor a speedup upper bound.

What blocks a claim: all 138 nonempty Data arrays were restored to an identical t128 entry for each repeat, and controls remained bitwise identical. Nonetheless, contact/EFC row allocation order varied under the same B0 graph; first-step sorted semantic contact/constraint coverage stayed identical, but tiny physical differences amplified over 32 steps (qpos spread up to `1.43`, with solver counts and overflow differing). A separately captured graph exhibited the same immediate behavior. It would be scientifically unsafe to bless candidate outputs with a meter-scale tolerance. See `STATE_AND_NUMERICAL_QUALIFICATION.md` and `FINAL_DECISION.md`.

The one scientific scene, batch and window were selected before observing performance; the sealed holdout `[384,416)` was never opened. `ACTIVITY_AND_CAPACITY.tsv` is **observer-only** structural evidence. `CAPACITY_LEDGER.md` separates address-deduplicated Data bytes from unknown graph-local scratch; there was no capacity A/B or formal `NATIVE_TIMING.tsv`. No active-world candidate, NSYS, NCU, NVBit, SASS, Accel-Sim, node174 computation or hardware work was run. This is not a negative finding about every scheduler.

This README is the review entry. `AUTHORITY_AND_FROZEN_CONTRACT.json` and `RUNTIME_SOURCE_RECEIPT.json` bind source, packages, input and graph. `RUN_RECEIPTS.json`, `RAW_DATA_INDEX.tsv` and `SHA256SUMS` locate and verify the full state/trajectory/asset raw on node164. Code changes are only isolated R20 audit/replay tools and this pack; the pinned MuJoCo Warp/Menagerie source checkouts and shared R19 environment remain clean. Future investment, if desired, should first target contact/EFC determinism or a new physically justified local correctness contract—not architecture review from these data.
