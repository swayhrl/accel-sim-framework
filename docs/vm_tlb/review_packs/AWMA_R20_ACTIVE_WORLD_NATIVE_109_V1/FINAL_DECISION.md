# Scientific STOP — R20 Native active-world qualification

Internal label: `R20_INPUT_OR_BASELINE_NOT_QUALIFIED` (specifically the B0 **numerical baseline**, not missing input/runtime).

The fixed MuJoCo Warp source, lock-derived environment, public G1 hfield scene/NPZ/Menagerie assets, original actual ctrl, B1024 memory admission, sparse Newton solver and real device conditional graph all qualified. On the frozen discovery window `[128,160)`, world iteration counts varied naturally and the active set shrank every step; mean derived active-slot fraction was `0.3733`. No contact/constraint capacity overflow occurred. Thus a structural target exists on this one author benchmark replay, but this alone is not a performance opportunity or a speedup ceiling.

The decisive gate is numerical. After restoring all 138 Data arrays to the same t128 entry, five B0 32-step trajectories shared the exact ctrl sequence yet diverged in physical state, nefc, solver_niter and overflow. A four-run one-step check, including an independent new graph, found identical sorted semantic contact/constraint sets but varying pooled atomic contact-ID order and small immediate FP32 state differences; these grew to meter-scale qpos and large velocity differences across 32 steps. We cannot freeze a meaningful whole-window candidate tolerance from such an envelope without masking a broken solver. The parent/source atomics provide a plausible cause, but do not make the numerical gate pass.

Therefore no online active-world-ID candidate was constructed, no formal paired B0/S1 timing was performed, the holdout `[384,416)` stayed sealed, and no NSYS/NCU/Accel-Sim/NVBit/SASS or hardware mechanism followed. This is **not** a negative performance result for dynamic active-world scheduling. It is a runtime-valid, input-valid baseline-qualification STOP. Further investment should first be a separately authorized correctness study of deterministic contact/EFC ordering or a physically justified local semantic contract; architecture review is not warranted from this round.
