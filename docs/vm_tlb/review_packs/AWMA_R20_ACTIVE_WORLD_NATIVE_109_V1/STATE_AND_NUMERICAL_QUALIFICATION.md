# Full-state restoration and baseline numerical qualification

One frozen B1024 discovery entrance was generated by the author's real `load_trajectory` and `_ctrl_noise` rule, advancing exactly t=0..127 before `[128,160)`. `DISCOVERY_ENTRY_FULL_DATA.npz` SHA256 is `17f59a5ebbedff9e544eb7c35cede114c3f9ec97b9b26d0ddfd363370bbcf6e3`. The runner recursively inventoried and GPU-snapshotted all 138 nonempty arrays in the MuJoCo Warp `Data` dataclass, including nested contact/constraint arrays: qpos/qvel/act/history/qacc_warmstart/ctrl/time, applied forces, eq_active, mocap, user/sensor, sleep/awake, solver and contact/constraint buffers. This conservative superset avoids assuming qpos/qvel are the whole cross-step state. Before each of five repeats, all 138 arrays were restored; selected entry hashes matched the frozen snapshot exactly every time. Model arrays were fixed/read-only. Graph-local temporary state is not included in `Data`, but the independent-graph one-step check below limits what can be inferred about its role.

The fixed source captures one CUDA graph with `graph_conditional=True`. A B16 and B1024 witness saw `wp.capture_while` called with a CUDA condition while the outer graph capture was active; Warp 1.15's source calls `wp_cuda_graph_insert_while` in precisely that branch, and actual graph replay succeeded. There was no per-iteration host scalar read or per-step recapture. Original `cli.unroll` and this runner produced bitwise-identical actual ctrl for four B16 steps; the actual ctrl differs from the NPZ center and has world-specific rows. The B16 comparison is engineering-only.

The numerical baseline **failed** for the mandatory 32-step discovery replay despite complete Data restore and exact controls. In five B0 runs from the same entry, ctrl trajectories were bitwise identical but qpos/qvel/qacc_warmstart, per-world solver_niter, nefc, overflow and raw row-order constraint hashes were not. First divergence occurred at step128 for state and row-order coverage, step129 for nefc/niter, and step131 for overflow. Across all 32 steps the largest B0-to-B0 differences were qpos `1.427573`, qvel `55.100785`, qacc_warmstart `14219.415039`; by step159, up to 406 world iteration counts, 449 nefc values and 22 overflow flags differed between repeats. These are not credible FP32-roundoff tolerances for certifying a new scheduler.

An independent same-entry one-step diagnostic repeated step128 three times on one graph and once on a separately captured fresh graph. All four had identical actual ctrl, nefc, niter, overflow, and the **sorted per-world semantic contact and constraint multisets** across all 1024 worlds. However the global pooled contact-ID order differed; qpos varied up to `5.66e-7`, qvel up to `1.11e-4`, qacc_warmstart up to `0.03244`. The fixed source uses global `atomic_add(nacon)` in `collision_core.py` and per-world atomic EFC-row allocation in `constraint.py`; this is consistent with order-dependent FP32 reduction and subsequent chaotic trajectory divergence. It is an evidence-backed explanation, **not proof** that every graph-local scratch dependency is absent. The fresh-graph comparison shows the effect is not unique to reusing one captured graph.

We cannot predeclare a physically defensible field-wise 32-step acceptance envelope by multiplying the baseline's large qpos/qvel drift. The qpos vector mixes translation, orientation and joint coordinates, so its maximum absolute difference is reported without assigning one physical unit. Widening the envelope would make an incorrect active-world implementation indistinguishable from normal variation. The Goal's G2 gate therefore closes as `R20_INPUT_OR_BASELINE_NOT_QUALIFIED`. No S1 patch, formal B0/S1 timing, NSYS/NCU or sealed holdout was run. The one-step canonical coverage and activity observations are structural diagnostics only, not performance or whole-trajectory semantic qualification. Future work would first need separately authorized deterministic contact/constraint ordering or a new local physical-correctness contract; neither is silently introduced here.
