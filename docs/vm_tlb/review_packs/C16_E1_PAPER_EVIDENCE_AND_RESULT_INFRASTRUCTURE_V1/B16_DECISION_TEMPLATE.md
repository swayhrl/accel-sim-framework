# Preregistered B16 decision template

Apply only after an independently accepted B16 primary review pack passes terminal, workload identity, correctness and source-provenance gates. A diagnostic run alone never selects a branch. Use the frozen canary window and the review pack's materiality/dispersion rules; do not invent a new threshold after seeing the result.

| Accepted B16 outcome | Extend to B8/B24/BFULL? | Revise mechanism first? | Stop system case? |
|---|---|---|---|
| Mechanism activates; local and reuse-window effects both positive beyond gates | Yes, test budget shape and repeatability | Only if counter costs expose a specific defect | No |
| Local effect positive; window neutral or negative | No immediate matrix expansion | Diagnose displaced work and adjust quota/admission policy under a new preregistered contract | If the measured offset cannot be removed under bounded revisions |
| Protected occupancy/hit activity low or denial high despite correct tags | No | Fix admission/quota behavior or classify trace pressure; rerun B16 first | Only after the revised bounded mechanism still fails |
| Protection high, but local/window timing gains absent | No | Test whether replacement opportunity is insufficient; avoid tuning without causal counters | Yes if the counterfactual benefit premise is falsified |
| Integration, terminal, workload identity or correctness failure | No | Repair the failing gate and requalify before timing interpretation | No scientific system decision from invalid evidence |

If B16 passes, the minimum next draft update is the accepted B16 table/counters, one simulator panel, the local-to-window comparison and the corresponding branch decision. Unrun budgets remain `PENDING_FUTURE_BUDGET`.
