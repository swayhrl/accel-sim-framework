The raw output contains 543 token-forward positions × 16 layer indices × 8 router-emitted top-k positions in both arms. The 512-token prompt contributes positions 0–511 and the first sampled token D0; positions 512–542 are forwards of generated D0–D30 that yield sampled D1–D31. The final sampled D31 is not forwarded. The top-k axis is **router output order**, not a canonically sorted expert-ID set. `ROUTING_SET_VS_ORDER.tsv` compares both representations for every one of the 8,688 `(position,layer)` events.
All six native runs in the OFF raw file share one routing SHA; the ON raw file contains one native run. The first-OFF selection therefore does not choose an anomalous OFF routing variant.

Of 2,215 affected routing events, 1,599 (72.19%) preserve the expert set and change only order, but **616 change the set**. In 615 of those, 7/8 experts intersect (Jaccard 7/9); one has 6/8 intersect (Jaccard 6/10). There are no duplicate IDs within an event, no layer/position/top-k shape shift and no cross-arm token-ID difference. First ordered difference is prompt position 0, layer 3, top-k slot 5; first set substitution is prompt position 3, layer 6, slot 7. Prefill-linked D0 accounts for 4,559/4,761 positional mismatches; later decoder positions for 202.

The source/raw do **not** expose gate logits, top-k weights, tie-breaking inputs, intermediate activations or an isolated compile-vs-graph ablation. The changed kernel inventory and `enforce_eager` policy cannot identify whether rounding, compilation, graph replay, schedule, or another numeric path causes the observed set substitutions. Sampled-token logprob already differs at D0 (absolute 0.00818), exceeds the frozen tolerance first at D1 and at D4/D6/D23/D29, with maximum 0.102547 at D23. D29's own routed event is ordered-equal while its sampled logprob still fails; step-local routing difference is therefore not a proven sole explanation.
