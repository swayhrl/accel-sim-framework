# Cross-CTA conversion reuse: measured boundary

1. **Local net performance has not been measured for M32/M64 cross-CTA reuse.** C-A proves only strict logical duplication under an identity that includes qweight, zeros, scales, affine format, FP16 rounding and operand layout. Four CTA-private productions per M64 strict tile (two for M32) are counted. The strong source already unpacks in registers and stages one `B_shared` tile per CTA; warp/CTA full-tile duplication is not the residual. The grouped report has no matched bounded-sharing operator time, dynamic execution count or physical cache attribution. A separate C-N M256 invalid-output conversion-removal oracle is slower, while its correct predecoded diagnostic changes representation and GEMM kernel, and excludes preparation. Neither fills this gap.

2. **A legal conceptual counterfactual is identifiable, but no currently qualified implementation establishes a clean one-change contrast.** One would freeze the same AutoAWQ packed input, source kernel, FP16 conversion/rounding, MMA/reduction/output, and compare the CTA-private conversion with a finite inter-CTA tile production/publication/consumption path. Consumers must receive exactly the same operand bits and execute the same math. An implementation must prove block scheduling/lifetime safety without assuming grouped logical block adjacency is execution order. Merely predecoding an entire weight matrix changes the representation, kernel and cache footprint. The available data do not prove that a finite same-semantic implementation can preserve consumer work and ordering while charging its costs. Therefore it is not yet one justified diagnostic proposal.

3. **Mandatory cost ledger, not free conversion removal:** per strict tile 2,368 encoded bytes versus 8,192 decoded bytes, four M64 or two M32 CTA consumers. One N tile across K is 1 MiB decoded; full operator 100,663,296 B decoded versus 26,148,864 B encoded, beyond the cited 64 MiB L2. Producer decoded writes, cross-CTA publication/visibility, synchronization/atomics or readiness state, finite storage/residency, consumer fanout reads, possible cache pollution and eviction, producer-to-last-consumer lifetime, scheduling deadlock avoidance, and competing output/reduction work must all be counted. Live duration in cycles, physical fanout traffic, capacity conflicts and net operator cost are UNKNOWN. A decoded-cache hit cannot be assumed free. Live decoded tiles may displace encoded data or activations.

The accepted natural SHARE3 up target fraction 1.73998% is a system-scope limit in that workload, not an estimate of conversion cost. The later E1 decode D3 up share 16.836% comes from a different intervention/workload scope; it does not expand the C-A grouped result. The negative M256 oracle and near-neighbor software dataflow (MARLIN, QUICK, FLUTE; StreamDQ memory-side decode) raise the burden for a new hardware claim, but do not prove zero value for every grouped shape.
