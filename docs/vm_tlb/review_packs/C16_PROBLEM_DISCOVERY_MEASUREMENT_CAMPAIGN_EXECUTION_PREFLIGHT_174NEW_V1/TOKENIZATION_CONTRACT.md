# Source text first, token IDs only after a pinned tokenizer is legally loaded

Twenty UTF-8 streams are stored under `input_sources/` and bound in `INPUT_SOURCE_MANIFEST.tsv` by exact path, byte count and SHA256. WikiText-103 raw source uses fixed train row ranges: discovery A00–A03 start at 10000+256i, each 128 rows; sealed B01–B15 start at 20000+512(i−1), each 128 rows. Each row's raw `text` is preserved and followed by one LF. The dataset repository SHA observed at freeze was `b08601e04326c79dfdd32d625aee71d232d685c3`; the public `/rows` API does not bind a requested commit, so **the stored bytes**, not an inferred revision-to-row link, are authoritative. PG-19 uses GCS generation pinned for `validation/11155.txt`, first 200000 bytes at a UTF-8 boundary; neither book nor excerpt was chosen by model output or token count.
The [dataset viewer row API](https://huggingface.co/docs/dataset-viewer/en/rows) lists only dataset/config/split/offset/length parameters; it does not provide a commit-addressed row read.

Engineering provenance: an unpublished uniform 64-row preview exposed a short raw-byte span. Before any tokenizer, model, timing or profiler result, **all** WikiText windows were uniformly extended to 128 rows under the same preselected starts; no individual prompt was swapped. The final 128-row files and hashes are the only admitted source identities. This is not a license to adjust spans after tokenization.

Point mapping is frozen: MP01/02/05/06/07 use A00; MP03 B4 uses A00–A03; MP04 B16 uses A00 plus B01–B15 in that order; MP08 uses the PG-19 excerpt. B text is public input, **not** a released holdout output. No tokenizer has been executed in this preflight.

Future 109 canary, only after separate authorization: load tokenizer from the same exact model commit in `MODEL_IDENTITY_PINS.tsv`; record tokenizer/config/chat-template SHA, library version, special-token IDs and prompt role policy. For each frozen source, apply the model's pinned single-user chat template with generation prompt; choose the **longest prefix of that same source text** whose complete templated prompt has at most the designed context token count (512 or 16384). The tie-break is the shortest byte prefix among equal token lengths. Do not replace, repeat or pad text to manufacture the target length. If the resulting token count is less than the target, label `SOURCE_TOO_SHORT_FOR_TARGET` and STOP the affected point or seek design review. No post-result excerpt choice is allowed. Record exact token IDs, count, SHA256 of canonical compact JSON, prompt bytes, truncation byte offset and source SHA in `TOKENIZATION_RECEIPT.json` before timing.

Tokenizers across model families need not produce the same token IDs from the same bytes. Future same-runtime correctness compares a point against its own pre-frozen token reference, not against a different model's token stream. MP04's A00 anchor permits a matched request within a different batch, but co-batched context must be reported rather than attributed away.
