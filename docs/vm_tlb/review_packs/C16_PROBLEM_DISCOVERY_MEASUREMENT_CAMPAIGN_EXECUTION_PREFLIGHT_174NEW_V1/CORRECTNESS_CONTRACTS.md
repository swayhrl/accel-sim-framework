# Canary-first correctness contracts (no tolerance invented here)

Every future native point must pass source/runtime/asset/SM89 and tokenization gates before timing. Pin request bytes, tokenizer and chat-template revision, generated D0–D31 IDs (or prefill output), tensor shapes/dtypes, operator order, backend/kernel names, warmup/replay and CUDA Graph policy. Preserve a native baseline and its `instrumentation ON/OFF` pair. Any mismatch stops that point; the threshold may not be relaxed after performance is seen.

| Class | Exact identities and checks | Numerical rule |
|---|---|---|
| Dense BF16 same runtime, MP01–04/08 | Same model revision and natural input bytes; prefill/decode endpoint, batch row mapping, shapes, finite outputs, token IDs, kernel/operator order and selected attention/projection path. MP04 is A00 plus 15 B prompts, not a B1→B16 single-variable causal comparison. | `TOLERANCE_TO_BE_FROZEN_BEFORE_TIMING`; future canary freezes per-tensor absolute/relative rule and reference hashes before timing. |
| W4/AWQ representation control, MP05 | Same Qwen checkpoint family but different representation; bind `bits=4`, `group_size=128`, `zero_point=true`, `version=gemm`, qweight/qzeros/scales layout and no requantization. Verify tuned AWQ/Marlin selected kernel rather than weak AutoAWQ fallback. | Per-arm token identity and finite/shape checks; BF16-vs-AWQ output tolerance and allowed token divergence must be frozen before timing. `CROSS_RUNTIME_STRONG_BASELINE` if backend differs; never call strict A/B. |
| OLMoE/Granite MoE, MP06/07 | Same-process natural token→router→expert sequence, expert IDs/top-k, input/output shapes, finite outputs, FusedMoE and attention kernel inventory. Pinned configs do not expose a shared expert; record `SHARED_EXPERT_NOT_PRESENT_IN_PINNED_CONFIG`, not an invented shared/routed comparison. | Within each model/point, tokens and routing must match its own canary reference. Numerical tolerance is `TOLERANCE_TO_BE_FROZEN_BEFORE_TIMING`; no cross-family bitwise requirement. |
| Holdout transfer, MP04/07/08 | Do not inspect encrypted output before the frozen DQ sign, estimator, threshold, STOP and exact holdout points are committed and gated. The holdout uses its own source/tokens/correctness receipt and natural parent wall interval. | Never modify tolerance or scientific role after discovery results; a failed/unavailable holdout blocks promotion. |

No present CPU static audit proves a runtime kernel executes correctly on RTX4080. The future canary must verify 420-like call-order invariants only where actually applicable; no old C16 count is transplanted to these new model identities. Native event wall, NSYS wall union and NCU profile kernel durations remain distinct measurement authorities.
