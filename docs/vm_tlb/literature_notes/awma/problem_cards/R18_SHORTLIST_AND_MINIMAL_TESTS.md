# R18候选准备卡｜两项优先，一项条件保留

日期2026-10-01。**不是执行Goal，没有GPU/下载/模拟器授权。** 本卡提出的是待证假设，不是已有论文承认的普遍缺陷。来源P/C编号见Round18报告及SOURCE_REGISTER。

## A｜低比特表示就绪：payload、scale、layout共同到达consumer

**问题。** 低比特GEMM/attention变快后，成熟软件中的groupmax→scale→pack/transpose→交付是否仍阻碍消费？要研究实际可用的数值表示，而不是孤立convert吞吐。

**现有能力。** P001已融合FP4/FP8直接转换与布局；P002研究转置一致性；P003/P007使用混合QK/PV/Direct-P；P006FA4与C002/C003已有softmax-warp、scale布局与交付优化。故“融合量化”“少做一次cast”“加入buffer”不是自动创新。

**下一次准备产物。** 一个真实operator链和其精度/舍入/scale生命周期图；两条可运行强基线；硬件支持表；一个有限干预假设。先在训练的双布局链和attentionP交付链中择一，不把两者混成大矩阵。

**最小候选实验。** 冻结真实activation/state、shape、quality合同及前序。A0为当前融合软件；A1最多一个局部原型，改变有限scale/payload生产或交付，不重写整个模型。D仅作离线诊断，可事先给定scale或放宽局部等待，但不能混为可实现方案或未经证明的严格上界。计时覆盖producer入口至consumer输出；记录payload与scale首次可用、等待、额外字节、metadata和数值误差。真实Native完整时间与插桩分段分开。

**平台。** 4080可验证部分数值转换和非原生布局代码，不能当BlackwellFP4/TMEM计时代理。优先确定论文开源kernel实际需要的硬件；有明确问题后再安排对应实机/校准模型，不先开发全Blackwell模拟器。

**停止/升级。** 同合同强fusion已解决或目标不在完整operator时间上，就关闭该局部假设；可在未知原因下进行一个有界诊断原型，不必预先证明5%。只有剩余表现可复现、可被有限干预解释且区别于现有能力，才进入architecture review。数值合同不能为了避免已有近似基线而人为过强，也不能见性能后放松。

## B｜自然动态工作集：强graphs/megakernel之后的调度与状态成本

**问题。** request的可执行行、结束、刷新和下一任务在线变化时，成熟software是否仍被固定cohort或资源归属限制？不是问GPU能否动态执行。

**状态先查。** 旧R53已有详细设计，本轮未取得其正式完成receipt；先查authority，若确有已测同边界则直接继承，禁止重命名复跑。P018/P019是新增近邻；P009/P010与现有conditionalgraphs/varlen/persistent是强基线能力。

**最小候选实验。** 一种公开可运行模型、一组真实请求、发现/留出分开。A0为完整自然动态轨迹的强runtime；A1一个小型调度/状态原型。保持同一decoder、refresh规则、quality、随机种子及逻辑工作；packing/同步/元数据成本包含。另一条algorithm-policy变化臂若必要，显式单列，不把减少去噪步数当调度收益。D固定步数仅作诊断，不能代表自然执行。

**观测。** 实际完成工作、可就绪工作、tile/warp闲置原因、状态存储/队列、完整请求延迟及吞吐。不要以Q1<整批Q32证明无优化；不要以Q32/32证明单请求理想时延。更不能以GPUkernel数减少代替完整应用收益。

**规模与终点。** 不同时移植三套完整编译器；只移植直接相关能力。普通环境/索引问题顺手解决；完整真实输入与算法不变是科学边界。若只剩hostwrapper则保留软件结论，若强执行能力已解决则停止；若有可解释原型响应，再补一次独立输入验证与最近邻消融。

## C｜条件保留：不可直接线性化的推理期fast weight

**问题。** 对真实保留动态特征函数或state normalization的算法，update→read/commit是否有新的有限状态管理机会？

**为什么不马上跑。** P016的部分并行加速包含算法消融；P017需要专门持续预训练和公开权重/输入资格。ReplaySSM/TreeWY已覆盖许多直观state写回/rollback方案。我们的RTC VJP冻结权重，不是该问题的性能证据。

**下一步仅源码/输入核查。** 精确列哪些参数在线变、数学更新及任务收益、现有线性化可否适用、checkpoint是否可取得。取得真路径后才考虑短序列状态生命周期测试；不能用随机矩阵更新当自然AI现象。

## 共同执行原则

1. 主目标仍是解决有实际意义且有增量的新问题，不是无限复现。
2. 准入证明服务于最终claim，不把论文级全因果证明设为每个小原型的前置条件。
3. 数值一致性、近似质量、同搜索工作、相同硬件分别处理；不可互相替代。
4. 独立资源和输入已冻结时，CPU准备可以并行；GPU依实际安全性与既有锁执行，不以闲置为理由扩题。
5. 原数据与基线保持，候选允许改变明确标出的结构/策略。最终也允许软件贡献、未知、未资格化、负响应和局部positive，不能强迫每次都成为硬件机制。
6. 本轮Lane E/F/G继续STOP，等待下一条明确授权的具体合同，不自动启动A/B/C。
