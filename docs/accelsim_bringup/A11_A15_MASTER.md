# Accel-Sim A11-A15 paper reproduction infrastructure master guidance

## Overall goal

Complete one large infrastructure round:

    A11_A15_PAPER_REPRODUCTION_PIPELINE

This round should move the current Accel-Sim state from "bringup and real workload alignment" to "paper reproduction infrastructure ready".

The round is divided into five ordered phases:

    A11 -> A12 -> A13 -> A14 -> A15

Phase meanings:

- A11: stats equivalence narrow plan and parser hardening
- A12: workload and config lockdown
- A13: experiment matrix runner
- A14: paper reproduction readiness closeout
- A15: trace acquisition and GPU gap plan

## Why A11-A15 are still needed

A10 proved that Accel-Sim can connect to prior Mascar and MeDiC reproduction artifacts. However, it is not yet a paper-level reproduction platform because:

1. The current stats parsing is smoke-level, not comparison-grade.
2. A10 mappings are evidence-row-level, not unique workload/config/run-level.
3. There is no lockfile that future experiments can consume directly.
4. There is no experiment matrix runner supporting baseline/variant/resume/rerun.
5. There is no readiness closeout proving the full minimal paper-reproduction loop.
6. Trace generation remains blocked without GPU, and the gap needs to be documented.

A11-A15 should close these gaps.

## Required phase order

Execute strictly in this order:

    A11 -> A12 -> A13 -> A14 -> A15

Do not skip a phase unless it is truly blocked. If blocked, write a clear BLOCKED report and continue only if later phases can still produce useful infrastructure.

## Hard rules

1. Do not push.
2. Do not use git add . or git add -A.
3. Do not modify prior GPGPU-Sim repos. They are read-only evidence sources.
4. Do not commit generated logs, traces, build directories, hw_run, downloaded apps, or review packs.
5. Runtime outputs must go only under ignored local paths:
   - .local_reports/
   - .local_logs/
   - .local_runs/
   - .local_traces/
   - hw_run/
   - review_packs/
6. Do not run a full benchmark campaign.
7. Do not validate NVBit tracer in this round unless GPU is visible and the user explicitly allows real trace generation.
8. Do not modify Accel-Sim architectural behavior.
9. Do not implement Mascar or MeDiC mechanisms in Accel-Sim in this round.
10. Do not fabricate mappings or stats equivalence.
11. All CSV output must have stable headers.
12. Strip carriage returns from parsed paths and fields.
13. Avoid creating a transient file named 0. If such a file appears and is untracked, tiny, and clearly generated by this round, remove it and record it.
14. Each phase must record:
    - start time
    - end time
    - wall clock seconds
    - status
    - command list
    - input files
    - output files
    - blockers
    - limitations

## Clean tree rule

For any phase that claims baseline-quality or paper-reproduction readiness:

1. Implement tracked scripts and docs.
2. Commit tracked changes with explicit git add paths.
3. Confirm:

       git status --short

   is empty.
4. Run the phase scripts.
5. After the run begins, do not edit tracked files.
6. If tracked fixes are needed, commit them first and rerun the affected phase from a clean tree.
