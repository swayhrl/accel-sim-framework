# Accel-Sim A10 real workload alignment master guidance

## Goal

Complete one large A10 round named:

    A10_REAL_WORKLOAD_ALIGNMENT

The purpose is to turn the A9 alignment template into a real alignment layer by reading the existing Mascar and MeDiC GPGPU-Sim reproduction artifacts, extracting their actual workload names, run configs, scripts, stats fields, and review-pack style, then mapping them to the current Accel-Sim trace-driven workflow.

This round should produce an auditable mapping and a bounded smoke validation. It should not try to reproduce the full Mascar or MeDiC papers inside Accel-Sim yet.

## Current state

A0-A9 already established:

- Accel-Sim build and clean baseline smoke pipeline works.
- A6B fixed the false dirty build-string rule.
- _modified_0.0 is accepted as clean diff zero when git status is clean.
- A7B ran a 3-app smoke.
- A8 ran a 5-app small baseline.
- A9 produced an alignment scaffold and review pack.
- A9 did not yet truly extract Mascar/MeDiC workload definitions from prior GPGPU-Sim artifacts.
- A3 tracer remains blocked because no GPU is visible.

## A10 phase order

Execute strictly in this order:

    A10A -> A10B -> A10C -> A10D -> A10E

Phase meanings:

- A10A: discover prior Mascar/MeDiC GPGPU-Sim workflow artifacts.
- A10B: extract real prior workload, config, and stats inventory.
- A10C: map prior workloads to available Accel-Sim traces and configs.
- A10D: run bounded aligned smoke and generate normalized stats.
- A10E: final docs, known gaps, and review pack.

## Hard rules

1. Do not push.
2. Do not use git add . or git add -A.
3. Do not modify prior GPGPU-Sim repos. Read only.
4. Do not commit generated logs, traces, downloaded apps, build dirs, hw_run, or review packs.
5. Runtime outputs must go under ignored local paths only:
   - .local_reports/
   - .local_logs/
   - .local_runs/
   - .local_traces/
   - hw_run/
   - review_packs/
6. Do not run a full benchmark campaign.
7. Do not validate NVBit tracer in A10.
8. Do not implement new Accel-Sim architectural behavior.
9. Do not assume prior repo paths. Search cautiously under /workspace/repos.
10. Avoid huge recursive scans. Exclude .git, build, hw_run, traces, .local_runs, .local_traces, large binary files, and build outputs.
11. If prior Mascar/MeDiC artifacts cannot be found, produce a precise BLOCKED_NO_PRIOR_ARTIFACTS report instead of fabricating mappings.
12. All phase scripts must write start time, end time, wall clock seconds, status, commands, important paths, and limitations.
13. All CSV output must use stable headers.
14. Strip carriage returns from parsed paths and CSV fields.
15. Guard against transient files such as a file literally named 0. If such a file appears, delete it only if it is untracked, tiny, and clearly generated by this round; record it in the report.

## Clean tree rule

Before running any phase that claims baseline quality or produces final alignment results:

1. Implement tracked scripts and docs.
2. Commit tracked changes with explicit git add paths.
3. Confirm:
       git status --short
   is empty.
4. Run the phase scripts.
5. If tracked scripts need fixes, commit them first and rerun affected phases from a clean tree.

## Final pass criteria

A10A pass:
- Prior artifact search script runs.
- Real artifact inventory CSV exists.
- Search is bounded and does not scan huge data blindly.
- If no artifacts found, report is precise.

A10B pass:
- Prior workload inventory CSV exists.
- Prior stats field inventory CSV exists.
- Inventory rows cite real source files or extracted review-pack files.
- No template-only mapping is presented as real extraction.

A10C pass:
- Accel-Sim trace inventory is built from existing kernelslist.g files.
- Prior workloads are normalized and mapped to available traces or marked missing.
- Mapping CSV has clear status values.

A10D pass:
- Bounded aligned smoke runs only for available mapped traces.
- Default max aligned runs is small.
- Stats CSV is produced.
- Run does not become a full benchmark campaign.

A10E pass:
- Final summary exists.
- Known gaps are explicit.
- Review pack exists.
- Final git status is clean.
